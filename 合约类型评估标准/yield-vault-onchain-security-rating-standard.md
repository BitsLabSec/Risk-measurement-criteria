# BitsScore 收益金库链上安全评估标准

- 记录日期：2026-11-10
- 文档版本：v0.2
- 适用范围：选定收益金库及其必要关联对象，不默认覆盖平台全部金库。
- 评估方式：基于单个 snapshot，采用三个计分模块及一组资金状态展示，不合成金库总分。
- 分值性质：沿用现有 Lending、DEX 的主要评级档位，尚未经过样本统计校准，不代表损失概率。

## 1. 评估范围与边界

### 1.1 评估对象

本标准适用于接收用户资产、持续管理其在底层协议或策略中的配置，并向用户提供收益归属和退出安排的产品。纯粹代用户完成操作、不持续管理用户资产和权益的 Router，不作为收益金库评估。

不限定链、虚拟机、份额标准、单策略或多策略、同步或异步退出。收益来源及运行机制按实际项目确定，不默认所有金库遵循同一种架构。

评估范围固定到选定金库及必要关联对象，不默认覆盖平台全部金库，也不无限递归评估底层协议。项目方提供的对象清单需要核对，不因提供清单即视为已经核验。

### 1.2 与代码逻辑评估的分工

| 内容 | 本模块处理方式 |
| --- | --- |
| 权益计算、收益分配、策略执行和退出机制是否正确 | 复用代码逻辑评估结论，不重新评估 |
| 当前谁能控制资产、改变策略或限制退出 | 权限评分 |
| 当前配置是否满足已确认的约束 | 配置评分 |
| 当前必要外部输入、资金组件是否正常 | 依赖评分 |
| 资产分布、集中度、锁定和领取状态 | 展示，不独立评分 |
| 收益率、历史回撤、策略盈利能力 | 不纳入 |

已有机制映射不足以解释当前状态时，相关项标为待核验，不在链上评分过程中补做一轮代码审计。

### 1.3 单快照原则

- 每轮绑定各链明确的区块／检查点、可用的唯一标识及时间；同一链使用一致的状态锚点，跨链分别标注，不冒充完全同步。
- 单次 snapshot 独立判断，不依赖历史趋势、累计事件、连续正常次数或历史处罚。
- 可以复用仍适用于当前对象的代码机制、控制独立性及其他既有证据。
- 使用当前时间计算输入年龄、剩余等待或领取条件，属于当前状态判断；不据此推断长期拥堵或运行效率。
- 不同金库、资产或用户权益存在实质差异时，分别说明范围，不用无关高分项稀释局部风险。

## 2. 权限与控制关系

### 2.1 检查内容

按实际业务后果和完整控制路径评分，不按角色数量、是否有多签打分。

| 检查项 | 当前需要确认的内容 |
| --- | --- |
| 资产及权益控制 | 谁可以转出资产、改变资金用途、调整用户权益或收款对象 |
| 策略及资金去向控制 | 谁可以增删、替换策略，改变资金配置；权限是否受实际可执行的范围约束 |
| 费用及退出条件控制 | 谁可以改变现有用户承担的费用、等待条件或退出限制 |
| 上级及间接路径 | 谁可以重新授予权限、替换执行主体、改变批准门限、解除限制或绕过等待 |
| 控制重合 | 多个角色是否由同一实际控制组掌握；表面分权是否存在更弱的共同上级 |

能力含义来自已有代码评估；这里核验当前主体、配置与路径。地址不同不直接证明控制主体独立，角色、多签或等待机制不作为独立加分项。报告中的中心化问题可提供线索，但不将报告风险等级再次用于本模块扣分。

### 2.2 业务后果与路径分值

| 已确认的业务后果 | A：单一控制组 | B：强制独立共同批准 | C：有效退出保护 | D：B＋C | 确认无对应能力 |
| --- | ---: | ---: | ---: | ---: | ---: |
| H1：任意处分用户资产或重写权益，包括能将资金转入任意、不受约束的去向 | 0 | 40 | 70 | 85 | 100 |
| H2：在明确约束内改变策略、费用或退出条件，对现有用户产生额外风险，但未达到 H1 | 20 | 50 | 80 | 90 | 100 |
| H3：可无限期阻断必要资金取回，且没有不可自行延长的到期或独立恢复保障 | 30 | 60 | 75 | 90 | 100 |

根据已有能力结论判断实际后果，不仅依据角色或功能名称。用户已接受的正常费用、等待机制，以及仅停止新增业务，不自动构成上述危险后果。

### 2.3 档位条件

| 档位 | 必要条件 |
| --- | --- |
| A | 单一实际控制组可造成对应后果，不满足有效退出保护 |
| B | 必须由至少两个已证实独立的控制组共同批准，没有更弱的上级或间接路径；不同时满足 C |
| C | 危险改变公开可见，存在不可绕过的等待，且当前证据支持相关用户在生效前完成必要退出；危险操作控制者不能提前关闭该路径；不同时满足 B |
| D | 同时满足 B 的独立共同批准条件和 C 的有效退出保护条件 |

- 金库有等待期不自动构成退出保护。如果资金当前锁定至危险改变生效之后，不能仅凭管理操作有延迟取得 C／D。
- 已排队操作使用当前剩余窗口，不统一规定等待多少小时即为安全。
- 保护只覆盖部分用户或资金时，按实际覆盖范围分别呈现，不能外推到全部权益。
- 当前退出证据不保证未来整个等待期间都可退出，也不保证所有用户同时退出。
- 独立主体仅有主动否决能力，不等于必须共同批准。

### 2.4 公式及特殊处理

设 `m` 为声明的评估范围，`h` 为适用业务后果，`P(m,h)` 为当前配置下已确认可达到该后果的完整控制路径集合，`q(p)` 为路径控制档位，`L(h,q)` 为评分表中的分值：

```text
路径分 S(p,h) = L(h, q(p))
后果分 S(m,h) = min { S(p,h) | p ∈ P(m,h) }
权限分 S_permission(m) = min { S(m,h) | h 为适用业务后果 }
```

| 情况 | 处理 |
| --- | --- |
| 已完整核验相关范围，确认不存在对应直接或间接能力 | 该后果记 100；不对空路径集合直接计算最小值，也不能仅凭未发现路径、角色无人持有或读取失败认定无能力 |
| 当前权限配置已造成必要退出路径永久失能 | 对应项记 0，优先于普通路径分档 |
| 关键控制路径、能力映射或独立性未知 | 对应项标 U；展示已确认结果，受影响范围暂不发布确定权限分 |

## 3. 当前关键配置

### 3.1 检查内容与依据

只评估已有明确含义和判断依据的配置，不制定所有金库通用的费率、闲置比例或策略数量要求。

| 检查项 | 判定依据 | 不应误判的情况 |
| --- | --- | --- |
| 当前资金去向及组件绑定 | 当前绑定是否符合已确认的用途、归属和兼容性要求 | 地址陌生、底层不知名，不直接扣分 |
| 额度及分配限制 | 当前设置是否满足该金库已确认的约束和参数关系 | 不统一要求分散到多个策略或保留固定比例现金 |
| 费用及接收对象 | 当前费率、计费配置及接收对象是否符合适用约束 | 费率高不直接等于不安全 |
| 存入、退出及领取开关 | 当前设置是否造成超出既定机制的必要退出限制 | 关闭新增存款、保留正常退出，不自动扣分 |
| 等待及结算相关配置 | 当前设置是否符合既定机制和已确认的约束 | 正常锁定期、异步结算不自动扣分 |

每项事先记录适用对象、约束或警戒条件、依据及规则版本，不根据结果临时调整标准。“已确认约束”需要记录来源和适用性。项目方声明可提供线索，但不能未经核验就作为安全依据；安全条件也不能只靠“项目允许这样设置”来证明。

### 3.2 评分规则

| 分值／状态 | 判定条件 |
| --- | --- |
| 100 | 当前配置满足适用约束，必要状态符合已确认的业务条件 |
| 60 | 满足以下任一条件：① 触及事先明确且适用的警戒条件；② 必要操作异常部分受限，但同一受影响范围内仍有已核验的部分可用完成／退出路径。警戒条件独立成立时无需以替代路径作为附加条件 |
| 0 | 明确违反安全约束，或阻断必要资金取回且没有有效替代 |
| U | 当前值、判断依据或关键证据不足 |
| N/A | 不存在该机制或配置项，须说明依据 |

先判断明确不满足，再判断警戒／受限，必要检查通过才计 100。只有满足／不满足两种结果的项采用 100／0，不强设 60 档。

```text
配置分 S_config(m) = min { s_i | i 为同一范围内适用且独立计分的配置项 }
```

## 4. 必要外部依赖的当前状态

### 4.1 检查内容

评估金库实际使用的依赖当前是否满足必要条件，不对底层协议重新做安全评级。

| 检查项 | 核验内容 | 边界 |
| --- | --- | --- |
| 必要资金组件 | 底层当前状态是否支持金库已有权益对应的必要取回、结算或领取路径 | 正常锁定和约定等待不是失效；仅停止接受新增资金不自动扣分 |
| 必要估值输入 | 实际用于权益结算等业务的价格、兑换率或净值输入，是否满足已确认的有效性条件 | 页面参考估值不作为协议运行依赖；不重审估值算法 |
| 必要执行组件 | 当前链上可确认的状态是否支持必要业务执行 | 不以链上状态推断链下执行者或托管方一定正常 |
| 实际替代路径 | 主依赖异常时，已存在的替代是否当前有效、覆盖哪些权益和金额 | 配置中存在备用，不等于已有效承接 |

新鲜度、有效范围及其他条件按实际机制确定，不统一规定所有金库适用的超时或价格偏差。固定值或直接从当前状态计算的值，不机械套用时间戳要求。

### 4.2 评分规则

| 分值／状态 | 判定条件 |
| --- | --- |
| 100 | 必要输入及相关路径满足当前有效性条件；正常等待也属于正常状态。完整有效的替代已承接时同样记 100 |
| 60 | 满足以下任一条件：① 触及事先明确且适用的警戒条件；② 必要业务异常部分受限，但同一受影响范围内仍有已核验的部分可用完成／退出路径。警戒条件独立成立时无需以替代路径作为附加条件 |
| 0 | 必要输入明确失效，或必要路径异常不可用，且无有效替代 |
| U | 关键状态无法核验，或缺少判断有效性的依据 |
| N/A | 不存在该必要依赖，须说明依据 |

先判断 0 分条件，再判断 60 分条件。

```text
依赖分 S_dependency(m) = min { s_j | j 为同一范围内必要且独立计分的依赖项 }
```

不按底层协议的知名度、合作关系或审计数量赋分。数据采集失败标 U，不能直接当成底层失效。接口调用成功也不能单独证明必要输入有效或全部资金可退出。

## 5. 资金状态与受影响敞口：展示，不评分

### 5.1 展示内容

| 展示项 | 最小内容 | 解释限制 |
| --- | --- | --- |
| 资产及权益口径 | 金库报告的资产、用户权益、计价单位；可独立核验的部分 | 协议自报资产不等于已证明足额兑付 |
| 当前资金分布 | 金库可直接控制的资产、底层协议／策略中的权益、未知部分 | 一层层持仓不能重复累计 |
| 集中度 | 各底层或已识别共同风险来源的敞口 | 集中不自动扣分，分散不自动加分 |
| 退出状态 | 当前可用、需从底层取回、锁定、待结算、已可领取的部分 | 按实际机制分类；不同分类可能重合，不能直接相加 |
| 已确认异常的影响 | 关联异常、受影响资产或权益、金额／比例及核验依据 | 退出受限不等于资产损失 |
| 已确认损失或缺口 | 在一致口径下可证明的损失／权益覆盖缺口 | 账面估值差异、缺少数据不直接视为坏账 |

即时退出比例高低不是通用安全指标。闲置资金为零、全部投入单一协议、正常排队或等待，均不自动扣分。单次成功退出不能证明所有用户可以同时退出；可见余额不直接等于可以向用户支付的金额。

### 5.2 敞口计算

只有口径一致、估值依据有效且没有重复计算时，才展示比例：

```text
异常受影响敞口比例
= 该异常实际影响的已核实资产价值
  ÷ 同一范围、同一估值口径下的资产总价值
```

分母无法核实时，只展示资产数量、已核实范围和未知部分，不输出百分比，也不按比例扣分。分母为零时比例不适用，不进行除法。多个异常影响同一资产时，分别关联原因；汇总影响不得直接累加重合部分。

例如：必要依赖当前赎回异常，影响金库 30% 的已核实资产敞口。该比例表示退出受限范围，不表示已经损失 30%，也不对应扣除 30 分。

## 6. 模块联动与去重

| 情况 | 处理 |
| --- | --- |
| 配置了错误的资金组件 | 配置计分；依赖和资金展示引用异常及影响，不重复扣分 |
| 配置正确，但底层当前异常 | 依赖计分；资金展示受影响敞口 |
| 管理者能改变资金去向，但当前配置正常 | 权限评估控制风险，配置按当前状态判断 |
| 当前退出条件不足以支持权限 C／D | 权限按实际条件分档；不再设置额外“退出安全分” |
| 发现资金缺口，但原因尚不明确 | 明确展示已确认异常及范围；原因归属待核验，不强塞进其他评分项 |

引用项仍展示异常状态，不伪装成正常或 N/A；标明计分归属，不重复进入接收模块的最小值公式。一个模块只有引用项而没有独立计分项时，显示“参见对应模块”，不补算满分。

## 7. 未知项、更新与输出

### 7.1 未知项与适用性

- U 表示证据或判断依据不足；N/A 表示机制确实不适用，不能相互替代。
- 同一范围存在关键 U 时，暂不发布该范围的确定模块分，仍展示已确认分项及异常；不能剔除未知项后算满分。
- 全部检查项确实不适用时显示 N/A，不记 100。
- 未知只影响依赖它的范围和模块。资金展示中的未知不机械清空其他模块；但若未知资金状态使退出保护无法确认，就不能声称具备该保护。
- 已确认损失、缺口或退出异常必须显著展示，不能被其他正常分数掩盖。

### 7.2 更新规则

| 变化或状态 | 本轮处理 |
| --- | --- |
| 新 snapshot | 独立读取与判断，不因连续正常加分，也不要求连续多轮才恢复 |
| 权限主体、批准门限、控制模块或等待条件变化 | 更新受影响控制路径及分档，不因变化本身扣分 |
| 参数、资金去向或组件绑定变化 | 按当前值及仍适用的依据重算相关项 |
| 资产配置、锁定或领取状态变化 | 更新资金状态与敞口展示；仅在影响其他评分条件时联动重算 |
| 升级使原能力或机制解释失效 | 仅将依赖该解释的项标为待复核，由代码侧补齐；原始状态仍可展示 |
| 异常消除且证据完整 | 按当前符合的档位恢复，不继承历史处罚 |
| 数据缺失或采集失败 | 标 U；旧快照可以单独展示，不能冒充当前状态 |

### 7.3 最小证据与对外展示

| 信息 | 最小要求 |
| --- | --- |
| 范围 | 金库、链、必要关联对象、资产及用户权益范围，以及未覆盖部分 |
| 当前状态 | 区块／检查点及可用唯一标识、时间、读取对象和关键原始结果 |
| 解释依据 | 当前适用的代码能力／机制映射、约束及有效性条件；标明来源 |
| 判定 | 分值或 U／N/A、原因、受影响范围、引用关系及计分归属 |
| 资金口径 | 自报／独立核验标识、资产单位、估值依据、分母范围及未知部分 |
| 规则版本 | 本标准版本和项目适用条件，支持复算 |

最终分别展示：**权限分、配置分、必要依赖分、资金分布与受影响敞口**。不合成金库总分；三项分数正常不等于保证本金或收益，也不代表底层协议已经得到全面安全验证。
