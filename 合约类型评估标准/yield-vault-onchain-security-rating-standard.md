# BitsScore 收益金库链上安全评估标准

- 记录日期：2026-11-10
- 文档版本 v0.5，更新于 2026-11-24。
- 适用范围为选定收益金库及其必要关联对象，包括与存量份额、收益权益及退出有关的实际策略。
- 各链使用声明的快照，分别输出权限管理、参数配置、资金与外部依赖。各业务的结果保留适用范围，向项目汇总提供一级业务模块分。
- 评分表中的数字为档位上限，当前分数由档位和独立档内扣分决定。项目范围、权限分表和对象上限见[链上评估复用指南](./链上评估复用指南.md)，通用配置和资金判定见[通用链上安全评估标准](./通用链上安全评估标准.md)。

## 1. 评估范围与边界

### 1.1 评估对象

本标准适用于接收用户资产、持续管理其在底层协议或策略中的配置，并向用户提供收益归属和退出安排的产品。纯粹代用户完成操作、不持续管理用户资产和权益的 Router，不作为收益金库评估。

不限定链、虚拟机、份额标准、单策略或多策略、同步或异步退出。收益来源及运行机制按实际项目确定，不默认所有金库遵循同一种架构。

评估范围固定到选定金库及必要关联对象，不默认覆盖平台全部金库，也不无限递归评估底层协议。项目方提供的对象清单需要核对，不因提供清单即视为已经核验。

先从金库、份额资产、策略绑定及必要出口确定顶层对象。已有份额的核验需要下钻时，说明依赖哪一个底层头寸、资金池或可独立领取对象。项目所有模块共用每轮最多 50 个独立核验目标的额度，各链的地址和对象均计入。

### 1.2 与代码逻辑评估的分工

| 内容 | 本模块处理方式 |
| --- | --- |
| 权益计算、收益分配、策略执行和退出机制是否正确 | 复用代码逻辑评估结论，不重新评估 |
| 当前谁能控制资产、改变策略或限制退出 | 权限评分 |
| 当前配置是否满足已确认的约束 | 配置评分 |
| 当前必要外部输入、资金取回及现有权益兑付是否正常 | 资金与外部依赖评分 |
| 资产分布、集中度，以及按期划分的锁定和领取状态 | 作为资金核对输入或披露，按具体义务确定用途 |
| 收益率、历史回撤、策略盈利能力 | 不纳入 |

已有机制映射不足时记录缺口并按结项规则评分。链上评估复用代码侧核验结果。

### 1.3 单快照原则

- 每轮绑定各链明确的区块／检查点、可用的唯一标识及时间；同一链使用一致的状态锚点，跨链分别标注，不冒充完全同步。
- 单次 snapshot 独立判断，不依赖历史趋势、累计事件、连续正常次数或历史处罚。
- 可以复用仍适用于当前对象的代码机制、控制独立性及其他既有证据。
- 使用当前时间核实必要输入的有效性和当前应付权益的领取条件。
- 不同金库、资产或用户权益存在实质差异时，分别说明范围，不用无关高分项稀释局部风险。

## 2. 权限与控制关系

现行权限分按[链上评估复用指南第 1.3 节](./链上评估复用指南.md)的通用分表计算。本节确定金库的控制路径和业务后果。旧版分表和公式保留用于追溯收益金库 v0.2 结果。

### 2.1 检查内容

按实际业务后果和完整控制路径评分，不按角色数量、是否有多签打分。

| 检查项 | 当前需要确认的内容 |
| --- | --- |
| 资产及权益控制 | 谁可以转出资产、改变资金用途、调整用户权益或收款对象 |
| 策略及资金去向控制 | 谁可以增删、替换策略，改变资金配置；权限是否受实际可执行的范围约束 |
| 费用及退出条件控制 | 谁可以改变现有用户承担的费用、等待条件或退出限制 |
| 上级及间接路径 | 核对已生效的角色与批准门限、时间锁配置及其时长，以及谁可以重授权限、替换执行主体、改短时长或绕过等待 |
| 控制重合 | 多个角色是否由同一实际控制组掌握；表面分权是否存在更弱的共同上级 |

能力含义来自已有代码评估；这里核验当前主体、配置与路径。地址不同不直接证明控制主体独立，角色、多签或等待机制不作为独立加分项。报告中的中心化问题可提供线索，但不将报告风险等级再次用于本模块扣分。

沿当前角色持有人、上级授权、凭证转授和策略执行主体追到实际控制组。管理员可任意更换资产去向或重写已发行份额权益时，核对通用分表的 H1。管理员可在约束内变更存量用户适用的策略、费用或退出条件时，核对 H2。暂停者可无限期阻断存量用户赎回或领取时，核对 H3，并查是否有独立恢复或不可自行延长的期限。复投者、调仓执行者和其他 Keeper 按其实际链路可造成的业务后果归类。同一范围按通用权限分表定档并计算档内得分。用代码和已生效的链上权限配置核对危险操作控制者能否禁用已设计的赎回、取消或到期领取入口。

### 2.2 业务后果与路径分值（v0.2 历史口径）

| 已确认的业务后果 | A：单一控制组 | B：强制独立共同批准 | C：有效退出保护 | D：B＋C | 确认无对应能力 |
| --- | ---: | ---: | ---: | ---: | ---: |
| H1：任意处分用户资产或重写权益，包括能将资金转入任意、不受约束的去向 | 0 | 40 | 70 | 85 | 100 |
| H2：在明确约束内改变策略、费用或退出条件，对现有用户产生额外风险，但未达到 H1 | 20 | 50 | 80 | 90 | 100 |
| H3：可无限期阻断必要资金取回，且没有不可自行延长的到期或独立恢复保障 | 30 | 60 | 75 | 90 | 100 |

根据已有能力结论判断实际后果，不仅依据角色或功能名称。用户已接受的正常费用、等待机制，以及仅停止新增业务，不自动构成上述危险后果。

### 2.3 档位条件（v0.2 历史口径）

| 档位 | 必要条件 |
| --- | --- |
| A | 单一实际控制组可造成对应后果，不满足有效退出保护 |
| B | 必须由至少两个已证实独立的控制组共同批准，没有更弱的上级或间接路径；不同时满足 C |
| C | 危险改变公开可见，存在不可绕过的等待，且当前证据支持相关用户在生效前完成必要退出；危险操作控制者不能提前关闭该路径；不同时满足 B |
| D | 同时满足 B 的独立共同批准条件和 C 的有效退出保护条件 |

- 金库有等待期不自动构成退出保护。如果资金当前锁定至危险改变生效之后，不能仅凭管理操作有延迟取得 C／D。
- 已排队操作使用当前剩余窗口，不统一规定等待多少小时即为安全。
- 保护只覆盖部分用户或资金时，按实际覆盖范围分别呈现，不能外推到全部权益。
- 当前退出证据不保证未来整个等待期间都可退出，也不保证所有用户同时退出。
- 独立主体仅有主动否决能力，不等于必须共同批准。

### 2.4 公式及特殊处理（v0.2 历史口径）

设 `m` 为声明的评估范围，`h` 为适用业务后果，`P(m,h)` 为当前配置下已确认可达到该后果的完整控制路径集合，`q(p)` 为路径控制档位，`L(h,q)` 为评分表中的分值：

```text
路径分 S(p,h) = L(h, q(p))
后果分 S(m,h) = min { S(p,h) | p ∈ P(m,h) }
权限分 S_permission(m) = min { S(m,h) | h 为适用业务后果 }
```

| 情况 | 处理 |
| --- | --- |
| 已完整核验相关范围，确认不存在对应直接或间接能力 | 该后果记 100；不对空路径集合直接计算最小值，也不能仅凭未发现路径、角色无人持有或读取失败认定无能力 |
| 当前权限配置已造成必要退出路径永久失能 | 对应项记 0，优先于普通路径分档 |
| 关键控制路径、能力映射或独立性未知 | 对应项标 U；展示已确认结果，受影响范围暂不发布确定权限分 |

## 3. 当前关键配置

### 3.1 检查内容与依据

只评估已有明确含义和判断依据的配置，不制定所有金库通用的费率、闲置比例或策略数量要求。

| 检查项 | 判定依据 | 不应误判的情况 |
| --- | --- | --- |
| 当前资金去向及组件绑定 | 当前绑定是否符合已确认的用途、归属和兼容性要求 | 地址陌生、底层不知名，不直接扣分 |
| 额度及分配限制 | 当前设置是否满足该金库已确认的约束和参数关系 | 不统一要求分散到多个策略或保留固定比例现金 |
| 费用及接收对象 | 当前费率、计费配置及接收对象是否符合适用约束 | 费率高不直接等于不安全 |
| 存入、退出及领取开关 | 当前设置是否造成超出既定机制的必要退出限制 | 关闭新增存款、保留正常退出，不自动扣分 |
| 等待及结算相关配置 | 当前设置是否符合既定机制和已确认的约束 | 正常锁定期、异步结算不自动扣分 |

每项事先记录适用对象、约束或警戒条件、依据及规则版本，不根据结果临时调整标准。“已确认约束”需要记录来源和适用性。项目方声明可提供线索，但不能未经核验就作为安全依据；安全条件也不能只靠“项目允许这样设置”来证明。

### 3.2 复核份额、赎回和复投

| 检查项 | 实际执行 | 判定依据 |
| --- | --- | --- |
| 对象及份额映射 | 从金库生产版本绑定份额币种、供应量、金库资产、策略及底层头寸。资产经包装或质押时继续定位到最终头寸，核对记录量与实际策略头寸 | 按部署规定的同口径量核对。已证实错绑或不一致导致现有用户权益转移、稀释或结算错误，按硬约束违反处理 |
| 赎回保护 | 核对当前版本、申请和领取对象、普通退出及替代出口、必要的全局与策略级开关。按实际顺序算费用和逐币净到账，核对用户签入的最小量（如适用） | 已确认费用或最低净到账检查违反约束，或必要退出完全受阻且无有效替代时取 0 档。同一范围部分异常受限时取 60 档。正常排队和已声明的异步流程按实际时限检查 |
| 策略、复投与调仓边界 | 查当前实际策略与池绑定、复投币种、已确认的兑换或用量预算、未用资产和残余资金的接收对象，核对调仓后记录量是否按实际增减更新 | 份额或资产归属、适用限额、风险预算确有违反时按相应硬约束或预设警戒判档。区间、上限、闲置率和预计收益有各自的数值含义，未设安全判据时只披露 |

对已确认按策略流动性份额记账的金库，可用所核实现重算。Cetus haSUI/SUI 样本在非首存状态用 `铸造份额 = floor(原份额总量 × 新增流动性 ÷ 原流动性)`，撤资用 `取回流动性 = floor(销毁份额 × 底层头寸流动性 ÷ 总份额)`。首存、空头寸或零总份额适用实际初始化规则，避免将其代入普通比例公式。按样本对两币分别计算 `净到账 = 取回量 − ceil(取回量 × 退出费率原值 ÷ 费用分母)`，然后核实签入的各币最低到账。若不存在该次请求，只记检查条件及当前配置，逐笔最小量保留交易级语义。

复投或调仓对用量、滑点、剩余资产设置保护时，核对其真实约束对象。Cetus 样本的对侧用量预算是 `预计用量 + floor(预计用量 × 容忍度原值 ÷ 分母)`，调仓收尾门槛另按指定币种解释。两者分别约束交易用量及剩余未部署资产，各自口径按所核实现披露。容量上限、收益和区间可承担性只有在已有适用预算或阈值时进入评分。 [Cetus 金库配置底稿](../research/cetus-configuration-assessment-346896130.json)

### 3.3 评分规则

| 档位上限／状态 | 判定条件 |
| --- | --- |
| 100 | 当前配置满足适用约束，必要状态符合已确认的业务条件 |
| 60 | 满足以下任一条件：① 触及事先明确且适用的警戒条件；② 必要操作异常部分受限，但同一受影响范围内仍有已核验的部分可用完成／退出路径。警戒条件独立成立时无需以替代路径作为附加条件 |
| 0 | 明确违反安全约束，或阻断必要资金取回且没有有效替代 |
| 0（证据缺失） | 适用的当前值、判断依据或必要路径结项时仍缺证，记录原因 |
| N/A | 不存在该机制或配置项，须说明依据 |

先查硬约束违反或必要路径完全阻断，再查适用警戒或异常部分受限，最后确认必要检查通过。100／60／0 为档位上限。只有通过和失败两种判据的项使用 100／0 档。

### 3.4 参数配置档内扣分

每行需核实当前配置、触发事实、实际适用的用户和头寸，以及适用的资产、数量、时间或预算约束。先按后果定档。表中“完整可用”指该条事实自身对必要权益的影响。在 60 档，定档异常照常保留，另行核实档内问题未进一步限制仍可用的路径或违反硬约束。

| 细分项 | 已核验的档内触发条件 | 扣分 | 何时换档 |
| --- | --- | ---: | --- |
| 份额与对象绑定 | 补充对象校验失效，资产、策略头寸和份额的主绑定校验实际仍覆盖全部现有权益，常规铸造与赎回步骤未增加 | 1 | 错绑已造成份额归属、结算或取回量违反硬性约束为 0。必要操作异常部分受限且有已核验的可用路径为 60 |
| 份额与对象绑定 | 当前绑定要求在铸造或赎回前额外刷新一次映射或提交一次迁移，全部适用用户仍以原受益人、原份额口径和适用期限完成 | 2 | 仅部分权益可通过迁移完成且尚无硬约束违反为 60。份额归属、结算量或硬性时限被破坏为 0 |
| 份额与对象绑定 | 独立的批量份额入口已失效，逐头寸入口可以对全部适用用户完成同样的存款或赎回，并维持原资金、份额口径和期限 | 3 | 部分头寸从所有可用路径均无法履行必要操作但仍有部分可用且未违反硬约束为 60。完全无法履行必要操作且无替代或违反硬约束为 0 |
| 赎回与领取 | 补充的领取对象校验或赎回状态复核失效，主路径仍实际验证受益人、当前可领状态和必要的最低净到账，用户步骤未增加 | 1 | 必要退出或领取异常部分受限并留有已核验部分路径为 60。错付、实付违反适用约束或必要路径完全阻断为 0 |
| 赎回与领取 | 现行配置单独增加一次请求确认、领取交易或额外等待，逐币净到账和原适用期限仍满足 | 2 | 超出预设适用警戒或部分必要动作异常受限为 60。违反硬性支付期限、最低净到账或完全阻断必要权益为 0 |
| 赎回与领取 | 附加的快速或批量退出／领取能力已关闭并无法使用，常规路径仍可在原适用时限内向全部用户完成各币种应付权益 | 3 | 常规及替代路径只能覆盖必要权益的一部分且无硬约束违反为 60。必要退出完全不可完成且无有效替代或已违反硬约束为 0 |
| 策略、复投与调仓 | 对实际调仓的补充用量、资产一致性或剩余量防护失效，主路径仍核实满足主要限额、余款归属和记账，操作无额外负担 | 1 | 触及预设适用的风险警戒或必要调仓部分异常受限为 60。实际授权限额、余款归属或头寸记录违反硬约束为 0 |
| 策略、复投与调仓 | 受当前配置影响，必要调仓或复投多一次中间余额领取／归集步骤，实际投入量、归属、期内可执行性和仓位记录仍可全部核验 | 2 | 补步只能恢复部分必要业务且未违反硬约束为 60。必要路径完全不可用且无替代或实际硬约束遭到违反为 0 |
| 策略、复投与调仓 | 独立的辅助批量调仓或可选复投模式失效，普通维护路径仍能按要求运行，全部用户的取回和收益领取权益均满足适用约束 | 3 | 已确认异常波及必要维护、退出或领取而只剩部分路径为 60。必要路径完全不可用且无替代或实际硬约束遭到违反为 0 |

同一金库业务和证据支持的范围先取适用配置项的最低档位上限，再扣去重后的独立轻微问题。按根因、范围和后果去重，同一事实取适用的最高扣分，由档位条件体现过的事实只用于定档。业务大项采用 100／60／0 三档时，100 档最终分为 61–100，60 档为 1–60，0 档为 0。整个计分单元仅有 100／0 两档时，其 100 档为 1–100。单个检查采用两档时，业务大项沿用自身适用的档位序列。无经核实的独立轻微问题时，采用该档上限。

```text
配置档位上限 B_config(m) = min { b_i | i 为同一范围内适用且独立计分的配置项 }
配置分 S_config(m) = max { 下一档上限 + 1, B_config(m) − 独立档内扣分合计 }
```

0 档直接记 0。适用的必要检查结项时仍缺证则记 0，保留缺证原因、已核事实和影响范围。所有检查项确实不适用时记 N/A。 [通用档内计分规则](./通用链上安全评估标准.md#13-先定档再计算档内分)

## 4. 资金与外部依赖

### 4.1 资金义务与可用资产

1. 按同一金库、币种和观察时限划分权益。区分仍在投资的份额、可申请的赎回、已应付的赎回或可领取收益。已确认的批次、队列记录或可证明的义务上界可以作为分母。按协议约定分辨当前应付与正常等待，记录本产品承诺的取回形式和期限。
2. 按同一义务分别核对金库闲置可付资产、已从底层释放的金额、可以在期限内实际取回的策略资产及其有效额度。账面权益经由策略或 Farm 包装时只核对应同一份底层头寸一次。仅将具有归属并经核验可在期限内用于该义务的金额列入可付资产，另列费用、奖励、已锁定资产及未知。
3. 同币种计算 `可支付 = 可用闲置余额 + 按期可达的已核策略回款`，`缺口 = max(0, 对应的实际应付 − 可支付)`。同一笔余额需扣除其他已保留或已确认更早到期的义务。存在已核实的实际转换时，按部署额度、可执行时限和实际净到账计入目标币种，并从来源扣除。使用精确金额或保守边界判定。可支付下界覆盖义务上界时可确认通过，义务下界高于可支付上界时可确认缺口。其余情形披露已核金额和范围，适用的必要资金覆盖检查按缺证记 0。

已核验的按双币份额退出按实物数量检查。Q64 型底层 CLMM 可用 [DEX 原生头寸拆分方法](./dex-onchain-security-rating-standard.md)估算该头寸的当前位置双币本金，再查实际退出程序、到账币种及费用。区间边界、未领奖励和现金归属各自记录。普通 LP 份额对应的底层资产可发生经济价值波动，按合同实际应付的数量、资产形式和期限判断。Cetus 的 haSUI/SUI 样本把金库份额、Farm 包装和底层 CLMM 头寸接成一条证据链，分别核对本金取回和当期奖励。 [Cetus 资金底稿](../research/cetus-funds-dependencies-review-346896130.json)

### 4.2 必要依赖和实际退路

评估金库实际使用的依赖当前是否满足必要条件，不对底层协议重新做安全评级。

| 检查项 | 核验内容 | 边界 |
| --- | --- | --- |
| 必要资金组件 | 底层当前状态是否支持金库已有权益对应的必要取回、结算或领取路径 | 正常锁定和约定等待不是失效；仅停止接受新增资金不自动扣分 |
| 必要估值输入 | 实际用于权益结算等业务的价格、兑换率或净值输入，是否满足已确认的有效性条件 | 页面参考估值不作为协议运行依赖；不重审估值算法 |
| 必要执行组件 | 当前链上可确认的状态是否支持必要业务执行 | 不以链上状态推断链下执行者或托管方一定正常 |
| 实际替代路径 | 主依赖异常时，已存在的替代是否当前有效、覆盖哪些权益和金额 | 配置中存在备用，不等于已有效承接 |

新鲜度、有效范围及其他条件按实际机制确定，不统一规定所有金库适用的超时或价格偏差。固定值或直接从当前状态计算的值，不机械套用时间戳要求。

对每条必要操作记录实际读取的价格组件、资金组件和执行资格。查到多个执行者时，按业务动作分别确认这些身份能否执行同一程序、是否还依赖同一报价或上级授权。授权状态仅证明资格，在线状态和实际签发需另有证据。对普通赎回、复投、调仓或可选的融资路径分别说明止付后果；一条可选路径读取额外价格源时，只关联实际依赖该源的操作。Cetus 样本核对了 Farm 和 CLMM 在普通双币退出中发挥的作用，并把额外融资路径的报价条件及单来源停止情景分列。 [Cetus 已采纳的当轮试评方法](../research/cetus-funds-dependencies-method-research-2026-11-20.json)

### 4.3 评分规则

| 档位上限／状态 | 判定条件 |
| --- | --- |
| 100 | 本检查涉及的适用资金义务均有足额同币资金，实际所需的输入和路径均有效。已核实的有效替代完整承接相应必要操作时计入 |
| 60 | 触及事先明确且适用的警戒，或必要业务异常部分受限且同一受影响范围仍有已核验的部分可用路径 |
| 0 | 已确认硬性资金义务覆盖失败，或必要路径异常完全不可用且无有效替代 |
| 0（证据缺失） | 适用的必要资金量、义务、时点、输入或运行路径结项时仍缺证，记录原因及范围 |
| N/A | 已核实不存在该项资金义务或必要依赖，保留原因 |

先查 0 档条件，再查 60 档条件，最后确认 100 档。100／60／0 为档位上限。

### 4.4 资金与外部依赖档内扣分

按对应币种、到期条件和业务必要性核实当前后果。按第 3.4 节确认档内问题的独立性及其对必要权益的影响。应付但尚未付的资金、已核实欠付、正常等候、受影响敞口和应急情景分别记录。仅在部署可验证时认定替代可用，写清备用路径可承担的币种、额度、时间和权益范围。

| 细分项 | 已核验的档内触发条件 | 扣分 | 何时换档 |
| --- | --- | ---: | --- |
| 资金与退出 | 承担实际义务的备用余额或第二回款渠道失效，当前独立来源以相同支付步骤、币种、金额和期限完整覆盖适用义务 | 1 | 达到预设适用的资金警戒或必要回款部分异常受限为 60。确认硬性义务出现实际覆盖缺口为 0 |
| 资金与退出 | 原可用回款方式当前异常，必须从实际策略多执行一次回款或归集，已核实按期到账的同币净额仍覆盖全部义务 | 2 | 同一影响范围内必要业务仅部分路径可用且尚无硬性缺口为 60。按期应付的币种和金额已确认不足或回款完全受阻且无替代为 0 |
| 资金与退出 | 已部署的可选加急或批量兑付功能当前不可用，普通路径已核实足额并按适用时限履行每项必要权益 | 3 | 普通及备用路径只能完成部分必要业务且无硬性违约为 60。确认实际欠付或必要退出完全受阻且无有效替代为 0 |
| 必要外部依赖 | 已启用的备用估值、执行或恢复来源失效，其余独立路径仍完全满足适用时效和额度，操作步骤未增加 | 1 | 已触及适用警戒或实际使用的必要输入／执行路径仅部分可用为 60。必要输入无有效替代且完全阻断必要业务或产生硬性违规为 0 |
| 必要外部依赖 | 实际执行者、状态续期或上游服务当前异常，使必要业务额外调用一次有效替代或刷新一次必要状态，并已核实所有相关权益仍能按期足额完成 | 2 | 替代只覆盖部分必要权益且无硬性违反为 60。完全失去必要服务导致必要权益无法履行且无替代，或实际违反硬约束为 0 |
| 必要外部依赖 | 已接入且实际适用的非必要外部功能独立失效，例如可选融资入口或额外的再部署路径不可用，普通赎回、领取和必要维护完整可用 | 3 | 故障同时导致必要取回、领取或维护部分异常受限为 60。必要操作完全受阻且无替代或已违反硬约束为 0 |

对资金与外部依赖采用第 3.4 节的档内区间及去重规则。单独的备用资金来源失效、主路径仍完整且无新增操作负担时扣 1。资金来源中断引起的归集、依赖和支付后果分别记录，同一根因在同一范围造成的同一后果只计一次。先按已确认的业务后果定档。该事实未决定档位时取适用的最高档内扣分。

例如，同一金库触及事先登记的资金警戒，资金与外部依赖取 60 档。该金库还独立失去一个已部署的辅助批量兑付服务，普通兑付仍能完成全部应付资金及期限要求，扣 3 分，最终得 57 分。若批量兑付失效已用于定档，该事实只参与定档。

```text
资金与外部依赖档位上限 B_funds_dependencies(m)
= min { b_j | j 为同一范围内适用、独立计分的资金义务或必要依赖项 }
资金与外部依赖分 S_funds_dependencies(m)
= max { 下一档上限 + 1, B_funds_dependencies(m) − 独立档内扣分合计 }
```

0 档直接记 0。适用的必要检查结项时仍缺证则记 0，保留已核事实、缺证原因及影响范围。全部检查项均已确认不适用时记 N/A。采集失败只证明存在证据缺口。

## 5. 资金状态与受影响敞口的披露

### 5.1 展示内容

| 展示项 | 最小内容 | 解释限制 |
| --- | --- | --- |
| 资产及权益口径 | 金库报告的资产、用户权益、计价单位；可独立核验的部分 | 协议自报资产不等于已证明足额兑付 |
| 当前资金分布 | 金库可直接控制的资产、底层协议／策略中的权益、未知部分 | 一层层持仓不能重复累计 |
| 集中度 | 各底层或已识别共同风险来源的敞口 | 集中不自动扣分，分散不自动加分 |
| 退出状态 | 当前可用、需从底层取回、锁定、待结算、已可领取的部分 | 按实际机制分类；不同分类可能重合，不能直接相加 |
| 已确认异常的影响 | 关联异常、受影响资产或权益、金额／比例及核验依据 | 退出受限不等于资产损失 |
| 已确认损失或缺口 | 在一致口径下可证明的损失／权益覆盖缺口 | 账面估值差异、缺少数据不直接视为坏账 |

即时退出比例高低不是通用安全指标。闲置资金为零、全部投入单一协议、正常排队或等待，均不自动扣分。单次成功退出不能证明所有用户可以同时退出；可见余额不直接等于可以向用户支付的金额。

### 5.2 敞口计算

只有口径一致、估值依据有效且没有重复计算时，才展示比例：

```text
异常受影响敞口比例
= 该异常实际影响的已核实资产价值
  ÷ 同一范围、同一估值口径下的资产总价值
```

分母无法核实时，只展示资产数量、已核实范围和未知部分，不输出百分比，也不按比例扣分。分母为零时比例不适用，不进行除法。多个异常影响同一资产时，分别关联原因；汇总影响不得直接累加重合部分。

例如：必要依赖当前赎回异常，影响金库 30% 的已核实资产敞口。该比例表示退出受限范围，不表示已经损失 30%，也不对应扣除 30 分。

## 6. 模块联动与去重

| 情况 | 处理 |
| --- | --- |
| 配置了错误的资金组件 | 配置计分，资金与外部依赖引用异常及影响 |
| 配置正确，但底层当前异常 | 资金与外部依赖计分，披露受影响敞口 |
| 管理者能改变资金去向，但当前配置正常 | 权限评估控制风险，配置按当前状态判断 |
| 危险操作控制者可以禁用已设计的退出入口 | 按生效权限与时间锁设置判断退出保护。当前资金可达性与实际付款由资金与外部依赖评估 |
| 已证实同币资金义务有缺口 | 在资金与外部依赖记录当前缺口及受影响范围，原因待核时另列 |

引用项仍展示异常状态，不伪装成正常或 N/A；标明计分归属，不重复进入接收模块的最小值公式。一个模块只有引用项而没有独立计分项时，显示“参见对应模块”，不补算满分。

## 7. 结项、更新与输出

### 7.1 证据缺失与适用性

结项时，仅计已确认的保护和替代路径。适用检查所需的必要条件仍缺证时，该项记 0 并保留在适用分母中，记录缺证原因、已核事实和影响范围。选配项缺证只披露，确认不适用才记 N/A。业务或项目适用 0 分封顶须另有确证，按实际影响范围判定。 [证据缺失与结项](./通用链上安全评估标准.md#5-证据缺失去重与结项) · [项目和业务风险封顶](./链上评估复用指南.md#项目和业务风险封顶)

资金披露缺少的字段只影响实际依赖它的必要检查。单列已确认的损失、缺口或退出异常。

### 7.2 更新规则

| 变化或状态 | 本轮处理 |
| --- | --- |
| 新 snapshot | 独立读取与判断，不因连续正常加分，也不要求连续多轮才恢复 |
| 权限主体、批准门限、控制模块或等待条件变化 | 更新受影响控制路径及分档，不因变化本身扣分 |
| 参数、资金去向或组件绑定变化 | 按当前值及仍适用的依据重算相关项 |
| 资产配置、锁定或领取状态变化 | 核对实际受影响义务、期限和可支付额度，同步更新评分与披露 |
| 升级使原能力或机制解释失效 | 重评依赖该解释的检查。结项仍缺必要证据的检查记 0，保留原始状态及失效依据 |
| 异常消除且证据完整 | 按当前符合的档位恢复，不继承历史处罚 |
| 数据缺失或采集失败 | 适用的必要检查缺证记 0，注明原因及范围。单列历史快照结果 |

### 7.3 最小证据与对外展示

| 信息 | 最小要求 |
| --- | --- |
| 范围 | 金库、链、必要关联对象、资产及用户权益范围，以及未覆盖部分 |
| 当前状态 | 区块／检查点及可用唯一标识、时间、读取对象和关键原始结果 |
| 解释依据 | 当前适用的代码能力／机制映射、约束及有效性条件；标明来源 |
| 判定 | 档位上下限和定档依据，独立轻微问题的证据及逐项扣分，最终整数分或 N/A，已证实的异常或缺证原因、受影响范围及计分归属 |
| 资金口径 | 自报／独立核验标识、资产单位、估值依据、分母范围及未知部分 |
| 规则版本 | 本标准版本和项目适用条件，支持复算 |

分别展示**权限管理、参数配置、资金与外部依赖**。资金与外部依赖同时给出各范围的可支付金额、义务、影响敞口和业务后果。项目汇总时，各大项先对前期确认的适用一级业务模块等权平均，再按权限 30%、参数配置 30%、资金与外部依赖 40% 加权。 [项目汇总和交付](./链上评估复用指南.md#3-项目汇总与正式交付)
