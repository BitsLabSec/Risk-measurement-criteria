# DeFi 链上评估的共同适用边界

当前三大项及分档以通用标准为准。项目业务对应的字段、公式、资金义务和外部路径使用类型专项。 [通用标准](./通用链上安全评估标准.md) · [类型专项索引](./README.md)

| 规则 | 如何适用 |
| --- | --- |
| 范围与快照 | 每项目每轮各链合计最多核验 50 个独立目标，同链同轮统一快照。优先从生产入口和共享对象开始。在明确必要操作和补证对象后下钻，局部证据支持局部结论。 |
| 权限 | 从实际角色、持有人及全部已确认替代路径找达到同一业务后果的最弱路径。各类型使用通用授权与延时档位及权限专用扣分表，以具体用户权益确认退出。 |
| 参数配置 | 核验当前有效的绑定、参数组合和必要操作状态。当前绑定错误或自身约束失效归配置。商业费率和额度随已采用的专项目标解释。 |
| 资金与依赖 | 按实际权益、币种和期限确认资金义务，区分现金、可调回资产与账面金额。实际采用的输入或外部组件异常，以及可核验的替代，归资金与外部依赖。 |
| 分档与范围 | 100、60、0 是配置和资金与外部依赖的通用档位上限，分别对应核验通过、已采用的警戒或已证实部分受限、硬约束失守或完全阻断。默认取同一业务大项及证据范围内最低适用上限，另按有据的独立问题细评。 |
| 档内扣分 | 以整数扣分，档内最低分为下一档上限加 1。0 档固定为 0。同一根因、范围和后果只计一次，已用于定档的事实不再扣分。专项明确采用组内汇总时，先评输入单元，再汇总。 |
| 结项 | 查不到相应保护就不计保护分。适用的必要检查缺证记 0 并留在分母，记录缺证原因。已证实不适用才记 N/A。 |
| 事实与情景 | 当前证据和已声明情景分列。只有对应专项或项目采用了该情景判据，才用它参与评分。提款高峰、价格压力或收入假设须记录来源和适用边界。 |
| 复合业务 | 沿用前期按功能划分的模块，共享状态读取一次。先算业务分并执行适用业务封顶，再在每一项目大项内等权平均适用业务分，按 30%／30%／40% 汇总。历史规则从原版本追溯。 |
| 封顶 | 局部风险只封受影响业务，该业务的封顶结果带入项目汇总。项目级风险封项目加权分。最终分取对应范围原分和适用上限中的较低值。 [汇总与封顶](./链上评估复用指南.md#3-项目汇总与正式交付) |

每个结果保留必要操作、范围、快照、资产或对象、原值和单位、机制与公式、证据、档位上限、档内下限、扣分理由和最终分。 [执行流程与交付](./链上评估复用指南.md)
