# BitsScore 同质化代币（Token）链上安全评估标准

v0.6 · 2026-11-24

每个快照分别输出**权限管理、参数配置、资金与外部依赖**。发行与资产控制权限评价可改变权益的实际路径，参数配置评价当前生效的转账及收费条件。资金与外部依赖按真实资金义务和必要转账组件判断适用。 [通用判据](./通用链上安全评估标准.md) · [范围和目标额度](./链上评估复用指南.md)

## 1. 对象与证据范围

适用于以 ERC-20 为代表的同质化代币。按链、代币合约或 mint 标识及当前部署确定对象。多链发行的同名资产分别核验。评估复用既有代码核验结论解释增发、冻结、收费等能力的实际后果，读取当前主体、控制路径、状态及参数。稳定币储备、桥接资产的支持情况、金库份额的赎回能力分别由相应业务专项说明。

每个快照固定区块或检查点、唯一标识及时间。默认读取全局设置、必要关联组件，以及已确认有业务差异的账户类别或转账方向。结论注明覆盖全体、某类账户、已核验地址还是特定交易池，无须遍历全部持有人和交易池。评级检查项可适配不同链的发行与冻结权限、转账费和外部校验机制。[ERC-20 接口规范](https://eips.ethereum.org/EIPS/eip-20) · [Solana 代币权限](https://solana.com/docs/tokens/basics/set-authority) · [Solana 代币扩展](https://solana.com/docs/tokens/extensions)

## 2. 发行与资产控制权限分

新评估的档位与档内扣分采用通用权限分表。以下类型后果及实际退出条件用于确定作用范围，旧分表用于追溯 v0.3 结果。 [复用指南第 1.3 节通用权限分表](./链上评估复用指南.md)

### 2.1 持有人承受的后果与 v0.3 历史分表

下列 H1／H2／H3 后果用于识别现行权限影响。表中的 A／B／C／D 档位及分值用于追溯 v0.3。

| 已确认的业务后果 | A 单组控制 | B 独立共同批准 | C 有效退出保护 | D 共同批准且有效退出 | 确认无对应能力 |
| --- | ---: | ---: | ---: | ---: | ---: |
| **H1 任意处分资产或改变权益**。能强制转走、销毁指定持有人的余额，向自选接收方任意增发，或在相关必要转移中实际收走全部或近乎全部金额 | 0 | 40 | 70 | 85 | 100 |
| **H2 在有效约束内改变权益**。能在不可绕过的实质额度内自主增发，或在实质约束内提高费用、改变豁免，使已有持有人承担额外成本或稀释 | 20 | 50 | 80 | 90 | 100 |
| **H3 可无限期阻断转移**。能冻结指定账户、通过名单阻断其转账或暂停全体转账，且缺乏不可延长的到期条件或独立恢复路径 | 30 | 60 | 75 | 90 | 100 |

| 档位 | 对完整控制路径的要求 |
| --- | --- |
| A | 单一实际控制组可实现该后果，且缺乏有效退出保护。 |
| B | 至少两个已证实独立的控制组必须共同批准。上级授权、主体替换或执行模块均无法提供更弱路径，且缺乏有效退出保护。 |
| C | 危险变更公开可见，等待不可绕过。当前证据支持受影响持有人在生效前独立完成能避开该后果的退出，控制者不能提前关闭该路径。此档未同时达到 B 的共同批准条件。 |
| D | 同时具备独立共同批准和有效退出保护。 |

### 2.2 现行退出保护和能力判定

从已生效的角色、门限、时间锁配置及其时长确认控制路径，核对缩短时长、绕过等待或替换执行主体的权限。按代码和链上配置确认已设计的退出入口能否避开相应后果，以及危险操作控制者能否禁用该入口。例如，增发稀释影响每单位代币对应的份额，转到自有地址仍受影响。设计了独立赎回时，沿其控制路径核对关闭权限。当前兑付能力由资金与外部依赖评估。

| 能力 | 快照证据与判定 |
| --- | --- |
| 增发与稀释 | 核验谁决定数量、时点和接收方，谁能提高上限、重授铸造权或更换实现。并列当前本链供应量、已核实上限、按现行规则剩余可增发量及上限控制者。固定计划可由任何人触发，若触发人无法改变其条件，就不将其视作自主增发者。 |
| 增发上限的实质 | 区分本期额度用完、不可变的总量上限，以及管理者可以放宽的限额。判断约束时说明当前供应与剩余额度的关系。形式上的上限须核实实际约束后才计入保护。披露已确认的能力和数值。判定后果或控制条件的必要证据在结项时仍缺失，该检查按缺证记 0。 |
| 强制转移与销毁 | 核验第三方能否在持有人未授权时处分其余额，注明适用账户与数量范围。持有人自行销毁，或应用仅使用持有人主动授予的额度，均不构成发行方任意处分权。 |
| 冻结、名单与暂停 | 分别检查限制发送、接收或全部转账的能力，以及解冻、续期和重复施加限制的主体。可持续冻结指定持有人即可在该范围构成 H3。即使单次冻结有时限，仍须检查同一主体能否连续延长实际限制。 |
| 调费、方向与豁免 | 核验可调区间、上限控制者、收费对象、豁免和方向规则。若能使某类用户的必要转移近乎全额收费，按受影响方向、代码规定的净到账及生效配置保留的替代入口判断 H1。近乎全额的判定须说明依据，不设跨代币通用费率红线。 |
| 间接控制 | 检查角色重授、升级、门限和执行模块变更、紧急通道、外部校验组件替换，以及不同角色是否归同一主体控制。把每条路径并入其实际可达的后果。例如铸造角色已撤销，但升级者能恢复任意增发，仍须评价该 H1 路径。 |

### 2.3 计算

对每项后果先比较完整路径的档位上限，再以适用后果的最低上限定档。新评估按指南核对同范围的独立权限扣分并计算最终分。历史 v0.3 批次按上方矩阵追溯。

完整核验后确认没有相应直接或间接能力，该后果进入 100 档。空角色、未发现路径或读取失败均不足以作此判断。关键能力映射、控制路径或授权证据缺失时，按第 5 节处理。

**永久失能特例。** 若已确认当前权限配置导致指定持有人按既定机制应当具备的必要转移永久失能，且已核验角色重授、升级、恢复、自动到期等相关路径均不能有效恢复，对受影响持有人及转账方向的 H3 直接记 0，优先于普通路径档位；不能因已无可行使的冻结权限记 100。

| 状态 | 判定 |
| --- | --- |
| 已确认必要转移永久失能，且无有效恢复路径 | 对应范围 H3 记 0，展示失能状态及核验依据。 |
| 当前暂停但仍存在有效恢复路径 | 按通用权限路径分表评价权限，当前配置按实际转账状态评价。 |
| 当前限制已知，但关键恢复或升级路径不能核验 | 展示已确认的限制。仅凭现有证据，永久性尚未证实，未核验的恢复保护不计入。H3 必要条件结项时仍缺证，该检查记 0 并注明原因。 |
| 协议本身不支持转让，或相关账户不具备既定转账资格 | 按机制及适用范围说明，不直接认定为异常永久失能。 |

证据应对应当前部署与受影响用户、代币及方向。暂时暂停、管理员已撤权或单次读取失败均不足以证明不存在有效恢复路径。

## 3. 当前转账与收费配置分

### 3.1 检查内容

| 检查项 | 读取结果与判定边界 |
| --- | --- |
| 全局转账状态 | 读取当前暂停状态、影响发送或接收的范围及生效豁免。分别展示普通地址和豁免地址适用的设置。开关开放只证明该配置允许操作。 |
| 名单与账户限制 | 核验名单模式、新账户默认状态及已核验对象的实际限制。全局采用名单、某个账户当前被冻结是两条作用范围不同的事实。 |
| 转账方向与限额 | 按实际规则核验普通转账、转入指定池或从池转出，以及相关单笔、余额或其他限额。对一个池的发现只发布该池或已验证绑定组的结论。 |
| 费用与豁免 | 读取当前生效的费率、固定费用或封顶值、收费对象和适用方向。普通持有人和豁免地址待遇有差异时并列展示。机制允许确定实际到账时，用同一转出数量对照。 |
| 代币和必要校验绑定 | 确认代币版本、币种精度、收款方及适用外部校验组件。绑定错误造成收费或必要转账保护失效时，在受影响范围记硬错误。组件当前状态见资金与外部依赖。 |

用真实整数运算顺序计算同一转出金额。单笔按比例扣费且费从投入中扣除时，`实际到账 = 转出量 − 实际扣费`。实际扣费沿合约应用方向、豁免、取整和封顶；另计费用的机制分别记录付款人扣款及收款人净收。用部署或产品对该对象已确认的安全约束与目前收费比较。无适用门槛的商业费率保留数值披露。

### 3.2 判定与计算

事先记录各项适用的安全约束、警戒条件及来源。已声明的业务限制应公开呈现，项目方声明本身不足以证明满足安全约束。

| 档位上限或状态 | 条件 |
| --- | --- |
| **100** | 当前设置符合已确认约束，该范围内按机制应当可用的转账路径符合条件。准入型代币按已核验准入条件解释，同时展示限制。 |
| **60** | 达到事先明确且适用的警戒条件；或必要转移异常部分受限，但同一受影响范围仍有已核验的部分可用路径。 |
| **0** | 明确违反安全约束，或对应持有人必要的转移路径完全受阻且无有效替代。 |
| **0（证据缺失）** | 适用的必要当前值、作用对象或安全约束结项时仍缺证，标明原因和范围。普通商业费率缺少适用评分门槛时按披露处理。 |
| **N/A** | 已确认该机制不存在或对当前对象不适用，如不具备转账收费功能。记录依据。 |

先判 0 档，再判 60 档。达到预设警戒可独立进入 60 档，不要求另行证明替代路径；异常部分受限时，须有同一受影响范围的已核验部分可用路径。只有满足／不满足两种结果的项使用 100／0 档。普通地址的必要转移若已完全受阻，另一个豁免群体仍可转账不能把前者改判为 60。当前修改规则的能力在权限模块计分，当前生效配置在本模块计分。同一根因在同一范围造成的同一后果只计一次，不同方向分别记录实际后果。

同一不可逆权限配置造成的已确认必要转移永久失能，在权限 H3 记 0；配置模块引用该异常，展示当前受阻状态及影响范围，不再次对同一原因计分。配置模块仍评价其他独立适用项；如果只有引用项，显示“参见权限”，不补算 100 或 N/A。独立的适用必要检查缺证按结项规则记 0。可恢复的暂停则按当前配置状态评分，暂停能力按权限路径另行评价。

### 3.3 配置扣分判据

| 检查项 | 扣 1 分 | 扣 2 分 | 扣 3 分 | 换档或适用性边界 |
| --- | --- | --- | --- | --- |
| 全局转账状态 | 已部署的二次状态保护停用，主入口仍按原条件校验并执行完整转账。 | 合资格持有人须完成一次新增的确认或刷新，同范围转账仍可足额按期完成。 | 可选批量发送功能失效，同范围持有人仍可逐笔按期发送全部应转金额。 | 同类合资格地址的必要转账异常部分受限且有路径时为 60，完全受阻且无有效替代为 0。 |
| 名单与账户限制 | 名单来源的独立核对保护削弱，主校验仍使用正确的账户资格。 | 同类合资格账户须经已核验的额外更新才能转账，原金额和期限完整保留。 | 已支持的可选名单更新通道失效，通过其他已核验路径仍可按期满足相同资格和转账条件。 | 实际名单配置违反适用硬约束时为 0。同资格账户若异常部分受限且有路径为 60，完全受阻且无替代为 0。正常准入或法定资格限制按机制披露。 |
| 转账方向与限额 | 特定方向的独立限额校验停用，生效主规则仍完整执行限额及用户权益约束。 | 同一资格和方向的合法金额须多笔提交，受核用户仍可在适用期限内转足且符合原约束。 | 现有的可选批量转账通道失效，所有适用转账方向仍可逐笔完整执行。 | 已采用的限额警戒命中为 60，违反当前硬约束或必要方向完全受阻且无替代为 0。正常设计限额按实际影响披露。 |
| 费用与豁免 | 独立收费或封顶复核削弱，实际费额、净到账和豁免仍按已确认规则执行。 | 同一合资格范围须多一步更新凭证才能适用原豁免，仍按原金额及期限到账。 | 可选自动优惠登记失效，同一范围仍可经现行入口及时足额兑现原豁免。 | 触发已采用的收费保护警戒为 60，实际费用或净到账违反适用硬约束时为 0。仅有商业费率及账户间费用差异不构成扣分。 |
| 代币和必要校验绑定 | 现有第二道代币版本或收款方核对保护退化，主路径的必要绑定和实际转账仍完整。 | 有效凭证需多做一次已核验的版本映射，原收款对象、币种、金额和期限均保留。 | 可选旧版本校验适配器失效，同一批合法凭证仍能用现行入口按原条款完成。 | 实际绑定错误影响资金归属、收费或使必要保护失效时为 0。实际来源或校验服务失效按资金与外部依赖评价。 |

## 4. 资金与外部依赖

| 检查项 | 当前读取与判定 |
| --- | --- |
| 普通代币的资金义务 | 核实声明的业务机制。没有固定赎回、兑付或托管义务时，资金义务项记 N/A。余额、市值及前十大持仓可以披露。 |
| 具备兑现权的代币 | 先确认权利实际由谁承接、资产、数额、资格及期限。份额赎回、质押换回、桥接资产或有明确支持义务的产品按其对应机制专项判定，代币分引用已计的结果。 |
| 必需外部校验或执行 | 核实正常发送、接收或特定方向是否必须调用该组件。绑定匹配归配置，当前组件失效及已有可用替代归资金与外部依赖。按实际依赖该组件的已纳入账户或方向限定范围。 |

适用资金义务有足额可用资金，必要依赖和路径均有效时进入 100 档。有效替代完整承接相应必要操作时计入。触发已采用的警戒，或必要操作异常部分受限且同一范围仍有已核验的部分可用路径时进入 60 档。资金硬约束违反，或必要转移完全受阻且无有效替代时进入 0 档。适用的必要检查结项时仍缺证，记 0 并注明原因。只有引用项时显示所参见的维度。直接责任和依赖都已确认不适用时，该模块记 N/A。

### 4.1 资金与外部依赖扣分判据

| 检查项 | 扣 1 分 | 扣 2 分 | 扣 3 分 | 换档或适用性边界 |
| --- | --- | --- | --- | --- |
| 普通代币的资金义务 | — | — | — | 已证实无兑付或托管义务时为 N/A。如证实有承诺，按下一项追到实际义务及承担者。结项时仍缺判定义务的必要证据，该检查按缺证记 0。 |
| 具备兑现权的代币 | 若有独立归属于代币的可兑现路径，已部署的备用减弱但原兑付仍全额按期。 | 该独立兑付路径增加一次已经核实的调拨或确认，仍按期足额到账。 | 该独立兑付路径的可选快速入口失效，常规入口仍按期全额兑现。 | 实际资金与兑现按对应业务专项的 60／0 条件判定，已计分结果在此引用。独立权益已证实违反兑付硬约束为 0。 |
| 必需外部校验或执行 | 独立校验备份或执行端减弱，主路径仍支持同一范围的全部必要转账且无新增负担。 | 已生效替代需多一次有效证明或执行步骤，原有资格、额度、到账期限均满足。 | 已部署的次要批量执行能力失效，既有必要转账仍逐笔按原条件完整执行。 | 触发适用警戒，或同范围异常部分受限且有可用路径时为 60；必要转账完全受阻且无替代为 0。已证实没有必要外部组件时为 N/A。 |

### 4.2 计分与去重

配置、资金与外部依赖各自按同一业务模块、同一大项和同一证据范围计分。先确定档位上限，再累计扣分。已部署的第二道保护或冗余削弱或失效，必要路径仍完整且无新增负担时扣 1。已有新增步骤、交易或等待，仍可足额、按期完成且符合硬约束和警戒边界时扣 2。独立次要业务功能已失效、必要权益仍可完整履行且未触发警戒时扣 3。60 档发生的独立轻微问题按自身造成的后果判断，定档事实只用于定档。

记录当前状态或事件、仍可满足原权益的路径证据、作用范围和扣量。单一事实取适用的最高扣量。独立问题按根因、范围和后果去重，已用于定档的事实只参与定档。必要证据缺失按第 5 节结项，已证实不适用记 N/A。 [通用档内计算规则](./通用链上安全评估标准.md#13-先定档再计算档内分)

```text
档位上限(m) = 同一业务模块及同一证据范围内适用独立检查项的最低档位上限
100 档的维度分(m) = max(该计分单元下一档上限 + 1, 100 − 独立适用扣分之和)
60 档的维度分(m) = max(1, 60 − 独立适用扣分之和)
0 档的维度分(m) = 0
```

业务大项采用三档时，100 档下限为 61。整个计分单元采用 100／0 两档时，100 档下限为 1。单个检查采用两档时，业务大项沿用自身适用的档位序列。

## 5. 输出、结项与更新

每条结论至少关联**链与代币标识、快照锚点、适用账户或方向、关键原始状态、机制或约束依据、规则版本、定档理由、档位上限、档内逐条扣分及最终分或状态**。区分以下情况：

- **未覆盖**表示对象不在此次声明范围内。某个池或账户的局部结论不能外推到所有持有人或市场。
- **证据缺失**。结项时仅计已确认的保护和替代路径。适用检查所需的必要条件仍缺证时，该项记 0 并保留在适用分母中，记录缺证原因、已核事实和影响范围。选配项缺证只披露。业务或项目适用 0 分封顶须另有确证，按实际影响范围判定。
- **N/A** 不参与定档或扣分。全部项已确认不适用时，模块显示 N/A。
- 新快照按当前授权、规则及绑定重新计算。升级使既有机制解释失效时，重评依赖它的检查。结项仍缺必要证据的检查记 0。
- **前十大持仓和代币市值**按已采用的展示范围单列。

权限保护按代码及生效的权限、延时和退出入口配置核验。兑付能力及外部组件的运行状态归资金与外部依赖。 [证据缺失与结项](./通用链上安全评估标准.md#5-证据缺失去重与结项) · [项目和业务风险封顶](./链上评估复用指南.md#项目和业务风险封顶)
