# BitsScore 链上评估复用指南

版本 v0.1｜2026-11-18。面向尚未迁移至执行器的类型试评。用链上证据回答一个问题：**协议能否继续健康运营，出现问题时会影响哪些用户权益和必要操作。** 本指南复用现有通用与类型标准的证据方法；加权总分在 Lending/NAVI 试用，未改变 [Lending v0.12 正式规则](./lending-onchain-security-rating-standard.md)、其他类型专项、扫描规则或前端，也不合并代码审计、业务攻防和盘外情报的分数。

## 1. 新项目先确定什么

1. **划范围。** 固定链、部署版本、业务、市场／池、资产、必要操作和直接依赖。把本次未覆盖的范围写明。代码／SDK 解释机制，链上对象说明作用于哪个部署、当前是什么状态。
2. **定义风险和阈值。** 每项先写清 `触发条件 → 实际路径 → 用户或业务后果 → 已有保护 → 剩余风险 → 影响范围`。区分当前异常、已证实的机制限制、假设压力。先冻结分母、情景、阈值、权重和适用条件，再计算项目；尚未校准的压力参数标为试评政策。
3. **分开采集要求和评分用途。** 必采或选配决定是否采；评分、披露或引用决定是否进公式。比如池内现金可作评分输入，TVL 和非必需收入可以只披露。优先复用已有快照、代码映射和汇总；不为填空默认查个人、逐笔交易或扩大市场。
4. **保留可复算证据。** 冻结区块／检查点、时间和版本；保存对象／调用、原值、单位、转换、证据定位、失败及影响范围。派生值保留公式和依赖项。先用单个案例校验规则；机制稳定后由引擎按规则读取与计算，只有部署、字段或业务逻辑变化才回到机制研究。

| --- | --- | --- |

| 权限与控制 | 特权函数及业务影响、必需／可选角色、当前持有人、最少不同密钥及门限、重叠、授权／升级／恢复／紧急旁路、强制延迟、协议退出开关 | 源码或验证机制＋链上 owner、cap、治理／多签状态。取完整可达路径；不要求证明签名人的链外身份。 |
| 业务风控配置 | 对象、单位与用途绑定；实际生效的费率、额度、风险参数与覆盖模式；暂停／冻结／替代状态 | ABI／源码说明单位和真实比较条件，链上读当前值。区分禁新增、存量限额、必要操作受阻。只采该类型实际使用的字段。 |
| 资金状态 | 按池与币种保存供应债权、借款、直接现金、费金库实际余额、账面国库份额和管理资产；衍生表保留价格时效与估值 | 链上池／储备／金库／已知管理器。原币优先；`现金`、`债权`、`借出`、`留存资产`分开。不同池或币不能默认互抵；同一金额不同时计作用户流动性和损失储备。无同类资产负债模型时换对应业务字段。 |
| 关键依赖 | 必要业务入口、实际报价或组件、主／备绑定及启用、最终消费端校验、异常和回退路径、受影响操作／范围 | 链上状态＋消费路径。分别核验过期、异常返回、调用失败或暂停；共同依赖和同源主备不能重复计冗余。缓存过期与实际无法更新分别记录。 |
| 收入和历史（按需披露） | 协议归属利息、窗口、来源范围、币种或估值基准；若已有可核验数据，再区分应计、到账、留存和用途 | 既有协议／索引汇总可作代理或交叉核对。混合手续费、当期 APR、借款本金、账面利息不能替代实收；不要求为披露项新增逐笔采集。 |

统一字段约定：每条至少带 `item_id / scope_id / required_or_optional / score_or_disclosure_or_reference / status / raw_value / unit / anchor_or_window / evidence_refs / formula_or_rule_id / weight / score_or_null / reason / impact_scope`。`U` 表示适用但证据不足，`N/A` 表示有证据确认不适用；另区分明确失败、未启用、未覆盖、不计分的引用。证据包和评级包分开，同一事实可被引用，不重复计分。更多来源与留痕见[元数据证据清单](../元数据采集与评分证据清单.md)。

## 3. 加权汇总：Lending 试评

| 模块 | 试评权重 | 主要回答 |
| --- | ---: | --- |
| 权限与控制 | 30% | 谁能取得危险能力，哪些约束真能阻止越权或让用户退出。 |
| 业务风控配置 | 30% | 当前参数是否支持有效的准入、清算、暴露限制和利率调节。 |
| 资金状态与关键依赖 | 40% | 资金能否周转，报价或直接组件失效时业务能否延续，以及额外缓冲有多少。 |

```text
S_onchain = 0.30 × S_permission + 0.30 × S_config + 0.40 × S_funds
```

资金与依赖权重略高，因为此试评更关注资金是否能周转、关键操作是否可用。模块分、贡献和重要风险同时展示。**只改变模块间的汇总。** 同一后果存在多条权限路径时，权限仍按实际最弱路径评价；若已有证据证明大范围必要业务受阻或单密钥能任意处分该范围用户本金，须显著标注受影响范围和重大风险，不能用平均分宣称该业务通过。若专项预先规定了封顶，另列触发事实及原始加权分；未经定义不自动设封顶或把任何局部低分当全局总分。

适用且有分的项按声明权重汇总。只有证实 `N/A` 才按预先规定重新归一，并公开实际分母。关键 `U` 的权重仍保留，不填 50 或 80；可将该项按 0–100 映射总分算术上下界，并保留已确认风险，不发布无证据支持的确定总分。若只具备范围不同的分项，不拼全协议总分。同根因同后果归主责项；例如暂停能力属权限，当前暂停状态属配置，独立外部依赖故障属依赖。

### 权限与控制

沿用 [Lending v0.12 第一部分的权限 v0.6](./lending-onchain-security-rating-standard.md)。从函数、角色、持有人闭合到所有可达的上级与绕过路径：必需角色按 AND 求联合的不同密钥，可任选路径按 OR 取更弱的完整路径。分别记录 H1 任意处分／权益重写、H2 业务条件变更、H3 必要操作阻断；辅助角色不以数量稀释关键路径。

| 路径 | 无有效延迟或不足 24h | 有效 24h 至不足 48h | 有效 48h 及以上 |
| --- | ---: | ---: | ---: |
| 单密钥可达 | 0 | 40 | 50 |
| 至少两把不同密钥强制共同批准且无单签旁路 | 80 | 85 | 95 |

有效延迟要求公开固定载荷、完整路径不可绕过、必要退出入口未被阻断且危险控制者不能提前关闭；排队剩余时间另外披露。完整核验后确认无对应能力才记 100。`S_permission = max(0, 最弱适用关键路径分 − 关联扣分)`；跨预定义关键域共享控制／密钥时最多一次扣 1，同一风险不按角色或多签对叠加；单签旁路按单签档。NAVI 是 `80 − 1 = 79`。其他类型的正式分档仍见各专项。

### 业务风控配置

按[配置方法](./lending-configuration-evaluation-method.md)的五组评估准入、清算、暴露、利率、模式：

```text
S_config_raw = 0.20 × 准入 + 0.25 × 清算 + 0.20 × 暴露 + 0.20 × 利率 + 0.15 × 模式
D_open = 1 − b / λ
H_after = (H_before − λ × β × f) / (1 − f)
M = 1 − λ × β
```

`b` 是最大有效开仓借款比例，`λ` 是有效清算线，`β` 是含奖励的总扣押倍率，`f` 是情景中偿还的债务比例。`M` 用于单抵押、单债务、价格不变、剩余抵押为正的部分清算情景：清算线附近 `M>0` 支持清算后健康度改善；不能据此推导全市场坏账。上限按代码的实际单位、计息状态和比较条件计算 `占用 = 当前适用计量值 / 有效上限`，超上限不自动等于允许继续新增；禁用或无上限不代入除法。利率用协议原生利用率和实际曲线校验拐点、反馈与限额，不用通用 `B/S` 替代。特殊模式用真实覆盖参数及允许方向重算，未知使用规模不假定覆盖全部供应。若已确认重大失效，只按配置方法预定的适用范围处理。NAVI 五组试评为 `80 / 85 / 80 / 85 / 80`，加权 **82.25**；其中增量档仍属案例判断，不能当自动规则或给未知项补一个基础分。

### 资金状态与关键依赖

```text
单池提现缺口_i(r) = max(0, r × 供应者债权_i − 池内直接现金_i)
提现覆盖率(r) = 100 × [1 − Σ(快照价格_i × 单池缺口_i) / Σ(快照价格_i × r × 供应者债权_i)]
S_liquidity = mean(提现覆盖率(5%), 提现覆盖率(10%), 提现覆盖率(15%))

S_dependency = 报价有效性检查分（40）+ 常规还款不依赖报价分（20）
             + 15 × 主源过期时可切换的供应金额占比
             + 25 × 主源适配器报错时可切换的供应金额占比

单池压力净损失_i = 1% × 借款余额_i
S_loss = 100 × Σ[快照价格_i × min(同池同币可用协议现金_i, 单池压力净损失_i)]
             / Σ(快照价格_i × 单池压力净损失_i)
S_funds = 0.90 × (45 × S_liquidity + 25 × S_dependency) / 70 + 0.10 × S_loss
```

- **提现。** 三档是敏感性比较用的政策情景。直接现金按实际池和币种配对；只在额度和可达性已经验证的情况下，另算含转换／调拨的情景。协议规模、TVL 不加分；缓存报价用于聚合时注明时间及有效性限制。
- **依赖。** 上式为 NAVI 路径试评分配。40 和 20 是对应保护经核验后得到的满分；存在不同影响范围时按已确认范围披露，未知不填分。同源主备不算独立冗余；分别验证“主源过期”与“调用失败”能否到达备源，不能用来源数量替代。NAVI 为 `40 + 20 + 15 × 78.07% + 25 × 0% ≈ 71.71`，常规还款可用性不等于所有必要操作正常。
- **损失吸收与恢复。** 测一次清算完成后仍有净损失的情景，即使机器人正常工作也可能出现。NAVI 只计可提取的独立手续费现金作为**潜在**同池缓冲，非赔付承诺；用户现金和账面国库债权不计，不做未经验证的跨池分配。1% 是试评强度，0.5%／2% 只做敏感性；此项仅占第三模块 10%、链上总分 4%。没有适用债务／损失分母时按 `N/A` 判断，不补满分。
- **收入披露。** 在同一损失项说明补库门槛，`所需留存并补入的比例 = 假设已动用缓冲 / (90 × min(近30日日均协议利息, 前60日日均协议利息))`。只有已知期限、正的收入分母才计算；收入汇总不证明已到账及能净补库，不另计分，也不假设固定间隔再发生一次损失。

NAVI 以检查点 `345771824` 和既有 35 个池复算：提现周转 **88.77**，关键依赖 **71.71**，净损失覆盖 **34.72**；第三模块 **77.88**。三模块加权 `79 × 30% + 82.25 × 30% + 77.8798856006 × 40% = 79.52695424024`，**展示 79.53，整数 80**。用未舍入分数计算，只有展示时舍入。见[计算结果、权重与证据来源](../research/navi-onchain-weighted-rating-2026-11-18.json)和[资金情景明细](../research/lending-sustainable-operations-research-2026-11-18.md#低权重净损失情景与-navi-复算)。

## 4. 套到其他类别时换什么

| 类型 | 先确定哪些必要操作 | 替换哪些采集对象和输入 |
| --- | --- | --- |
| [DEX](./dex-onchain-security-rating-standard.md) | 交易、撤资、结算 | 已选池的实际资产、费用和权限，必要路由、适配器或 Hook；不默认全量扫池，不套借款坏账。 |
| [收益金库](./yield-vault-onchain-security-rating-standard.md) | 赎回、领取、从策略取回资金 | 空闲底层资产、实际策略分配、赎回队列和已确认可调回额度；提现需求以有权赎回的份额／资产及实际时限定义。 |
| [永续](./perpetuals-onchain-security-rating-standard.md) | 减仓、结算、提取保证金 | 保证金和结算配置、价格依赖、已确认保险／风险准备及结算状态；没有池级范围和证据时不重建逐仓盈亏或全平台结算差额。 |
| [同质化代币](./fungible-token-onchain-security-rating-standard.md) | 持有人必要转账、协议约定的赎回／兑现（若有） | 发行／冻结／升级、费率和限额、校验组件；普通代币不凭市值补一个资金安全分。必要校验若已归配置，依赖模块仅引用。 |

复用的是**范围、证据格式、控制路径、资金匹配、故障测试和加权方法**。每个类型仍需先冻结自己的必要操作、经济指标、阈值、权重和缺失处理；不沿用 Lending 的权重、清算公式或坏账情景作为默认。正式标准未定义同范围总分的类型，迁移前仍按各自规则发布。

## 5. 新项目的最小交付

| 输出 | 至少填什么 |
| --- | --- |
| 范围记录 | 类型和版本、锚点、纳入对象及必要业务、未覆盖范围、适用与不适用理由 |
| 采集规则 | 已确认对象、读取方式、单位与转换、来源优先级、失败处理；读数保留证据 ID 和可重复定位 |
| 评分规则 | 风险情景与因果路径、公式和分档、分母与权重、适用范围、未知及重大异常的处理 |
| 评估结果 | 原值和派生值、模块分、权重贡献、总分或区间、主要风险、披露和证据限制；分数原因须能指回具体字段和判据 |
