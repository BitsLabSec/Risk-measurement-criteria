# BitsScore 通用链上安全评估标准

- 版本 v0.5，更新日期 2026-11-24
- 适用范围：已明确纳入评估的链上业务、资产、用户权益及其必要组件。
- 评估方式：固定各链快照，分别输出权限管理、参数配置、资金与外部依赖结果。三项共同判断当前状态能否支持协议长期正常运行。
- 规则性质：分值是评级政策档位，尚未经过损失样本校准，不代表攻击或损失概率。

通用标准定义分档、扣分、证据和结项规则。类型专项落实具体读取对象、公式及适用条件。项目和业务汇总及风险封顶以链上评估复用指南为准。 [类型专项索引](./README.md) · [项目汇总与交付](./链上评估复用指南.md#3-项目汇总与正式交付)

## 1. 使用方法与边界

### 1.1 通用项、专项与特殊情况

| 层次 | 内容 | 实施方式 |
| --- | --- | --- |
| 通用检查项 | 各类型共用的权限、配置、资金与外部依赖问题及分档 | 使用本文的通用判据及复用指南的执行顺序。 |
| 类型专项 | 业务实际使用的能力、参数、必要操作、资金义务和依赖 | 按业务功能选择专项。使用专项确认的输入、公式及适用阈值。同一功能所涉及的多个合约归入同一业务。 |
| 机制差异 | 实际机制与专项默认条件不同 | 登记实际机制、适用范围和逐项替代依据。未采用的警戒阈值只披露读数。适用的必要检查按第 5 节结项规则计分。 |

采用旧版规则的既有结果按其规则版本、范围和快照追溯。新评估在范围确定时登记适用的通用版本、专项版本及已确认的项目判据。

项目有多项业务时，沿用前期按功能划分的业务模块，依次加载适用专项。检查结论注明业务、链、组件、资产、用户权益及操作范围。共用事实可复用，同一根因、同一范围、同一后果按第 5 节去重。

### 1.2 快照与代码边界

- 每轮独立判断当前状态。同一链绑定一致的区块或检查点、可用唯一标识及时间；跨链分别记录锚点和确认状态。
- 执行目标沿用范围清单。每项目每轮跨链合计最多核验 50 个独立目标，按链及地址或对象 ID 去重。顶层足以判断时停止下钻，只对已说明用途的具名对象补证。 [范围与核验流程](./链上评估复用指南.md)
- 复用仍适用的代码评估、机制映射和控制独立性证据。代码侧解释能力及实现，链上侧评价当前控制路径、配置与必要依赖。
- 当前快照用于确认当前资格、实际生效的配置及必要输入的有效性。权限按当前角色、控制路径及配置的延时评价。历史表现、累计事件和连续正常次数不作为本轮分数的必要输入。
- 按实际机制及约定范围采集。局部市场、地址或池的结果不直接代表其他对象；无法形成平台级结论时披露范围。
- 前期确定适用的约束、警戒条件及依据。项目方说明可以作为线索，但单凭声明不足以证明安全条件成立。

### 1.3 先定档再计算档内分

1. **先按证据定档。** 评分表中的数字是档位上限。同一业务模块、同一大项、同一证据可支持的评分范围，默认取适用检查项中最低的档位上限。专项明确要求先对资产、市场或其他计分单元分别评分并汇总时，先对各输入单元定档和细评，再使用专项公式。计算得到的汇总值无需再定档。
2. **再评档内问题。** 每个问题须有当前证据、适用扣分条款和可说明的实际后果，并核实该问题仍符合已定档条件。同一问题适用多条时只取最高扣分。同一根因、同一范围、同一后果只计一次。已用于确定当前档位的事实只参与定档。独立问题可以累加，累计结果须留在本档内。
3. **按整数算档内分。** 存在下一档时，本档最低分等于下一档上限加 1。使用该计分单元适用分表的档位序列。0 档固定为 0。必要判据缺证时按第 5 节结项规则计分。已证实不适用时记 N/A。各级汇总可保留小数。

```text
档内最低分 = 下一档上限 + 1
档内得分 = max(档内最低分, 本档上限 − 独立适用扣分之和)
```

例如适用 100／60／0 分表时，100 档最多可扣到 61 分，60 档最多可扣到 1 分。扣分计算达到档内下限时，仍保留全部有据问题和实际扣分明细。新证据满足较低档判据时重新定档。只有 100／0 的检查项按自身硬判据确定档位，不因档内问题引入 60 档。若所在业务大项使用通用三档，业务档内下限仍按三档计算。

**参数配置及资金与外部依赖的通用扣分尺**

| 每个独立问题扣分 | 判定条件 |
| ---: | --- |
| 1 | 已部署的第二道保护、备用路径或可用余量已削弱或失效。独立主路径仍按原条件覆盖全部必要业务，当前无额外操作负担。 |
| 2 | 已证实增加操作步骤、交易次数或等待。相同资格范围仍可足额、按期完成相关必要操作，并符合各项硬约束及警戒边界。 |
| 3 | 已证实一项独立的次要业务功能不可用，例如可主动使用的批量或快速入口。全部相关必要权益仍可完整履行，当前事实未触发已采用的警戒。仅提供同一业务冗余的备用失效适用 1 分条款。 |

专项用具体对象、读数和执行路径落实上表。100 档按适用问题扣分。60 档只扣触发警戒或部分受限之外的独立问题。表中权益仍可履行的条件针对该独立问题自身，定档时已计入的另一异常可以继续存在。若新增事实进一步影响必要权益、触发已采用的警戒或违反硬约束，按实际后果参与定档。0 档保留问题与范围，不另扣。设计上无选配功能、没有已采用安全阈值的商业取舍、未经核实的风险猜测只按原规则披露，不构成档内扣分。

## 2. 权限与控制

新一轮 DeFi 评估的权限档位及档内扣分统一按链上评估复用指南第 1.3 节执行。各类型专项用于确定业务后果、保护对象和退出路径。下方 v0.1 分表用于追溯采用该版本的结果。 [链上评估复用指南](./链上评估复用指南.md)

### 2.1 通用检查项

| 编号 | 检查项 | 核验内容 |
| --- | --- | --- |
| P1 | 资产及权益处分 | 当前是否存在任意处分用户资产或重写权益的能力，谁能执行，覆盖哪些资产和用户。 |
| P2 | 条件变更 | 是否能在约束内改变已有用户的业务条件，形成额外风险；核验可修改范围以及约束能否解除或反复绕过。 |
| P3 | 必要操作阻断 | 是否能无限期阻断已有用户的必要操作；核验受影响操作、用户范围及不可自行延长的到期或独立恢复路径。 |

沿直接执行、角色授予、控制者替换、升级、模块、门限调整、紧急通道和恢复路径，追踪实际控制主体。多个角色的控制重合、共享签名人及最弱可达路径均纳入同一权限图。多签、管理员、延迟与模块是路径证据，不单独计分。

### 2.2 业务后果与分档（v0.1 历史规则）

| 通用后果 | A 单组控制 | B 独立共同批准 | C 有效退出保护 | D 共同批准＋有效退出 | 确认无对应能力 |
| --- | ---: | ---: | ---: | ---: | ---: |
| P1／H1 任意处分资产或重写权益 | 0 | 40 | 70 | 85 | 100 |
| P2／H2 受约束地改变条件，对已有用户造成额外风险，尚未达到 H1 | 20 | 50 | 80 | 90 | 100 |
| P3／H3 在缺乏不可延长的到期或独立恢复保障时，无限期阻断必要操作 | 30 | 60 | 75 | 90 | 100 |

| 控制档位 | 判定条件 |
| --- | --- |
| A | 单一实际控制组可以沿完整路径造成相应后果，且缺乏有效退出保护。 |
| B | 至少两个已证实独立的控制组必须共同批准，没有更弱的上级、升级或替代路径，且缺乏有效退出保护。 |
| C | 危险变更公开可见、完整路径的等待不可绕过。当前证据支持受影响用户在生效前避开该后果，危险操作控制者不能提前关闭退出路径。未同时满足 B。 |
| D | 同时满足 B 的强制独立共同批准和 C 的有效退出保护。 |

有效退出应覆盖声明范围内实际必要的操作。等待时间、账户资格和资金条件须结合当前状态判断；排队变更使用当前剩余窗口。地址不同、表面多签门限、仅有否决权或仅有延迟，均不足以单独提升档位。保护只对已有证据支持的用户及资金范围成立。

### 2.3 公式与例外（v0.1 历史规则）

设 `m` 为声明的业务、资产及用户权益范围，`h` 为适用后果，`P(m,h)` 为当前可达到该后果的完整控制路径集合，`q(p)` 为路径档位，`L(h,q)` 为上表分值。

```text
路径分 S(p,h) = L(h, q(p))
后果分 S(m,h) = min { S(p,h) | p ∈ P(m,h) }
权限分 S_permission(m) = min { S(m,h) | h 为适用后果 }
```

| 情况 | 处理 |
| --- | --- |
| 完整核验后确认不存在对应直接或间接能力 | 该后果记 100。角色空置、未发现路径或读取失败不足以证明无能力。 |
| 关键路径、控制独立性或退出证据缺失且可能改变档位 | 对应后果为 U，保留已确认风险，不发布该范围确定权限分。 |
| 当前权限配置已使该范围必要操作永久失能，经核验不存在有效恢复路径 | 对应项直接记 0，优先于普通路径档位。暂时暂停或管理员撤权本身不足以证明永久失能。 |
| 机制本身不提供相关操作或对象不具备既定资格 | 按实际适用条件处理，不直接认定为异常失能。 |

永久失能例外已同步至五类专项。例如已确认 Token 持有人按既定机制应有的必要转移永久失能，且重授、升级、恢复和自动到期等有效路径均不能恢复时，受影响范围的 P3／H3 记 0。

### 2.4 五类专项映射

| 类型 | P1／P2／P3 业务内容 | 退出保护的类型判定 |
| --- | --- | --- |
| Lending v0.9 | 资产或债务处分、抵押与清算条件变更、还款／提款／清算阻断 | 核验协议退出／还款入口和延迟保护，普通还款与抵押前提按机制说明，不要求逐账户证明。 |
| DEX | 用户资产处分、费用及结算条件变更、必要撤资或结算阻断 | 按实际涉及的用户权益核验撤资或结算。 |
| 收益金库 | 资金去向或权益改变、策略与费用变更、必要赎回阻断 | 查赎回与领取入口在权限配置中是否保留，危险操作的控制者能否关停这些入口。 |
| 永续合约 | 保证金或结算权益处分、已有仓位风险条件变更、减仓／结算／提款阻断 | 持仓人可能须依次减仓、结算和提款。 |
| 同质化代币 | 任意增发或强制处分、受约束增发或调费、冻结或转移阻断 | 转到自己另一个地址无法避开增发稀释，须按实际有效路径判断。 |

## 3. 参数配置

### 3.1 通用检查项

| 编号 | 检查项 | 读取和判断 |
| --- | --- | --- |
| C1 | 关键对象绑定 | 核实资产、池或市场、收款方、价格源、策略和结算组件的实际绑定。按用途、归属、版本兼容性、单位及精度判断。已证实错绑或单位错误会改变估值、收费、资产归属或结算时，在相应作用范围记硬错误。 |
| C2 | 参数及其组合 | 核对实际生效的费率、限额及其他保护参数，按消费逻辑联合计算。违反适用硬约束或组合导致保护失效时按已证实后果判定。触发已采用、适用的警戒才给部分分。只有商业比较意义的数值按披露处理。 |
| C3 | 必要操作状态 | 检查暂停、冻结、名单、限额和其他开关对交易、结算、还款、提款或撤资的实际作用。区分停止新增、机制规定的等待、存量权益操作异常受限。部分可用性的证据应来自同一批受影响用户、资产和操作。 |

从有效值追到代码消费位置。注明全局默认、局部覆盖或单次交易输入，记录单位、合并规则及适用对象。用专项核验机制上限、条件组合及必要操作是否正常。同一配置对同一后果只计一次。管理者对配置的修改能力归权限。

### 3.2 分档与公式

| 档位上限或状态 | 判定条件 |
| --- | --- |
| 100 | 必要证据齐备，当前设置符合适用安全约束，必要操作满足已确认状态条件。确认该业务无可由特权改变的参数，且固定配置符合约束时，本项核验通过。 |
| 60 | 触发事先采用且适用的警戒，或必要操作出现异常部分受限且同一范围仍有已核验的部分可用路径。 |
| 0 | 证实当前配置违反适用硬约束，或完全阻断该范围的必要操作且无有效替代。适用检查在结项时仍缺必要当前值、单位、绑定、机制或路径证据，也记 0，另列缺证原因。 |
| N/A | 已确认该机制或操作不适用，记录依据。 |

先判 0，再判 60，已完成必要核验的通过项归 100 档。只有通过和失败的硬判据使用 100／0。已采用的专项警戒可以独立触发 60 档。当前配置违反硬约束须重新核对有效读数及代码作用。尚无评级阈值的商业取舍保留读数和影响说明。

```text
配置档位上限 B_config(m) = 同一范围内适用独立配置项的最低档位上限
配置分 S_config(m) = 按第 1.3 节计算该范围内的档内得分
```

| 检查项 | 档内扣分举例 | 改判较低档的事实 |
| --- | --- | --- |
| C1 关键对象绑定 | 次要交叉校验绑定已失效，主绑定及保护仍生效，无额外操作，扣 1。 | 必需资产、收款方、精度或结算对象错绑，已使安全约束失效，记 0。 |
| C2 参数及其组合 | 生效限额导致已证实的额外分次操作，必要权益仍能按适用期限完整执行，扣 2。 | 参数达到已采用警戒记 60。组合违反已确认硬约束记 0。 |
| C3 必要操作状态 | 次要快捷入口被实际配置关闭，已核实正常入口覆盖相同资格、资产、金额和时限，扣 3。 | 部分必要权益异常受限且同范围仍有可核验路径，记 60。必要操作全阻断且无替代，记 0。 |

### 3.3 选择专项

以独立业务功能判断类型。同一套协议的现货、借贷、策略金库和奖励功能可使用不同专项。共享配置读取一次，记录可证实的管辖范围。某池或市场的结果保留在该范围内。若有适用专项，用该专项确定需要哪些字段、如何归一单位、怎样计算和何时触发已采用的警戒。 [类型专项索引](./README.md)

## 4. 资金与外部依赖

### 4.1 通用检查项

| 编号 | 检查项 | 读取和判断 |
| --- | --- | --- |
| F1 | 资金义务与可用资产 | 先确定已承诺的币种、金额或份额、时限及用户资格。核对对应余额、应付、负债、锁定或已支付记录。固定金额义务按同币可用资金匹配。有份额或原币分配机制时按实际兑付规则判断。 |
| F2 | 资金调拨和取回 | 从实际付款或退出入口追到资金所在、可达额度、耗时及限制。区分直接现金、应计债权、已保留资金和经策略或外部池才能取回的资产。只有可证实能够按需到达的资金用于对应结论。 |
| D1 | 必要输入 | 从业务消费端确认实际采用的报价、签名、兑换率或其他必需输入，核对对象、有效条件和当前状态。当前配置的绑定关系引用 C1。 |
| D2 | 依赖路径和有效替代 | 确认实际使用的执行者、结算组件、策略和外部资金路径。分别判断对新增业务、存量结算和原有资产退出的影响。备用要有可用证据，注明独立性、适用操作、额度和时间。 |

按币种、权益归属及期限对账。一个资金余额用于多个义务时，按真实分配规则或可核验的共同预算处理。对可变份额和头寸，使用实际资产和结算条件。用保守边界核对时，可用资金下界覆盖义务上界可确认足额。义务下界高于可用资金上界可确认缺口。两组区间重叠且没有其他付款证据时，不能确认足额，适用覆盖检查按缺证记 0。TVL、账面收入和余额大小单列披露。另记读取失败的原因，当前依赖失败需有实际输入、链上状态或消费路径支持。

### 4.2 分档与公式

| 档位上限或状态 | 判定条件 |
| --- | --- |
| 100 | 必要证据齐备，适用资金义务有可用资金或已证实可达来源，必要输入及路径符合条件。已核验的替代可完整承接相应业务。 |
| 60 | 触发事前采用且适用的资金或依赖警戒，或必要操作异常部分受限且同一受影响范围仍有可核验的部分完成或退出路径。 |
| 0 | 已证实当前违反硬性资金或兑付约束，或必要输入、执行组件或资金路径失效导致必要操作完全受阻且无有效替代。适用检查在结项时仍缺必要义务、可用资金、有效输入或实际路径证据，也记 0，另列缺证原因。 |
| N/A | 该范围确无对应义务、必要输入或依赖，记录依据。 |

当前状态和假设情景分别记录。类型专项采用情景计分时，先固定停供来源、业务后果、覆盖范围和合同时间边界。沿实际路径验证资金、替代或退出能否承接。历史试评的压力值、时间窗和权重按对应版本追溯。

~~~text
资金与外部依赖档位上限 B_funds(m) = 同一范围内适用独立资金或依赖项的最低档位上限
资金与外部依赖分 S_funds(m) = 按第 1.3 节计算该范围内的档内得分
~~~

| 检查项 | 档内扣分举例 | 改判较低档的事实 |
| --- | --- | --- |
| F1 资金义务与可用资产 | 已设置的备用现金来源有可证实的额度收缩。可即时或按期动用的同币金额仍足额，且未触发适用警戒，扣 1。 | 命中已采用的覆盖率警戒记 60。证实违反到期兑付硬约束记 0。 |
| F2 资金调拨和取回 | 已核实完整取回需额外执行一次调拨，相关资金仍可足额按期到达，扣 2。 | 异常部分受限且同范围尚可完成部分，记 60。必要支付完全受阻且无替代，记 0。 |
| D1 必要输入 | 已启用的独立备源实际可覆盖的对象减少，主源仍覆盖全部相关操作且无额外负担，扣 1。 | 已核实实际输入失效导致部分必要操作受限且余下可用，记 60。必要操作全部受阻且无有效备源，记 0。 |
| D2 依赖路径和有效替代 | 独立次要结算或退出入口已不可用，已验证主路径仍完整承接全部必要权益，扣 3。 | 必要结算或退出部分受限且同范围有剩余路径，记 60。完全受阻且无有效替代，记 0。 |

专项另有明确采用的分项汇总方式时，披露公式、分母和规则版本，同时保留主要短板和作用范围。结项按第 5 节处理证据缺口。

### 4.3 选择专项

资金义务从实际产品权利确定。例如 Lending 的池级现金与供应债权、DEX 或策略金库按实际资产份额退出、订单按订单余额结算或退款、Farm 按已释放奖励核付。外部组件依据执行、结算和退出各自的实际消费路径检查。 [类型专项索引](./README.md)

## 5. 证据缺失、去重与结项

按已确认的范围、快照、来源和 50 个目标额度查完即结项。查不到的多签、时间锁、备用资金、报价或替代路径按没有相应保护计分。如果缺少的是确认适用必要检查通过的证据，该检查记 0，留在分母。原始读数保留缺失状态，评分字段记录数值 0，原因用「证据未取得」，与「已证实失败」分别记录。仅选配或披露项查不到时，只记录事实缺口。明确证实不适用时才用 N/A。

例如已知某路径受多签控制，但未取得可证明强制等待的证据，按无有效延时档出分。已确认存在到期兑付义务但未取得资金可用证据，资金检查记 0。证据不足的 0 分用于检查计分，单独触发业务或项目的 0 分封顶仍须有确证。

| 情况 | 处理 |
| --- | --- |
| 同一管理员影响多个业务 | 路径证据读取一次，按各业务的实际后果分别判断。 |
| 同一配置既可修改、当前又异常 | 权限评价修改能力；配置评价当前状态。 |
| 配置绑定错误导致依赖异常 | 配置计分；依赖引用该异常和影响。 |
| 绑定正确，但外部输入或组件失效 | 在资金与外部依赖计分，配置引用实际影响。采用旧版 Token 规则的结果按原版本追溯。 |
| 同一根因影响多个专项 | 同一范围、同一后果只计一次，关联所有受影响业务。不同后果分别判断。 |
| 同一事实既命中档位判据又出现在扣分表 | 使用该事实定档。档内明细只列额外的独立计分问题；同一事实产生的重复引用仅作证据关联。 |
| 同一不可逆权限配置造成当前永久失能 | 权限对应项记 0；配置引用并展示受影响操作。 |
| 必要证据未取得 | 适用检查按结项规则计分，并显示原始证据范围及缺证原因。 |
| 全部检查项确为 N/A | 显示 N/A，不记 100。 |
| 模块只有引用项 | 显示“参见对应模块”并关联实际计分项，引用本身不进大项分母。 |
| 评估对象未纳入范围 | 标“未覆盖”，不冒充已检查或不适用。 |
| 指标缺少适用评级阈值 | 保留已确认的硬约束、实际运行结论和读数。未采用的警戒只披露，必要事实缺失按结项规则计分。 |
| 新快照、权限或配置变化 | 用当前状态重算受影响项；异常消除且证据完整时按当前档位恢复。 |
| 升级使既有机制解释失效 | 使用新版本对应证据计分，结项时仍未取得的必要证据按缺证处理，并保留原始读数。 |

## 6. 披露及项目汇总边界

每条结论记录业务类型、链、对象、用户／资产／操作范围、快照锚点、读取值、规则版本、定档依据、档位上限、适用档内下限、逐条扣分及证据、扣分合计和最终分或 N/A。跨模块引用注明原因归属和影响范围。

各业务分别呈现权限管理、参数配置、资金与外部依赖分项原分。业务封顶处理后进入项目汇总。项目各大项内对适用业务等权平均，再按 30%／30%／40% 汇总，最后执行适用的项目级封顶。 [计算与封顶](./链上评估复用指南.md#3-项目汇总与正式交付)
