# BitsScore 通用链上安全评估标准

- 版本：v0.1
- 适用范围：已明确纳入评估的链上业务、资产、用户权益及其必要组件。
- 评估方式：每次独立使用一个 snapshot，分别输出权限、配置、必要依赖结果。
- 规则性质：分值是评级政策档位，尚未经过损失样本校准，不代表攻击或损失概率。

本标准依据 [Lending](./lending-onchain-security-rating-standard.md)、[DEX](./dex-onchain-security-rating-standard.md)、[收益金库](./yield-vault-onchain-security-rating-standard.md)、[永续合约](./perpetuals-onchain-security-rating-standard.md)和[同质化代币](./fungible-token-onchain-security-rating-standard.md)五类既有标准制定。

## 1. 使用方法与边界

### 1.1 通用项、专项与特殊情况

| 层次 | 内容 | 实施方式 |
| --- | --- | --- |
| 通用检查项 | 所有类型共用的权限、配置与必要依赖问题及分档 | 本文规定检查对象、分数和证据口径。 |
| 类型专项 | 业务特有的能力、参数、必要操作及依赖 | 加载适用类型，使用专项规定的具体判定条件。专项内容填入通用检查项，不重复生成同义评分项。 |
| 特殊情况 | 实际项目机制与标准默认适用条件存在差异 | 记录涉及项、机制差异、调整理由、替代判定、证据、范围及复核条件。证据不足标 U。 |

项目有多项业务时，依次加载各适用专项，形成共同检查集。检查结论注明业务、链、组件、资产、用户权益及操作范围。共用事实可复用，同一条件和同一后果按第 5 节去重。

### 1.2 快照与代码边界

- 每轮独立判断当前状态。同一链绑定一致的区块或检查点、可用唯一标识及时间；跨链分别记录锚点和确认状态。
- 复用仍适用的代码评估、机制映射和控制独立性证据。代码侧解释能力及实现，链上侧评价当前控制路径、配置与必要依赖。
- 当前快照可计算输入年龄、已排队操作的剩余窗口及当前资格。历史表现、累计事件和连续正常次数不作为本轮分数的必要输入。
- 按实际机制及约定范围采集。局部市场、地址或池的结果不直接代表其他对象；无法形成平台级结论时披露范围。
- 前期确定适用的约束、警戒条件及依据。项目方说明可以作为线索，但单凭声明不足以证明安全条件成立。

## 2. 权限与控制

### 2.1 通用检查项

| 编号 | 检查项 | 核验内容 |
| --- | --- | --- |
| P1 | 资产及权益处分 | 当前是否存在任意处分用户资产或重写权益的能力，谁能执行，覆盖哪些资产和用户。 |
| P2 | 条件变更 | 是否能在约束内改变已有用户的业务条件，形成额外风险；核验可修改范围以及约束能否解除或反复绕过。 |
| P3 | 必要操作阻断 | 是否能无限期阻断已有用户的必要操作；核验受影响操作、用户范围及不可自行延长的到期或独立恢复路径。 |

沿直接执行、角色授予、控制者替换、升级、模块、门限调整、紧急通道和恢复路径，追踪实际控制主体。多个角色的控制重合、共享签名人及最弱可达路径均纳入同一权限图。多签、管理员、延迟与模块是路径证据，不单独计分。

### 2.2 业务后果与分档

| 通用后果 | A 单组控制 | B 独立共同批准 | C 有效退出保护 | D 共同批准＋有效退出 | 确认无对应能力 |
| --- | ---: | ---: | ---: | ---: | ---: |
| P1／H1 任意处分资产或重写权益 | 0 | 40 | 70 | 85 | 100 |
| P2／H2 受约束地改变条件，对已有用户造成额外风险，尚未达到 H1 | 20 | 50 | 80 | 90 | 100 |
| P3／H3 在缺乏不可延长的到期或独立恢复保障时，无限期阻断必要操作 | 30 | 60 | 75 | 90 | 100 |

| 控制档位 | 判定条件 |
| --- | --- |
| A | 单一实际控制组可以沿完整路径造成相应后果，且缺乏有效退出保护。 |
| B | 至少两个已证实独立的控制组必须共同批准，没有更弱的上级、升级或替代路径，且缺乏有效退出保护。 |
| C | 危险变更公开可见、完整路径的等待不可绕过。当前证据支持受影响用户在生效前避开该后果，危险操作控制者不能提前关闭退出路径。未同时满足 B。 |
| D | 同时满足 B 的强制独立共同批准和 C 的有效退出保护。 |

有效退出应覆盖声明范围内实际必要的操作。等待时间、账户资格和资金条件须结合当前状态判断；排队变更使用当前剩余窗口。地址不同、表面多签门限、仅有否决权或仅有延迟，均不足以单独提升档位。保护只对已有证据支持的用户及资金范围成立。

### 2.3 公式与例外

设 `m` 为声明的业务、资产及用户权益范围，`h` 为适用后果，`P(m,h)` 为当前可达到该后果的完整控制路径集合，`q(p)` 为路径档位，`L(h,q)` 为上表分值。

```text
路径分 S(p,h) = L(h, q(p))
后果分 S(m,h) = min { S(p,h) | p ∈ P(m,h) }
权限分 S_permission(m) = min { S(m,h) | h 为适用后果 }
```

| 情况 | 处理 |
| --- | --- |
| 完整核验后确认不存在对应直接或间接能力 | 该后果记 100。角色空置、未发现路径或读取失败不足以证明无能力。 |
| 关键路径、控制独立性或退出证据缺失且可能改变档位 | 对应后果为 U，保留已确认风险，不发布该范围确定权限分。 |
| 当前权限配置已使该范围必要操作永久失能，经核验不存在有效恢复路径 | 对应项直接记 0，优先于普通路径档位。暂时暂停或管理员撤权本身不足以证明永久失能。 |
| 机制本身不提供相关操作或对象不具备既定资格 | 按实际适用条件处理，不直接认定为异常失能。 |

永久失能例外已同步至五类专项。例如已确认 Token 持有人按既定机制应有的必要转移永久失能，且重授、升级、恢复和自动到期等有效路径均不能恢复时，受影响范围的 P3／H3 记 0。

### 2.4 五类专项映射

| 类型 | P1／P2／P3 业务内容 | 退出保护的类型判定 |
| --- | --- | --- |
| Lending | 资产或债务处分、抵押与清算条件变更、还款／提款／清算阻断 | 出借人核验提款条件，借款人按机制可能需要先还款。 |
| DEX | 用户资产处分、费用及结算条件变更、必要撤资或结算阻断 | 按实际涉及的用户权益核验撤资或结算。 |
| 收益金库 | 资金去向或权益改变、策略与费用变更、必要赎回阻断 | 对照锁定、赎回和领取条件与危险变更剩余窗口。 |
| 永续合约 | 保证金或结算权益处分、已有仓位风险条件变更、减仓／结算／提款阻断 | 持仓人可能须依次减仓、结算和提款。 |
| 同质化代币 | 任意增发或强制处分、受约束增发或调费、冻结或转移阻断 | 转到自己另一个地址无法避开增发稀释，须按实际有效路径判断。 |

## 3. 当前配置

### 3.1 通用检查项

| 编号 | 检查项 | 需要判断的当前状态 |
| --- | --- | --- |
| C1 | 关键对象及绑定 | 资产、接收或结算对象、策略、价格源及必要组件，是否满足已确认的用途、归属、单位和兼容性要求。 |
| C2 | 业务参数及约束 | 费用、额度、风险参数及其组合，是否满足适用安全约束，是否触及有依据的警戒条件。 |
| C3 | 必要操作状态 | 开关、名单及限制是否异常阻断已有用户按机制应能执行的必要操作。 |

同一配置按根因只归属一个计分项。例如 Lending 清算费用与清算激励合并评价；Token 某方向的费率和豁免作为同一适用收费规则评价。管理者能否修改配置在权限模块评价。

### 3.2 分档与公式

| 结果 | 判定条件 |
| --- | --- |
| 100 | 当前设置满足已确认的适用约束，必要操作状态符合业务条件。 |
| 60 | 触及事先明确的警戒条件；或同一受影响范围的必要操作异常部分受限，仍有已核验的部分可用路径。 |
| 0 | 明确违反适用约束，或协议自身配置完全阻断该范围的必要操作且无有效替代。 |
| U | 当前值、适用约束或关键证据不足。 |
| N/A | 已确认该机制或操作不适用，记录依据。 |

Lending 等经济参数的 60 分可依据已核验的缓冲不足或适配警戒，不要求同时存在替代操作路径。仅有满足／不满足两种状态时采用 100／0，不强设 60。

```text
配置分 S_config(m) = min { s_i | i 为同一范围内适用且独立计分的配置项 }
```

### 3.3 五类专项映射

| 类型 | C1 关键绑定 | C2 专项参数 | C3 必要操作 |
| --- | --- | --- | --- |
| Lending | 抵押／借款资产用途、价格源及计价映射 | 抵押和清算参数、清算激励、风险上限、利率、特殊模式 | 已有用户还款、提款和清算 |
| DEX | 交易、收款及结算组件 | 交易／结算费用和适用限制 | 已有资金撤资与结算 |
| 收益金库 | 策略、底层资金组件及接收对象 | 分配限制、费用及退出参数 | 赎回、领取和资金取回 |
| 永续合约 | 保证金、价格及结算组件 | 保证金、清算及风险限制 | 已有仓位减仓、结算和可用保证金提款 |
| 同质化代币 | 代币及必要转账校验组件 | 方向费率、豁免和限额 | 普通地址及特定类别的转账状态 |

Lending 专项 C7 对应本文 C3，按市场、资产、用户资格与操作判断。正常抵押约束、正常排队或仅停止新增借款不自动扣分。现金不足归资金状态，外部组件失效归必要依赖。

## 4. 必要依赖

### 4.1 通用检查项与分档

| 编号 | 检查项 | 当前核验内容 |
| --- | --- | --- |
| D1 | 必要输入 | 实际采用的价格、兑换率或其他输入是否满足适用的有效性条件；有可比参考时按专项规则判断一致性。 |
| D2 | 必要组件与路径 | 外部资金、结算或执行组件的当前状态是否支持相应必要操作；已生效的替代路径覆盖哪些范围。 |

备用路径是 D1／D2 的判定条件。仅有备用配置不足以证明它已经生效。正常等待按实际机制判断；采集接口失败不能直接证明依赖故障。

| 结果 | 判定条件 |
| --- | --- |
| 100 | 必要输入和路径满足条件，或有效备用已完整承接。 |
| 60 | 达到适用警戒，或异常部分受限但有已核验的部分可用路径。 |
| 0 | 必要输入明确失效，或必要路径不可用且无有效替代。 |
| U | 当前状态或适用依据不足。 |
| N/A | 已确认不存在对应必要依赖，记录依据。 |

```text
依赖分 S_dependency(m) = min { s_j | j 为同一范围内适用且独立计分的必要依赖项 }
```

### 4.2 专项规则与 Token 例外

Lending、DEX、收益金库和永续合约按各自机制检查实际必要输入与组件。Lending 的价格偏离阈值、来源可信性 40／0 封顶属于该专项，不自动应用于其他类型。

同质化代币现有标准将必要外部转账校验的绑定及运行状态放在配置分内。本版继续按该专项归属计算。依赖维度引用该事实，标注“参见配置”，不重复计分。

- 项目另有独立必要依赖时，依赖模块继续评价那些依赖。
- 模块只有引用项时显示“参见对应模块”，不补算 100 或 N/A。
- 只有确认不存在相应必要依赖时才标 N/A。
- 后续若把 Token 校验组件迁入依赖模块，须作为单独规则变更，重新计算受影响的配置分与依赖分。

## 5. 去重、未知与更新

| 情况 | 处理 |
| --- | --- |
| 同一管理员影响多个业务 | 路径证据读取一次，按各业务的实际后果分别判断。 |
| 同一配置既可修改、当前又异常 | 权限评价修改能力；配置评价当前状态。 |
| 配置绑定错误导致依赖异常 | 配置计分；依赖引用该异常和影响。 |
| 绑定正确，但外部输入或组件失效 | 依赖计分；配置引用实际影响。Token 依第 4.2 节处理。 |
| 同一根因影响多个专项 | 同一范围、同一后果只计一次，关联所有受影响业务。不同后果分别判断。 |
| 同一不可逆权限配置造成当前永久失能 | 权限对应项记 0；配置引用并展示受影响操作。 |
| 适用关键项 U | 展示已确认结果与风险，暂不发布该范围的确定维度分。不能剔除未知项后得满分。 |
| 全部检查项确为 N/A | 显示 N/A，不记 100。 |
| 模块只有引用项 | 显示“参见对应模块”，不记 N/A 或 100。 |
| 评估对象未纳入范围 | 标“未覆盖”，不冒充已检查或不适用。 |
| 新快照、权限或配置变化 | 用当前状态重算受影响项；异常消除且证据完整时按当前档位恢复。 |
| 升级使既有机制解释失效 | 仅将依赖该解释的项标 U 待复核，原始读取可继续展示。 |

## 6. 披露及项目汇总边界

每条结论记录业务类型、链、对象、用户／资产／操作范围、快照锚点、读取值、机制与约束依据、分数或 U／N/A、判定理由和规则版本。跨模块引用注明原因归属和影响范围。

Lending 的流动性、头寸和坏账，收益金库的资金分布与退出状态，永续的结算异常，以及 Token 的前十大持仓和市值，依各自专项披露规则处理。现有披露项不因纳入通用框架自动变成计分项。

三个维度分别展示。本版未确定复合项目的最终总分权重或项目级风险封顶。代码安全和业务攻防的终审报告封顶，以及 Lending 来源可信性封顶，继续适用于各自原模块。
