# Launchpad 发行、领取与退款链上安全评估专项

版本 v0.3｜2026-11-24。适用于按具名发行池和购买凭证向用户履行配售、退款义务的功能。权限适用通用分表。 [通用链上标准](./通用链上安全评估标准.md)

## 1. 确定范围

固定发行池、部署版本和快照。按机制标明募集中、失败或取消、已成功结算待领取等阶段，列出该阶段需要核验的认购、结算、领取和退款路径。优先读取全局和发行池对象、机制所需的累积字段。项目当轮所有独立核验目标统一计入 50 个上限。所选历史发行池的结论只覆盖其存量权利。

权限从结算、取消发行、修改有效配售或退款条款、调拨用户预留和提取发行人收入的实际入口出发，分别确定控制者能达到的后果及最弱路径。核对已生效的角色、门限、时间锁时长和可绕过路径。按代码和当前权限配置核对危险操作控制者能否禁用已设计的领取或退款入口。 [复用指南第 1.3 节通用权限分表](./链上评估复用指南.md)

## 3. 资金与外部依赖

1. 逐池、逐币区分配售库存、退款现金、发行人可提款和其他已预留用途。用当前用户可支取的余额对比剩余配售或退款义务。对以池状态和凭证到账的实际付款，分别核对领取、退款及对应扣账。
2. 缺少全部未领用户余额汇总时，可以用池级守恒和取整导出义务上界。核对初始预留覆盖全部合约分配、其后发行人只提专属份额、用户领取时严格同步扣库、领取凭证限制重复支付，以及额外充值是否增加承诺。证明这些条件截至快照仍成立后，可比较用户预留与剩余责任上界，避免枚举全部购买者。原币余额低于仅有的保守上界时，查已核下界或实际无法支付的证据，结项仍缺必要证据时，资金覆盖检查按缺证记 0，单列原因。
3. 募资和结算阶段按实际机制核验时间、价格或流动性注入依赖。已结算池按现存操作核验，若领取和退款直接由同币预留支付，分别记录付款路径和已证实不适用的依赖。用户领取后的独立市场出售及撮合按相应业务范围处理。

## 计分与去重

参数配置、资金与外部依赖分别计分。先按结项规则确定适用状态，再取同一业务模块、同一大项和同一证据范围内适用独立检查项的最低档位上限。

再累计该范围内独立、已证实、未决定当前档位的轻微问题。逐条记录当前状态或事件、仍可履行原权益的路径证据、影响范围和扣量。扣 1 分适用于已证实的第二道保护或纯备用削弱、失效，且独立主路径仍按原条件覆盖相关必要操作，未增加负担。扣 2 分适用于已证实的新增操作负担，必要权益仍按原约束履行。扣 3 分适用于已证实的独立次要业务功能失效，该事实本身未影响必要权益按原约束完整履行，也未命中已采用的警戒。单一事实取满足条件的最高扣量，按根因、范围和后果去重。同一事实触发警戒、异常部分受限或硬失败时用于定档，不再按轻微问题扣分。

0 档固定 0 分。以扣分合计为 `d`，100 档得 `max(61, 100 − d)`，60 档得 `max(1, 60 − d)`。事先未采用的商业阈值只作披露。配置绑定或开关异常归配置，资金或外部运行路径本身异常归资金与外部依赖。同一事实跨表引用时只计一次。 [通用档内计算规则](./通用链上安全评估标准.md#13-先定档再计算档内分)

按正式范围及本轮目标额度完成核验。未取得证据的保护或替代按未具备相应保护计分。结项时仍缺可用证据的适用必要检查记 0，其所属计分模块仍纳入大项分母。分别记录「证据未取得」和「已证实失败」。未经证实的选配项仅披露。已证实不适用的项记 N/A。同一根因在同一范围造成同一后果时，由责任项计分。仅引用的结果标出责任项，引用本身不进入分母。 [证据缺失与结项](./通用链上安全评估标准.md#5-证据缺失去重与结项)

先确定各大项得分，再按复用指南计算业务和项目原始分，并在相应范围分别应用风险封顶。局部风险对应受影响的业务，项目封顶须核对全项目的控制或后果。缺证导致的检查 0 分按结项规则计入原始分。0 分封顶须有确证。 [项目和业务风险封顶](./链上评估复用指南.md#项目和业务风险封顶)

**Cetus 复算入口。** `launch-allocation-refund` 和 `launch-owner-and-user-partition` 对应两个具名结束池。早期池以购买量和白名单保护份额推导配售、退款上界，后期超募池再核对有效认购的整数组合和已用流动性预留。两份证明只说明用户预留覆盖义务，精确未领总额仍需相应累积证据。 [配置底稿](../research/cetus-configuration-assessment-346896130.json) · [资金底稿的 focusedReviews.launchpad](../research/cetus-funds-dependencies-review-346896130.json)
