# BitsScore DEX 链上安全评估标准

- 记录日期：2026-11-10
- 文档版本 v0.5，更新于 2026-11-24。
- 适用范围为声明的 DEX 现货功能、选定池或报价簿及其必要关联对象。原生 AMM、聚合执行和 RFQ 各按交易、结算、取回资产的实际路径核验。
- 各链使用声明的快照，分别输出权限管理、参数配置、资金与外部依赖。各业务的结果保留适用范围，向项目汇总提供一级业务模块分。
- 评分表中的数字为档位上限，当前分数由档位和独立档内扣分决定。项目范围、权限分表和对象上限见[链上评估复用指南](./链上评估复用指南.md)，通用配置和资金判定见[通用链上安全评估标准](./通用链上安全评估标准.md)。

## 1. 评估范围与代码安全边界

### 1.1 复用已确认机制，只评价当前状态

资金保管、交易结算、退出机制、函数能力及其可能造成的业务后果，由代码安全评估或仍适用的既有核验结论提供。链上模块不重新寻找代码漏洞或重新评价机制设计，只将这些已有结论与当前链上状态对应。

| 问题 | 归属 |
| --- | --- |
| 某函数能否任意转移用户资产，哪些调用组合能达到相同后果 | 代码侧已有能力确认，作为链上评估输入 |
| 当前谁掌握相关权限，角色授予、门限、模块或延迟是否允许绕过约束 | 链上权限评分 |
| 某参数的含义、实现和安全约束是什么 | 已确认机制与适用依据，作为输入 |
| 当前参数值、开关、绑定地址是否满足这些约束 | 链上配置评分 |
| 外部依赖为何必要，其输入应满足什么有效性条件 | 已确认机制与适用依据，作为输入 |
| 协议当前使用的必要输入和相关链上路径是否正常 | 链上依赖评分 |

已有机制映射不足时记录缺口并按结项规则评分。链上评估复用代码侧核验结果。

### 1.2 不预设 Uniswap 架构，不全量扫描交易对

- 不默认项目存在 Factory、Router、交易池、LP、预言机或其他特定组件。按实际存在且与评估问题相关的对象检查。
- 项目方提供对象清单，我们核对并固定评估范围；项目方提供不等于已经核验。
- 需要检查具体交易池时，仅纳入明确选定的池，注明选择范围和遗漏范围；其他池不自动继承本次结论。
- 先核对产品入口、共享配置和必要结算对象，再按关键路径的证据需要选定池、路由或报价簿。所有模块共用每项目每轮最多 50 个独立核验目标的额度，按链与地址或对象 ID 去重。
- 流动性深度、LP 集中度、池内价格偏离等不作为本版默认评分项。确需评价项目自营或承担明确责任的核心池时，后续另行确定专项。
- 对链下报价、撮合或执行服务，仅使用本模块能够确认的链上状态；不据此推断链下实现安全或服务可用性。

### 1.3 单快照原则

- 同一链的状态绑定指定区块或检查点、可用唯一标识及时间；记录链、对象、读取结果及必要取证时间。
- 每轮独立计算，不依赖上一轮分数、历史趋势、累计事件或连续正常次数。
- 可以复用仍适用于当前部署和来源的代码机制、控制独立性及其他既有证据，不要求每轮重新审计或背景调查。
- 使用当前区块时间核实报价等必要输入的有效状态。
- 外部参考数据注明来源、取证时间和适用条件；跨链状态分别绑定各链快照，不冒充完全同步。
- 不同资产、组件或用户范围存在实质差异时分别评价，不能通过其他无关高分项稀释局部风险。

## 2. 当前权限配置

现行权限分按[链上评估复用指南第 1.3 节](./链上评估复用指南.md)的通用分表计算。本节确定 DEX 的控制路径和业务后果。旧版分表和公式保留用于追溯 DEX v0.2 结果。

### 2.1 检查内容

在已确认能力映射上读取已生效的管理员、角色持有人、授予关系、多签门限与模块、时间锁配置及其时长，形成当前完整控制路径。

应追踪可替换管理员、改变门限、启用执行模块、绕过等待或获得同等能力的上级路径。多个角色或地址的控制重合，按已有核验依据处理；地址不同不能直接证明控制主体独立。

角色、多签、Timelock 是控制路径的组成部分，不作为独立加分项。不重新评价代码报告中的中心化风险等级，报告相关内容可作为线索或说明。

在原生 AMM，能任意划走用户池资产或改写 LP 权益的实际路径归 H1。受约束但能改变存量用户收费或结算条件的路径归 H2。聚合路由和 RFQ 分别核对能否处分用户资产、修改存量结算条件，或无到期或独立恢复地阻断必要结算及取回（H3）。仅能提交报价、处理做市商自有库存或配置用户逐笔接受的新交易条件的，先按其实际能力确定后果。必须经过的审批、共享签名人和控制端替换随路径记入通用权限分表。用代码和已生效的链上权限配置核对危险操作控制者能否关闭已设计的撤资、领费、订单取消或库存取回入口。

### 2.2 业务后果与路径分值（v0.2 历史口径）

| 已确认业务后果 | A：单一控制组 | B：强制独立共同批准 | C：有效退出保护 | D：共同批准＋退出保护 | 确认无对应能力 |
| --- | ---: | ---: | ---: | ---: | ---: |
| H1：任意处分用户资产或重写用户权益 | 0 | 40 | 70 | 85 | 100 |
| H2：在约束内改变费用或交易、结算条件，对用户产生额外风险，尚未达到 H1 | 20 | 50 | 80 | 90 | 100 |
| H3：无明确到期或独立恢复保障地阻断用户必要的资金取回、撤资或结算 | 30 | 60 | 75 | 90 | 100 |

按已确认的实际业务后果分类，不能仅依据权限或函数名称。普通收费、用户主动接受的新交易条件，不自动构成 H2。暂停新交易与阻断已有用户资金退出分别判断，不能一律归为 H3。

### 2.3 控制档位的认定（v0.2 历史口径）

| 档位 | 认定条件 |
| --- | --- |
| A | 单一实际控制组可沿完整路径造成相应后果，且不满足有效退出保护 |
| B | 必须由至少两个已证实独立的控制组共同批准；当前没有上级替换、模块等更弱路径；不满足有效退出保护 |
| C | 危险改变公开可见，完整路径存在不可绕过的等待，且声明范围内当前退出条件有证据支持；不同时满足 B |
| D | 同时满足 B 的独立共同批准与 C 的有效退出保护 |

v0.2 历史退出保护判据如下。

- 等待、目标及影响范围可以核验；已排队操作使用当前剩余窗口。
- 上级路径、紧急通道或模块不能提前实现同等危险后果；危险操作控制者不能提前解除保护或关闭退出入口。
- 退出条件采用既有机制及当前可核验状态，按实际涉及的用户资金、订单或权益范围判断；没有相应资金暴露时不强设 LP 撤资要求。
- 不统一规定等待多少小时就安全；只存在 Timelock 不足以取得 C／D。
- 当前退出条件不保证未来整个等待期间都可退出，也不保证所有用户同时退出。
- 独立主体仅拥有主动否决能力，不等同于强制共同批准。

### 2.4 公式与特殊处理（v0.2 历史口径）

设 `m` 为声明的评估范围，`h` 为适用业务后果，`P(m,h)` 为当前配置下已确认可达到该后果的完整控制路径集合，`q(p)` 为路径控制档位，`L(h,q)` 为上表分值：

```text
路径分 S(p,h) = L(h, q(p))
后果分 S(m,h) = min { S(p,h) | p ∈ P(m,h) }
权限分 S_permission(m) = min { S(m,h) | h 为适用业务后果 }
```

| 情况 | 处理 |
| --- | --- |
| 已完整核验相关范围，确认不存在对应直接或间接能力 | 该后果记 100；不能仅凭未发现路径、角色无人持有或读取失败作此判断 |
| 当前权限配置已使必要资金取回路径永久失能 | 对应项直接记 0，优先于普通路径分档；不能因管理员已放弃权限取得满分 |
| 暂停具有不可自行延长的到期或独立恢复保障 | 不按无限期阻断处理，当前可用性影响由相关模块说明 |
| 约束仅保护部分用户或资金 | 按实际覆盖范围评价，不将保护外推到全部用户 |
| 关键控制路径、能力映射或独立性无法确认 | 对应项为 U；展示已确认结果，受影响范围暂不发布确定权限分 |

## 3. 当前关键配置

### 3.1 评分对象

仅纳入实际影响安全、且具有已确认含义和判断依据的当前配置，例如费用、收款地址、关键组件绑定、交易与资金退出开关。不同 DEX 采用不同的适用项，不要求列出所有参数。

每项事先确定适用对象、安全约束或警戒条件、依据及规则版本。不能看到结果后临时调整标准以维持分数。

### 3.2 分档

| 结果 | 档位上限 | 判定条件 |
| --- | ---: | --- |
| 当前满足要求 | 100 | 当前值满足已确认的安全约束；必要业务状态符合适用条件 |
| 当前部分受限或触及警戒 | 60 | 满足事先确定且适用的警戒条件；或必要业务异常部分受限，同一受影响范围仍有已核验的部分可用完成／退出路径 |
| 当前明确不满足 | 0 | 当前配置违反已确认的安全约束，或已阻断对应必要资金取回／结算路径且无有效替代 |
| 必要证据缺失 | 0 | 适用的当前值、约束或必要路径结项时仍缺证，记录缺证原因 |
| 不适用 | N/A | 项目不存在对应机制或配置项，须说明依据 |

先查硬约束与必要操作的失败条件，再查已采用警戒及异常部分受限，最后确认必要保护通过。100／60／0 为档位上限。只有通过和失败的判据使用 100／0 档。

### 3.3 实际判定口径

| 配置内容 | 判定方式 |
| --- | --- |
| 费用 | 按已确认的收费约束判断，不统一规定超过某个费率就不安全；不同收费组成按实际机制解释 |
| 收款或组件地址 | 核对已确认的归属、绑定及兼容性要求，不因地址陌生就扣分，也不因地址非零就判正常 |
| 业务开关 | 结合实际影响判断；停止新增业务但允许已有资金退出，不自动扣分 |
| 正常等待或限制 | 机制本身要求的正常等待，不自动视为当前失效；明确异常限制才进入相应分档 |
| 其他关键参数 | 复用已确认的参数关系及适用依据。支持定性判断时说明证据、理由和范围。适用必要条件缺证按 0 分结项 |

### 3.4 按现货执行方式核验参数

| 类型 | 关键对象及绑定 | 当前参数及约束 | 必要操作状态 |
| --- | --- | --- | --- |
| 原生 CLMM／DLMM | 从实际池登记资产顺序、生产版本、费率层级及费用接收方。按部署核对 CLMM 头寸归属、DLMM 池、bin 步长及管理器版本 | 分开记录全局允许的最高费率和所选池实际生效费率。核对协议和 LP 的实际收费基数和分账。动态费按部署的波动累加器、步长、衰减、截顶和舍入重算 | 分别合并全局与池级开关，确认交易、撤资、费用领取及实际退出方式，例如能否直接按双币份额撤资 |
| 聚合路由 | 从所选入口核对构造、确认和保护对象使用的是配套版本。登记场所、适配器、资产类型及收款或退款对象 | 对所核路径检查初始授权输入、签入最低净到账、场所费与聚合费的扣费顺序、部分成交和中间资产归回。逐笔签入的滑点和费用随该次指令记录 | 核对所选路径能否使用正确版本完成。需重新构建并签名的路线单列，替代路径仍须满足声明的资金和到账条件 |
| RFQ 报价簿 | 绑定实际簿、做市方、币种、方向和签名验证对象。按部署要求核对适用本簿的有效量、签入字段和重用条件 | 核对允许的有效期、每层可成交数量、费用和签入的时间调价上限。报价的具体价格及深度按当前状态单列 | 核对全局、做市商和簿的开关。分别核对接收报价、成交、刷新与库存取回，记录哪条路径需要报价 |

采用部署的原始整数、精度和舍入顺序。样本给出三种可复算方式：

1. 原生池的部署若按费用基数上取整，先算协议费 `ceil(实际交易费 × 分成比率)`，再用实际交易费减去协议费得到 LP 费用。例如 Cetus DLMM 样本中，`基础费原值 = 步长 × 基础费因子 × 10`，`动态费原值 = ceil(动态费控制参数 × (当前波动累加器 × 步长)^2 ÷ 10^11)`，`总费原值 = min(基础费原值 + 动态费原值, 代码上限)`，费率分母为 `10^9`。比较当前值和代码允许的边界时使用实际截顶、衰减及舍入。全局费档上界、价格网格及市场中间价按实际含义披露。经济竞争力或 LP 收益只有在事先确定了适用判据时进入判断。
2. Cetus 聚合 V3 按初始投入计算 `Q0 = floor(初始投入 × 报价输出 ÷ 报价输入)`，再计算 `最低净到账 = floor(Q0 × (M − 滑点单位) ÷ M)`。此实现的 `M = 1_000_000`。场所返回额扣除实际集成费后核对净到账和中间资产归回。部分成交按实际代码确定保护是否仍绑定初始投入。只有保护代码证据时，记录保护条件的覆盖范围。
3. RFQ 若签入时间调价，按签入的斜率、时间单位和代码上限计算，再确认方向及舍入。Cetus 样本采用 `调价单位 = min(floor(报价年龄毫秒 × 签入调价值 ÷ 时间偏移毫秒), 调价上限)`。报价是否过期、失效后是否有可用来源归资金与外部依赖。

已确认错绑资产、场所、费用接收对象或管理器，并导致估值、收费、归属或结算违反硬约束时，关联范围取 0 档。净到账保护或资金归回违反既定要求时，按实际受影响范围取 0 档。预先确认的适用警戒或必要操作异常部分受限时取 60 档。所列必要检查通过时取 100 档，适用的关键字段或必要路径结项时仍缺证，记该检查 0 分并注明原因。池级结论保留各自范围。 [Cetus 配置评估记录](../research/cetus-configuration-assessment-346896130.json)

### 3.5 参数配置档内扣分

按所选原生池、路由或报价簿的实际生效配置取证。每项记录实际对象、生产配置、证据定位和已核可用路径。先定档，再累计独立轻微问题。表中“完整可用”指该条事实自身对必要权益的影响。在 60 档，定档异常照常保留，另行核实档内问题未进一步限制仍可用的路径或违反硬约束。

| 业务 | 扣分 | 可核验触发 | 换档条件 |
| --- | ---: | --- | --- |
| 原生 CLMM／DLMM | 1 | 池级配置关闭或撤去了一条已确认的补充资产、费档或管理器匹配校验。实际交换和撤资所走的主检查仍与生产池、币种及档位绑定，用户流程照常 | 实际消费路径错绑，且违反资产归属、收费或结算硬约束，取 0 档 |
| 原生 CLMM／DLMM | 2 | 当前池或管理器配置要求受影响 LP 在撤资领费前额外刷新头寸或执行一次解包。已核验原有权限、到期条件、逐币净额及领取资格仍全部满足 | 撤资或应领费用仅有部分用户、币种或额度可正常完成时取 60 档。必要操作完全受阻且无替代时取 0 档 |
| 原生 CLMM／DLMM | 3 | 已配置的辅助合并领费或批量头寸管理入口因当前开关或对象绑定失效。逐币领取、逐头寸操作及普通撤资均按原约束验证可完成 | 失效延伸到必要的领取或撤资，按实际异常部分受限或完全受阻判 60 或 0 档 |
| 聚合路由 | 1 | 所选版本配置中的第二道场所或币种匹配检查失效。实际使用的构造与确认版本仍配套，原投入、收款对象和净到账由主检查完整约束，用户流程照常 | 有效路径绕过签入的最低净到账、超出授权投入或将资金交给错误对象时取 0 档 |
| 聚合路由 | 2 | 当前适配器配置改变后，既有路由需重建或重签。已核验能在原有效期内完成整单，签入资金边界、净到账及退款条件全部保留 | 只能承接该范围的一部分订单或投入额度时取 60 档。必要结算完全受阻且无替代，或硬约束被突破时取 0 档 |
| 聚合路由 | 3 | 已部署的用户自选场所或批量组单功能因生产绑定或开关失效。所声明的币对和整单额度仍有已核路由，保留原投入、最低净到账及退款条件 | 可用路线只承接部分已声明交易时取 60 档。必要结算完全受阻且无替代，或硬约束被突破时取 0 档 |
| RFQ | 1 | 所选簿的一道补充绑定校验被当前配置关闭。主校验仍逐条约束币对、方向、签名和有效期，成交与库存取回流程照常 | 出现实际未经授权的报价接受、错绑资产或越过数量、调价硬约束时取 0 档 |
| RFQ | 2 | 所选簿的生产配置要求原有合资格做市商额外更新簿绑定或进行一次准备操作。全部必要成交或取回仍可按已确认期限和原币权益完成 | 合资格范围或可支付数量已异常部分受限时取 60 档。完全失去必要结算或取回路径且无替代，或违反硬约束时取 0 档 |
| RFQ | 3 | 簿配置关闭原已提供的辅助批量更新入口，逐笔更新仍能覆盖双方必要操作，存量库存可全额按原条件取回 | 必要更新、成交或取回只剩部分可用路径时取 60 档。完全受阻无替代，或违反硬约束时取 0 档 |

### 3.6 公式

```text
配置档位上限 B_config(m) = min { b_i | i 为同一范围内适用且独立计分的配置项 }
配置分 S_config(m) = 档内分(B_config(m), 独立轻微问题扣分)
```

按适用检查的最低档位和档内规则结项。必要条件缺证的检查记 0，保留其适用范围，全部已确认不适用才显示 N/A。

档内分为整数，业务大项采用 100／60／0 三档时，100 档限 61–100，60 档限 1–60，0 档固定 0。整个计分单元采用 100／0 两档时，100 档限 1–100。单个检查采用两档时，业务大项沿用自身适用的档位序列。按根因、范围和后果去重，同一事实命中多条时取最高扣分。决定当前档位的事实只用于定档。无已核实的独立轻微问题时取该档上限。 [通用档内计分规则](./通用链上安全评估标准.md#13-先定档再计算档内分)

例如，所选 DLMM 池全部必要操作通过，生产配置确认补充管理器匹配检查失效，另一个独立开关也使批量领费停用。主校验仍有效，逐币领取和普通撤资完整可用，分别扣 1 和 3，配置得 96 分。如果批量领费失效与补充校验失效来自同一事实且影响相同，只扣 3，配置得 97 分。

## 4. 资金与外部依赖

### 4.1 按实际资金义务检查

| 类型 | 采集与核验 | 资金结论的边界 |
| --- | --- | --- |
| 原生 AMM | 在选定池读真实币种余额、头寸或 bin 份额口径及已确认的费用义务。需要核验具名权益时，按该头寸的实际价格区间或 bin 份额计算应取的两腿原币，核对可用资产和撤资路径 | 按份额承担市场风险的流动性只产生适用的份额义务。虚拟储备和当前格点深度用于解释价格，排除在可付现金之外 |
| 聚合路由 | 核对输入、场所交接、扣费后输出及退款，确认用户交付与最终结算是否原子完成。分列协议费用金库和独立的跨交易用户资金（若有） | 经核实只有交易内的原子交接时，跨交易托管存量义务为 N/A。本笔交接、最低净到账和失败回滚仍按实际路径核验。协议费单列 |
| RFQ | 按所选做市商及报价簿读原币库存、归属、已保留额度及提款条件。核对实际对应的支付或取回金额是否在各币种可用额度内 | 报价剩余深度、簿的余额和可保证成交额分别记录。库存取回和取得新报价的条件分别判定 |

按同一币种、时点及适用范围算 `缺口 = max(0, 实际应付 − 到期可用金额)`。只有已存在且可按时执行的转换才计入，并从来源资产扣除同一份额度。用保守边界时，可用资产下界覆盖义务上界可确认足额，义务下界高于可用资产上界可确认缺口。边界重叠且尚无实际付款结果时，披露已核范围，适用的必要覆盖检查按缺证记 0。

原生头寸按实际取回程序及整数顺序拆分币种。以按区间拆分的 Q64 型 CLMM 为例，令 `A < B` 为区间端点平方根价格，`S = min(max(当前平方根价格, A), B)`，`L` 为需取回的已确认流动性。原币本金拆分的参考式为 `amountA = L × 2^64 × (B − S) ÷ (S × B)`、`amountB = L × (S − A) ÷ 2^64`。实际结算使用部署的舍入规则，费用及奖励另列。DLMM 确认为按各 bin 份额分配时，逐 bin 按头寸份额和该 bin 份额总量计算两币权益，按实际舍入后相加。份额总量为零时走实际初始或空仓分支。只有样本池总余额时，披露存量与路径，精确头寸应付以能绑定到相应头寸的数据为准。

### 4.2 必要依赖的状态和替代路径

仅检查当前业务确实依赖、且能够取得链上状态依据的输入或组件，例如实际采用的预言机价格、兑换率、必要 Hook 或外部资金组件。依赖用途及有效性要求复用已有机制映射。

不存在必要预言机或其他依赖时，对应项为 N/A；不要求项目为了取得分数新增依赖。仅用于页面估值的参考价，注明用途，不视为协议运行依赖。

| 类型 | 查哪些链上证据 | 如何解释故障 |
| --- | --- | --- |
| 原生 AMM | 从实际交换、撤资和领取入口确认价格来自池状态还是必须读取外部报价。查明是否依赖 Hook、资产管理器或底层结算组件 | 已证实普通直接入口独立于前端、聚合报价和做市商时，这些外部依赖记 N/A。池储备和实际区间仍可解释所选操作的条件 |
| 聚合路由 | 分开保存报价构建和链上执行的必要输入。核对具名场所、资产映射、所需临时签名或报价和具体替代路线 | 必需的一跳不可用时，先判断已签路由的执行后果。完整承接须验证同一业务范围和保护条件。需要重新构建或签名时，记录实际可行范围和对成交、退款、费用的影响 |
| RFQ | 按簿和方向读缓存报价的时间、来源、剩余认证深度、验签与更新入口。`剩余有效时间 = 报价到期时间 − 快照时间`，`剩余认证深度 = Σ(该层授权量 − 该层已成交量)`。用部署的到期比较符和单位 | 缓存过期只确认这份缓存不能继续使用。由可核验的新报价或替代路径判断能否继续成交。只有更新入口时，未经证实的新报价不计入可用来源。库存取回沿实际提款入口独立判断 |

将声明的停止情景与当前状态分别记录。若唯一报价来源停止，核对现有报价在剩余时间和深度内是否还可使用，再查新成交停止时存量库存的退出路径。复用已生效的情景规则须记录停止对象、假设、影响范围和规则版本。项目错误配置依赖归配置，实际绑定正确但服务或资金路径状态异常归本项。

### 4.3 分档

| 结果 | 档位上限 | 判定条件 |
| --- | ---: | --- |
| 当前正常 | 100 | 本检查涉及的适用资金义务均有足额可用资金，实际所需的输入和路径均有效。可用的替代完整承接相应必要操作时计入 |
| 当前受限 | 60 | 触及事先确定且适用的警戒，或本项必要业务异常部分受限且同一受影响范围仍有已核验的部分可用路径 |
| 当前失效 | 0 | 当前硬性资金义务覆盖失败，或必要路径完全受阻且无有效替代 |
| 必要证据缺失 | 0 | 必需金额、时点、绑定、路径状态或有效性依据结项时仍缺证，记录原因及范围 |
| 不适用 | N/A | 完成核验后确认没有这项资金义务或必要依赖，注明机制依据 |

先查 0 档条件，再查 60 档条件，最后确认 100 档。已达到适用警戒条件时，可独立取 60 档，无需另行证明替代路径。

### 4.4 实际判定口径

- 检查协议实际采用的输入和入口；最外层调用成功，不足以单独证明其必要输入有效。
- 新鲜度、有效范围和警戒阈值按具体机制确定，本版不新增 DEX 通用价格偏差或超时时限。
- 固定值或按当前链上状态计算的兑换率，不机械套用时间戳要求。
- 不把池内成交价格偏离市场价直接判为预言机失效，不把输入有效直接等同于资产价格稳定。
- 备用路径已正常完整承接时，先确认是否新增实际操作负担，或已核实其他独立的冗余／辅助能力损失。部分承接按实际受限范围定档。
- RPC 或采集接口失败单列为证据缺口。依赖检查在结项时仍缺必要证据则记 0，并标明该分来自缺证。
- 不从链上状态推断链下撮合、报价或执行服务正常，也不在本模块重新评价外部组件代码安全。

### 4.5 资金与外部依赖档内扣分

本表适用的资金义务、到账时限及必要操作沿用该范围已声明的判据。按第 3.5 节核对各项独立事实的影响。同一业务的备用源或备用路径失效但主路径完整承接且无额外负担时扣 1。扣 3 须确认可独立使用的次要业务功能失效。记录同币可用金额、流程时点、有效替代和对应证据。

| 业务 | 扣分 | 可核验触发 | 换档条件 |

| 原生 CLMM／DLMM | 1 | 已确认的辅助报价或备用取回来源失效，普通交换或撤资的现行路径仍可全量完成，按实际区间或 bin 权益结算，用户流程无额外负担 | 有效来源只剩部分能承接时按 60 档判断。必要路径完全不可用且无替代，或同币硬性义务有缺口时取 0 档 |

| 聚合路由 | 3 | 已上线的可选批量结算功能因外部组件失效。已核逐笔结算能完整承接同等资产、金额及收款要求，主要交换与退款仍可运行 | 受影响必要业务只获部分承接时取 60 档。无有效替代的完全阻断或资金硬约束失效取 0 档 |

### 4.6 公式

```text
资金与外部依赖档位上限 B_funds_dependencies(m)

```

按适用检查的最低档位和档内规则结项。必要条件缺证的检查记 0，全部已确认不适用才显示 N/A。

## 5. 模块联动、证据缺失与结项

### 5.1 原因归属与去重

| 情况 | 原因计分位置 | 其他模块的处理 |
| --- | --- | --- |
| 当前主体有能力修改配置或替换依赖 | 权限 | 配置和依赖分别按当前实际状态判断，不因存在修改能力自动判异常 |
| 当前错误配置了必要依赖地址 | 配置 | 资金与外部依赖引用该异常及实际影响 |
| 绑定配置满足要求，但当前输入失效或资金路径受阻 | 资金与外部依赖 | 配置模块引用实际影响 |
| 已证实同币义务有缺口 | 资金与外部依赖 | 其他模块引用已确认影响，基于自身独立事实判定 |
| 已确认原因造成用户当前退出受限 | 对应原因模块 | 在实际受影响范围说明退出后果。权限使用已设计退出入口的配置及其控制路径判断保护 |

引用项展示异常状态和影响。分值只进入责任模块的最小值公式。独立的适用检查缺证时按结项规则计 0 并留在分母。整个模块只有引用项时显示“参见对应模块”。

### 5.2 更新与失效范围

| 变化或状态 | 本轮处理 |
| --- | --- |
| 新 snapshot | 使用本轮状态独立计算，不因连续正常加分，也不要求连续多轮才恢复 |
| 权限转移、门限或模块变化 | 更新受影响控制路径及其分档；不因变化事件本身扣分 |
| 参数、业务开关或组件绑定变化 | 按当前值及仍适用的依据重算相关项 |
| 升级导致原能力或机制解释不再适用 | 重评依赖该解释的检查。结项仍缺必要证据的检查记 0，保留原始读数及失效依据 |
| 异常已消除，必要证据完整 | 按当前符合的档位恢复，不继承历史处罚 |
| 关键数据缺失或采集失败 | 适用的必要检查缺证记 0，注明原因及范围。单列历史快照的读数和结果 |
| 局部未知或异常 | 只影响实际相关对象、路径、范围及模块结果，不清空无关结论 |

结项时，仅计已确认的保护和替代路径。适用检查所需的必要条件仍缺证时，该项记 0 并保留在适用分母中，记录缺证原因、已核事实和影响范围。选配项缺证只披露，确认不适用才记 N/A。业务或项目适用 0 分封顶须另有确证，按实际影响范围判定。 [证据缺失与结项](./通用链上安全评估标准.md#5-证据缺失去重与结项) · [项目和业务风险封顶](./链上评估复用指南.md#项目和业务风险封顶)

## 6. 最小证据与对外展示

| 信息 | 最小要求 |
| --- | --- |
| 评估对象与范围 | 项目、链、核心合约或组件、所涉及资产／用户权益；如包含具体池，明确列出 |
| 当前状态 | 区块或检查点、可用唯一标识、读取对象、关键原始值和必要取证时间 |
| 解释依据 | 仍适用的代码能力／机制映射、相关报告或核验记录，以及使用的约束和参考条件 |
| 检查结果 | 定档依据、档位上下限、独立档内扣分和证据、最终整数分或 N/A、已证实的异常或缺证原因及影响范围。引用项注明计分归属 |
| 规则版本 | 本标准版本及项目适用条件，能够还原该次判定 |
| 适用性 | 相关升级或配置变化是否使已有依据待复核；报告日期与快照时间分别记录 |

分别展示权限管理、参数配置、资金与外部依赖。原生池、聚合路由和报价簿各列结论和影响范围。项目汇总时，各大项先对前期确认的适用一级业务模块等权平均，再按权限 30%、参数配置 30%、资金与外部依赖 40% 加权。 [项目汇总和交付](./链上评估复用指南.md#3-项目汇总与正式交付)
