# Lending 配置风险评估方法与执行流程

- 记录日期：2026-11-17；讨论总结版本：v0.1。
- 状态：总结已讨论的评估目标、步骤和初评方法。不是已经迁移到执行器的新版规则；当前冻结的Lending v0.12和前端分数保持原样。
- 适用边界：链上、宏观、轻量；先复用当前代码映射与快照，不扩大市场／账户范围。
- 核心目标：判断当前配置是否为协议健康持续运行提供合理基础，指出可能妨碍偿付、流动性调节或必要业务的配置风险。分数由风险判断形成，不以预期分数倒推规则。

## 一、判断门槛与证据口径

### 1. 不要求穷尽证明，但必须完成必要核验

以下条件成立时，可以进入约80的基础档：

1. 关键字段、单位、用途与作用范围已明确，当前读数能绑定到本次快照。
2. 必要控制确实参与代码路径，参数联动与协议机制一致。
3. 根据已核验的代码、参数与合理情景，未发现足以表明配置存在实质冲突的具体风险路径。

不要求证明参数在所有未来行情下安全、不要求求出经济学上的唯一最优值，也不要求损失已经发生才能判断风险。缺少高级仿真、历史相关性或绝对额度优化模型，不自动降为不及格或U。

“没有发现问题”必须注明已检查什么。没有读代码、没有取得必须参数、关键路径未解释，不能仅以未发现损失给80。机制存在也不是充分结论：要说明它在什么条件下起保护作用，以及还有什么剩余风险。

### 2. 风险证据与敏感性提示分开

| 情况 | 处理 |
| --- | --- |
| 必要核验完成、保护生效，未发现具体实质冲突 | 约80基础档，不要求证明所有极端情景 |
| 已确认额外且独立的保护，对某风险有明确增量效果 | 可进入85／90／95；记录增量依据，同一事实不重复加分 |
| 有参数／代码支持的具体风险链，影响有界且基本保护仍在 | 单列风险、范围和程度，再作有限扣分；不等损失发生才处理 |
| 已确认错误单位、实质不兼容、必要功能完全不可达等重大问题 | 对确认的影响范围设低分或封顶，不让其他正常项平均掩盖 |
| 只有假设压力未通过，未建立实际机制风险或资产适用性 | 保留计算与敏感性说明，不凭统一跌幅直接判全配置不合格 |
| 关键必需输入／机制确实未知 | U，仅影响依赖它的判断；不能以未调查高阶市场模型代替关键缺口 |
| 机制明确不适用 | N/A，排除相应分母，不补100 |

“直接证据”包括代码和当前参数能够支持的因果推断，不限于事故、交易复现或已发生损失。每项使用下述风险链：

```text
触发条件 → 参数如何作用 → 可能后果
          → 当前保护 → 剩余风险 → 影响范围
```

## 二、先回答五个运营问题，再映射分数

| 控制组 | 要回答的问题 | 本次工作权重 |
| --- | --- | ---: |
| 抵押与借款准入 | 什么资产、按什么比例、可以支持哪些债务？准入和估值规则是否匹配？ | 20% |
| 清算机制联动 | 进入清算后，债务能否按该机制得到有效处置？清算是否改善剩余头寸状况？ | 25% |
| 暴露规模与风险限制 | 某类资产或组合出问题时，协议配置把影响限制在哪里、限制到什么程度？ | 20% |
| 利率及已采费用分配、流动性响应 | 流动性紧张时，价格反馈、新增借款限制和供应激励如何配合？ | 20% |
| 特殊模式与组合约束 | 更高杠杆对应什么配对、参数和退出限制，新增的敏感性是否受约束？ | 15% |

资产／单位／价格入口绑定作为正确性前提；还款、提款、清算开关作为必要业务检查及重大失效判断。它们既不能被忽略，也不作为两个自动满分项稀释其他经济风险。权限集中度和预言机来源韧性引用各自模块，不在配置层重复处罚。

## 三、必须按顺序执行的工作步骤

| 顺序 | 工作 | 必须产出 |
| --- | --- | --- |
| 1 | 冻结目标、市场／资产／模式、快照、源码及评分版本 | 范围清单；复用已有资料，不从头扩扫 |
| 2 | 对照源码／SDK解释每个必要参数 | 字段、单位、计算口径、实际比较条件及代码位置 |
| 3 | 把当前读数映射回业务路径 | 准入、借款、还款、清算、退出、模式和限额作用范围 |
| 4 | 为五组分别建立风险链 | 触发条件、后果、保护、剩余风险和影响范围 |
| 5 | 使用现有输入做必要联动计算 | 开仓距离、清算后健康方向、上限状态、实际利率曲线等；不查个人头寸 |
| 6 | 判断基础是否合理，以及风险是否有具体依据 | 基础成立／有限弱项／重大问题／U／N/A；不得先选分再拼理由 |
| 7 | 将判断映射到分档 | 基础约80；增量保护与风险调整有依据、有范围、有上限，不重复计分 |
| 8 | 按固定权重汇总、同时保留局部风险 | 五组贡献、适用分母、重大失效范围；默认／模式不冒充实际敞口 |
| 9 | 校验并发布 | 风险结论先于分数；数据、公式、版本、证据和展示一致 |

首次由Agent完成机制研究、数据映射和规则设计，结合执行结果复核。规则冻结后由引擎按JSON读取、计算和判断；日常扫描不依赖Agent。只有部署、参数结构、来源或未映射机制变化，才返回对应研究步骤。

本轮尚处于研究／初评到固定判据的整理阶段，不能把讨论性初评冒充已由确定性规则自动生成的结果。

## 四、各组的详细评估方法

### A. 抵押与借款准入，20%

**已有输入：** LTV、清算阈值、借款权重、抵押／借款用途、资产／池／市场／价格映射、隔离和允许组合信息。

**步骤：**

1. 先确定资产当前用途：允许新增抵押、仅供应、允许／禁止新增借款。禁用某用途不等于协议失败，也不代表存量债务为0。
2. 按代码得到有效最大初始借款比例b、清算线λ；借款权重只按其实际公式折算，不能重复除权。
3. 检查参数是否满足该机制的定义、用途与约束；例如普通超额抵押模型通常要求0<b≤λ≤1。其他机制按其实际规则适配。
4. 披露最大借款对应的开仓缓冲和合理压力情景，说明借款者容错空间；不把开始清算当作协议失效。

```text
D_open = 1 − b/λ
H0 = λ/b
H(d) = (1−d)λ/b
```

无独立b的机制不虚构b=λ后罚零缓冲。默认b=0的资产在抵押判断中N/A，其他配置仍可评价。5%／10%及1%／3%可保留为披露情景，不能未经资产和时间窗口校准就成为通用及格线。

### B. 清算机制联动，25%

**已有输入：** 有效清算线、清算奖励、清算量／比例规则、协议奖励分配、扣押边界、必要清算路径。

**步骤：**

1. 弄清谁还多少债、扣多少抵押、奖励给谁、受到什么上限约束；不能混用固定奖励、折价拍卖和动态奖励。
2. 归一化总扣押倍率β，区分额外奖励和售价折扣；协议／执行者分配不能重复计入总奖励。
3. 检查部分清算在清算线附近能否改善剩余头寸，清算量是否为正且受边界限制；确认是否存在允许借款却无法进行必要处置的配置冲突。
4. 明确价格越线后、动态奖励或多抵押情景的剩余风险。不做Gas、闪电贷成本或净利润分析。

在单抵押／单债务、固定λ与β、偿还债务比例0<f<1、操作内价格不变及剩余抵押为正的情景：

```text
H_after = (H_before − λβf)/(1−f)
清算线附近H_before=1时：
H_after = 1 + f(1−λβ)/(1−f)
M = 1−λβ
```

M>0支持该情景下的恢复方向，不代表所有行情都能成交。M与D_open分别解释，不再取最小值后代表全部配置健康度。NAVI的liquidation_ratio基于选定抵押价值限制偿债量，不能直接当成债务close factor。

### C. 暴露规模与风险限制，20%

**已有输入：** 供应上限、借款比例上限、占用、禁止新增、用途和组合约束；相应执行检查的源码。

**步骤：**

1. 判断风险可通过哪些资产／债务路径进入市场，有哪些有限上限、禁新增、配对或隔离等约束。
2. 使用协议实际比较的单位和数量核对上限；零值是禁用还是无限额必须有机制依据。
3. 判断新业务是否被约束，存量余额超现有限额时还允许哪些操作。不能只凭快照超限就认定执行绕过。
4. 结合市场角色和已有宏观量判断风险边界；绝对额度最优性若需要未采市场深度，保留判断范围，不凭低占用给满分，也不自动列补采任务。

不要求每种隔离工具都启用；替代约束可以达到相同控制目的。配置存在并不自动充分，要说明其约束对象与保护效果。

### D. 利率及已采费用分配、流动性响应，20%

**已有输入：** IRM及单位、base、kink、有效高低段响应、当前利用率、借款／供应利率关键点、reserve_factor、treasury_factor及借款比例上限。

**步骤：**

1. 检查模型、定义域、年化、费用分配和边界，按分段线性／自适应／固定等机制分别适配。
2. 展示当前u与关键利用率下的借款成本、供应收益；不能仅因斜率为正就声称有充分经济调节。
3. 联合检查利用率上升时的价格反馈、借款上限和供应激励，解释能如何促使资金回流，以及仍依赖什么行为。
4. 高利用率、弱反馈或存量退出依赖借款回流可以列观察风险；不设置统一安全APR，也不把更陡、更高当成无限安全。

独立额外借款手续费与闪电贷费用当前只取得相关对象ID，未采完整费率状态；本工作口径仅评价已采利率与费用分配。它们未列为这版必要输入，不因此扩大采集或阻断基础判断。

### E. 特殊模式与组合约束，15%

**已有输入：** 10个方向的启用、成员、借贷方向、覆盖参数，以及进入／退出和成员检查代码。

**步骤：**

1. 确认模式到底改变哪些参数、只允许哪些抵押／债务关系，进入和退出需要什么条件。
2. 使用实际覆盖参数重新检查准入和清算联动，不能拿默认配置替模式通过。
3. 单列相对价格偏离、奖励后余量与可能的流动性共用风险。稳定币名称或批准配对不是风险为零的证据。
4. 区分独立头寸、独立流动性池和损失承担边界；不能相互替代。

默认与各模式分别评价。本15%是配置政策权重，不是实际资金使用比例；没有模式占用金额时，不把最弱模式乘以该资产全部供应。新增模式也不能仅凭多一项正常值稀释已有风险。

## 五、分档、汇总与输出

### 1. 分数映射

约80表示基础风险控制合理且有效，适用于本次声明范围；不是仅凭参数合法或未发现事故。85—95应有更强、适用且可回溯的保护依据。一般弱项只在其影响范围内有限扣分；重大问题另设明确范围的门槛或低分。100不表示未来零风险，也不能因未调查而给出。

每次调整必须写明：基础判断、增量保护或风险原因、影响范围、调整程度及适用条件。同一事实若已是80基础成立的条件，不能再次机械加5。

### 2. 汇总

```text
S_raw = 0.20×S_准入 + 0.25×S_清算 + 0.20×S_暴露
      + 0.20×S_利率 + 0.15×S_模式
S_config = min(S_raw, 适用于已确认重大失效范围的评分上限)
```

无适用模式时有依据地N/A并对其余权重归一，不补100。关键输入U不从分母删除后发布高分。默认资产内、模式内和共同控制项必须避免重复计分；资产权重只描述已知账面分布，不能冒充实际借款人抵押或模式分布。

### 3. 发布内容

每项先给“结论→风险链→保护及剩余风险→范围→证据及公式”，再给分数。记录快照、源码／规则版本、已采字段、计算值、判断状态、score_reason、调整及证据位置。采集完成不代表高分，初步判断也不冒充确定性规则结果。
