# BitsScore 永续合约链上安全评估标准

v0.5 · 2026-11-24

每个快照分别发布**权限管理、参数配置、资金与外部依赖**。按声明范围结项，逐项标明操作、资产、用户及证据覆盖。 [通用判据](./通用链上安全评估标准.md) · [范围和目标额度](./链上评估复用指南.md)

## 1. 评估范围与采集边界

首次接入时，从已有代码评估和部署资料中确认哪些组件控制保证金、仓位操作、权益结算和提款，记录各组件与平台、市场组或资产的绑定关系。评估对象适用于订单簿、流动性池或其他永续架构，由当前部署决定。

| 结构 | 本版可发布的结论 |
| --- | --- |
| 平台共用保证金提款入口 | 若可核验绑定关系，可发布该入口对哪些抵押资产生效、当前是否允许提款。结论限于该入口管辖的资金。 |
| 一组市场共用价格或结算组件 | 共享组件检查一次。标明结果覆盖的市场组、实际输入和业务用途，例如用于清算或权益结算。 |
| 市场独立配置但共用上级管理员 | 权限结论可覆盖该管理员管辖的市场。各市场独立配置的参数和价格输入另行注明覆盖情况。 |
| 各市场均独立，缺少可核验的公共状态 | 已核验的局部事实保留市场名称及证据。声明范围内的适用检查按结项规则评分，并注明证据覆盖范围。 |

每轮 snapshot 绑定明确的链、区块或检查点、唯一标识和时间，在同一状态下核对当前绑定及读数。跨链组件分别标注锚点。每轮独立判定，历史趋势、响应速度和压力预测均在本标准范围之外。

默认采集范围限于已识别的公共控制路径、共享配置、必要依赖及可直接读取的结算异常记录。全市场扫描、账户或仓位枚举、逐仓盈亏重算均不属于例行采集。单个热门市场的数据只支持该市场的结论。

代码侧提供能力后果、参数含义、清算与结算机制的已有核验结论。链上模块判断这些结论对应的当前控制关系、设置与状态。链下撮合、报价或执行服务的安全属于业务攻防评估。

## 2. 权限评分

新评估的档位与档内扣分采用通用权限分表。本节的后果分类用于选择适用的保证金、持仓和退出路径。旧矩阵用于追溯 v0.2 结果。 [复用指南第 1.3 节通用权限分表](./链上评估复用指南.md)

从能够影响现有用户保证金或权益的操作出发，沿已生效的角色、签名门限和时间锁配置及其时长追踪到最终控制主体。检查直接执行、上级授权或替换、升级、门限或执行模块变更、紧急通道、缩短或绕过等待，以及多个角色由同一主体控制的情况。已有报告中的中心化问题作为核验线索，按当前链上权限计分。

**v0.2 历史分表。** H1／H2／H3 用于识别现行业务后果。以下 A／B／C／D 判据及分值用于历史复算。

| 已确认的业务后果 | A 单组控制 | B 独立共同批准 | C 有效退出保护 | D 共同批准且有效退出 | 确认无对应能力 |
| --- | ---: | ---: | ---: | ---: | ---: |
| H1 任意处分保证金或重写权益，包括可通过任意指定结算输入达到相同后果 | 0 | 40 | 70 | 85 | 100 |
| H2 在约束内改变已有仓位适用的保证金、清算或结算条件，使持仓人承担额外风险，后果未达到 H1 | 20 | 50 | 80 | 90 | 100 |
| H3 可无限期阻断已有用户必要的减仓、结算或资金取回，且缺乏不可自行延长的到期或独立恢复保障 | 30 | 60 | 75 | 90 | 100 |

| 档位 | 完整路径的判定条件 |
| --- | --- |
| A | 单一实际控制组可实现相应后果，且缺乏有效退出保护。 |
| B | 至少两个已证实独立的控制组必须共同批准，无更弱的上级或间接路径，且缺乏有效退出保护。仅有主动否决权不足以证明必须共同批准。 |
| C | 危险变更公开可见，具有不可绕过的等待，当前证据支持受影响用户在生效前完成必要退出，控制者不能提前关闭退出路径。此档未同时达到 B 的共同批准条件。 |
| D | 同时达到独立共同批准和有效退出保护的条件。 |

**现行仓位权限与退出保护。** 仅对新开仓生效的参数按实际作用范围判断。替换价格源区分在受限来源间切换与任意指定结算输入，按已确认的业务后果归档。用代码和已生效的链上权限配置核对危险操作控制者能否关闭已设计的减仓、权益结算或保证金提款入口。当前资金能否兑付、持仓能否实际结算由资金与外部依赖评估。

对每项后果先比较完整路径的档位上限，再以适用后果的最低上限定档。新评估按指南核对同范围的独立权限扣分并计算最终分。历史 v0.2 批次按上方矩阵追溯。

经完整核验确认无对应直接或间接能力时，该后果进入 100 档。读取失败、角色空置或路径尚未查清时，无能力的结论不能成立。沿用公共权限规则，当前权限配置已使必要退出路径永久失能时，对应项进入 0 档。关键控制路径、独立性或保护依据不足按第 6 节处理。

## 3. 配置评分

评估前记录适用范围、安全约束、警戒条件及依据。只对当前部署实际使用、已有判断依据的配置作出确定结论。

| 检查项 | 当前读取与判定 |
| --- | --- |
| 资产和组件绑定 | 核对市场、保证金币种、适用价格和结算组件、精度及计价对象。实际错绑威胁资产归属或结算属于硬约束违反。 |
| 开仓与减仓 | 分别核验能否增加和减少敞口。仅允许减仓时，披露“限制新开仓”。若已有仓位的必要减仓、结算和退出条件均满足，该模式本身不扣分。 |
| 已有权益结算 | 读取结算模式、有效组件绑定和暂停状态，判断已经满足结算条件的权益是否受到异常阻断。正常等待按既定机制说明。 |
| 提取可用保证金 | 核对提款开关、适用资产和有效替代入口。判断对象为已满足提取条件的资金。持仓占用的保证金单列说明。 |
| 共用风险参数 | 对已确认作用于平台或市场组的保证金要求、清算参数或敞口限制，按事先确认的约束判定。仅在各市场独立生效的参数归入相应市场范围。 |

具有初始保证金与维持保证金两个独立门槛时，按部署归一到同一计量基础，核对正常开仓规则是否允许满足初始条件的仓位直接落到该模式的清算边界外。参数名称、单位或比较方向因实现不同，以实际生效代码为准。最大杠杆、名义上限和正常费率有读数时可披露，达到已采用的适用警戒才用于定档。

| 档位上限或状态 | 判定条件 |
| --- | --- |
| 100 | 当前设置满足适用安全约束，已有用户所需的业务状态符合既定条件。 |
| 60 | 满足事先明确的适用警戒条件；或必要操作异常部分受限，但同一受影响范围仍有已核验的部分完成或退出路径。 |
| 0 | 明确违反安全约束，或必要减仓、结算、取款路径已受阻且无有效替代。 |

先判 0 档，再判 60 档。对只有“满足／不满足”两种结果的设置适用 100／0 档。适用的必要条件结项时仍缺证，该检查记 0 并注明原因。已确认不适用记 N/A。例如，A 组的必要提款路径已证实完全阻断且无有效替代时，A 组该项进入 0 档。B 组提款正常，单独呈现 B 组状态。

## 4. 资金与外部依赖

| 检查项 | 当前读取与判定 |
| --- | --- |
| 可执行结算与保证金取回 | 记录所选范围中已结算可提余额、可直接核对的到期应付、适用限制和同币结算现金。将持仓占用、未实现权益、已实现应付及直接现金分列。以同一结算范围的确权金额与能够按时到达的资金核对。 |
| 资金调拨和风险储备 | 读取被执行路径实际使用的资金组件及有效限额。项目持有储备有明确分配规则且可按需到达时，记录相应可用额度。仅有保险或储备余额时作为披露。 |
| 清算或结算实际采用的价格 | 核实当前生效来源、适用的有效性条件及用途。公共入口可读，只能证明入口层面的事实。逐市场独立的输入需有对应证据才能发布市场结论。 |
| 共用结算或资金组件 | 核验组件明确暴露的暂停、结算限制及资金释放状态。对于链下执行者，仅凭一个快照无法判断其在线率或长期可用性。 |
| 替代路径 | 核验备用是否已经生效、可承接的操作和资产范围。仅登记在配置中的备用不足以证明可用。 |

| 档位上限或状态 | 判定条件 |
| --- | --- |
| 100 | 可核对的必要资金义务有匹配资金，实际采用的必要输入和路径满足条件，或有效备用完整承接相应操作。 |
| 60 | 满足事先采用的适用警戒，或必要减仓、结算、提取可用保证金异常部分受限且同范围仍有已核验路径。 |
| 0 | 确认违反可核对的到期资金义务，或必要操作因资金或依赖失效完全受阻且无有效替代。 |
| 0（证据缺失） | 适用的结算义务、可用资产、当前输入或必要执行路径结项时仍缺证，记录原因。 |
| N/A | 已确认该范围没有相应义务或依赖。 |

先判 0 档，再判 60 档。

对可核对的固定同币应付，余额缺口为 `max(0, 到期应付 − 同一结算范围可及时动用的同币资金)`。引用源标识及金额、精度和期限。配置和资金与外部依赖按各自范围计算。机制消费端绑定错归配置，实际采用的正确来源失效归资金与外部依赖。同一根因在同一范围造成的同一后果只计一次。各自成立的独立原因按各自条款判断。

### 4.2 计分与去重

配置、资金与外部依赖各自按同一业务模块、同一大项和同一证据范围计分。先确定档位上限，再累计扣分。已部署的第二道保护或冗余削弱或失效，必要路径仍完整且无新增负担时扣 1。已有新增步骤、交易或等待，仍可足额、按期完成且符合硬约束和警戒边界时扣 2。独立次要业务功能已失效、必要权益仍可完整履行且未触发警戒时扣 3。60 档发生的独立轻微问题按自身造成的后果判断，定档事实只用于定档。

记录当前状态或事件、仍可满足原权益的路径证据、作用范围和扣量。单一事实取适用的最高扣量。独立问题按根因、范围和后果去重，已用于定档的事实只参与定档。必要证据缺失按第 6 节结项，已证实不适用记 N/A。 [通用档内计算规则](./通用链上安全评估标准.md#13-先定档再计算档内分)

```text
档位上限(m) = 同一业务模块及同一证据范围内适用独立检查项的最低档位上限
100 档的维度分(m) = max(该计分单元下一档上限 + 1, 100 − 独立适用扣分之和)
60 档的维度分(m) = max(1, 60 − 独立适用扣分之和)
0 档的维度分(m) = 0
```

业务大项采用三档时，100 档下限为 61。整个计分单元采用 100／0 两档时，100 档下限为 1。单个检查采用两档时，业务大项沿用自身适用的档位序列。

| 当前能够取得的证据 | 对外表述 |
| --- | --- |
| 共享组件直接记录未覆盖损失 | 列出记录金额、资产单位、所属组件、字段会计含义及覆盖范围。 |
| 单一市场记录结算缺口 | 写明市场及金额。其他市场的缺口保留为未核验。 |
| 已核验结算或提款受限，金额无法直接确认 | 披露受限操作、影响范围及“金额未知”，引用已计分的原因。 |
| 缺少可核验的汇总，计算缺口需要重建逐仓账本 | 整体缺口金额标未核实。依赖该证据的适用必要资金检查按缺证记 0，已核结论继续展示。 |
| 组件缺口字段为零 | 显示“该组件当前记录的未覆盖损失为零”，保留字段口径与快照证据。 |

上述披露使用当前可核验记录。未平仓量、准备金余额和待清算账户数不能单独决定资金结论。整体偿付能力需要其独立证据，保留可直接验证的局部结算结果。

## 6. 证据、结项与更新

每条结论保留**适用对象与操作、证据覆盖范围、快照锚点、读取对象与原始值、机制或约束依据、规则版本、定档理由、档位上限、档内逐条扣分及最终分或状态**。对共享组件还应保留其与受影响市场组、资产或入口的绑定依据。开关显示开放时，可确认配置允许操作。实际成交、结算完成或资金到账需要相应证据。

| 情况 | 发布与更新规则 |
| --- | --- |
| 未覆盖 | 明确未纳入的对象。按声明范围发布评分，标明局部结论和范围边界。 |
| 必要证据缺失 | 已纳入范围的适用必要检查缺证记 0 并保留在适用分母中。注明缺证原因、已核子项和已证实异常。 |
| N/A（不适用） | 现有机制已确认不适用，记录依据。全部项均不适用时显示 N/A。 |
| 重复引用 | 原因在归属模块计分一次。模块若只有引用项，显示“参见对应模块”。权限使用已设计退出入口的配置及其控制路径判断保护。 |
| 权限、参数、开关或绑定变化 | 用新快照重算受影响项及其实际范围。升级使原机制解释失效时重评相关检查，结项仍缺必要证据的检查记 0。 |
| 异常消除 | 当前证据满足适用条件即可恢复对应档位，不附加连续正常次数或历史处罚。 |

结项时，仅计已确认的保护和替代路径。缺证原因与已证实故障分列，选配项缺证只披露。业务或项目适用 0 分封顶须另有确证，按实际影响范围判定。权限按代码及生效的权限、延时和退出入口配置核验。实际资金兑现和结算路径的运行状态归资金与外部依赖。 [证据缺失与结项](./通用链上安全评估标准.md#5-证据缺失去重与结项) · [项目和业务风险封顶](./链上评估复用指南.md#项目和业务风险封顶)

配套标准见[代码安全评分标准](../code-security-rating-standard.md)、[DEX 链上安全评估标准](./dex-onchain-security-rating-standard.md)与[Web3 业务攻防评级标准](../web3-business-security-rating-standard.md)。
