# Lending 预言机：已有事实与下一步讨论

记录日期：2026-11-17。状态：讨论准备，不修改预言机规则或分数。数据沿用NAVI检查点345771824，源码映射commit `9ff791fe309358a8bf6f3783a2aeb0c95f72a1dd`。本轮没有新增链上、账户或外部接口采集，也没有模拟故障。

## 1. 本模块要回答什么

评价价格输入是否为持续借贷、还款和清算提供合理基础：什么来源参与报价；错误、过期或偏离输入会怎样处理；来源异常后是安全停止、可切换，还是可能继续使用错误价格；管理员能够覆盖哪些保护。先分清报价安全与业务可用性，再讨论分数。

当前按协议所接上游服务／读取路径统计来源数，不把两个同名配置槽算作两个来源，也不据此推断上游内部只有一个报价者。这里评价声明范围内的来源和配置韧性，不重新调查供应商组织或遍历用户交易。

## 3. 代码和配置已支持的判断

| 情景／能力 | 已确认行为 | 风险含义 |
| --- | --- | --- |
| 最终存储价格非正或超过消费端有效期 | `oracle.move:193`判无效，`calculator.move:99/105`要求is_valid | 对应正常计算路径拒绝使用；不能表述为已确认接受过期价格 |
| 主源返回了可解析但不新鲜的价格，备源新鲜 | `oracle_pro.move:133–135`选备源 | 存在这一类自动替代，不是完全没有fallback |
| 主源配置被禁用 | `oracle_pro.move:87–89`直接return | 不继续尝试备源；是正常更新路径的可用性限制，不等同最终直接接受错误价 |
| 主源适配器调用abort | 91行调用发生在备源读取和择源之前，没有catch替代分支 | 该次更新回滚，无法走到后备选择 |
| 备源适配器调用abort | 101行在最终择源前读取备源 | 即使主源可用，该次更新也可能回滚，属于共享更新路径的耦合 |
| 主备都不新鲜或后续范围／历史检查失败 | 136–138或147–161行停止更新 | 需结合最终消费者拒绝旧值判断业务影响，不能单凭return断言继续使用失效价格 |
| 直接Feeder写价 | `oracle.move:137–150`写最终值和当前时间，未走普通适配器价差／历史策略 | 属于管理员覆盖能力；最终仍查正值／时效，但这不证明其写入市场价格正确。引用权限模块，不能算第三个独立报价源 |

本快照中主备配置为启用；没有此刻适配器已报错或发生业务中断的证据。异常分支来自代码分析，是可触发的机制风险，不是已发生事故。旧缓存价过期也不能独立证明按需更新机制永久故障。源码与部署独立等价核验的既有限制继续保留。

## 4. 应先讨论的五个问题

1. **来源是否合理且绑定正确？** 看实际消费入口、资产、单位和有效来源；单个有效来源不自动等于不合格，多源也不自动满分。
2. **最终读取端如何拒绝无效输入？** 必须从上游一直看到消费端，不能只看更新函数或配置槽。
3. **哪些故障能切换，哪些会停止？** 分别列主源过期、报错、禁用、备源报错，避免一句“支持双源”掩盖耦合。
4. **安全停止影响哪些业务？** 确认范围和可恢复条件，区分暂时可用性限制与接受错误价格造成的估值风险。
5. **谁可以覆盖普通报价保护？** 记录换源、禁用和直接写价路径；引用已做的权限判断，不对同一控制关系重复扣分。

下一步沿用配置层的判断原则：必要来源和保护已经核验、没有具体实质失效证据时，可讨论合理基础档；额外冗余按其实际效果加分；明确的切换限制按影响范围有限调整。不会要求证明所有价格永远正确，也不会因没查到错误就直接满分。具体基准、加减分和汇总方式尚未确定，当前正式分仍60。

## 5. 边界与入口

- 不新增逐账户取价、逐交易刷新模拟、独立市场参考价、Gas／清算盈利或穷尽上游组织调查。
- 无效价拒绝、价格数值正确、来源冗余和权限覆盖是不同判断；分别给依据，不能互相替代。
- 来源与报价层的结论不能无依据扩大成全协议停摆或资金损失。
