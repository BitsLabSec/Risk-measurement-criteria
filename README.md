# BitsScore 评估指南

> 评分规则的上位依据是[评分骨架 v1.0](./评分骨架.md)。各标准与骨架冲突时，以骨架为准。
> **执行评估的 agent 请直接按[工作流](./工作流/README.md)的步骤卡操作。**目前覆盖前期准备和代码安全；agent 只填写事实，计分由脚本完成。

## 做什么

一次评估最终交付**一个项目评估 JSON 文件**。

JSON 记录本轮范围、生产版本和适用的链上快照，以及代码安全、链上安全、业务攻防和盘外情报四个维度的分数或状态、主要结论及证据。未纳入本轮的维度标为「未评估」。

## 为什么做

让读者知道分数对应哪个版本、覆盖了什么、还有哪些缺口。代码安全要回答当前部署的代码有多少得到了审计覆盖。链上安全要回答当前的权限、参数、资金和依赖能否支持协议长期正常运行。另一位评估人应能用同一批证据复核结论。

## 怎么做

### 1. 确认本轮任务

记下评估哪个项目、纳入哪些业务、要做哪几项评估。只进入本轮任务指定的评分分支。

### 2. 做前期准备

做代码安全或链上评估时，先打开[前期准备执行表](./前期准备/前期准备执行表.md)，从第 1 步找到生产部署开始。核验生产源码后，按业务梳理模块、代码职责、特权角色和关键控制。跟着表里的链接查具体判据，每步填上结果或产物链接。

前期准备产出一张全量关系图和一张结构化表。同一轮同时做代码安全和链上评估时，两项共用这套图表、生产版本和业务范围。 [前期准备产物格式](./前期准备/assessment-preparation.md#三交付什么)

### 3. 按评估项执行

| 本轮评估项 | 从哪里开始、接着怎么做 |
| --- | --- |
| 代码安全 | 打开[代码安全评分标准 v1.1](./code-security/code-security-rating-standard.md)，按第 3 节七个步骤执行：建分母、收集报告、逐行判定覆盖、算覆盖分、给总体评价、风险封顶、得出最终分。交付内容见[第 4 节](./code-security/code-security-rating-standard.md#4-交付)。 |
| 链上安全 | 打开[链上安全评估标准 v1.0](./onchain/链上安全评估标准.md)，按第 2 节的流程执行；每个业务按[专项索引](./onchain/README.md#类型专项)选一个专项。结果字段见[第 10 节](./onchain/链上安全评估标准.md#10-每个结果必须带的字段)。 |
| 业务攻防 | 打开[业务攻防评级标准](./业务攻防/web3-business-security-rating-standard.md)。把终审渗透报告的覆盖和保留风险映射到实际业务流程，按标准评分。 |
| 盘外情报 | 打开[盘外情报评级标准](./盘外情报/offchain-intelligence-rating-standard.md)，逐项查公开材料并判断符合程度。按需整理[安全运营与披露](./盘外情报/security-operations-disclosure-supplement.md)，作为不计分的补充信息。 |

### 4. 生成并校验最终 JSON

- 将本轮结果和关联证据汇入一个项目评估 JSON 文件，核对其内容与评估记录是否一致。
- 按评估项分别记录结果。核对每项结论能否追到本轮范围、版本和证据。按对应标准标明未覆盖、评估未完成、失败和不适用。同一证据可以复用，同一风险只计一次。
- 采信适用于本轮的审计和渗透报告，以终审结论判断问题状态。同类报告同等采信。纯中心化问题按当前链上控制评估，新增测试或演练另行约定。
- 分别记录报告或测试日期、最新适用性确认日期、链上快照时间和资料更新时间。适用性确认只记录证据是否仍可使用。缺少日期标「未提供」。
- 历史结果按原批次的范围、快照和规则版本复算。
