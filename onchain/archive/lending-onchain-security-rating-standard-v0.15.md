## v0.15 执行规则

权限管理采用 [通用权限分表](./链上评估复用指南-v0.7.md)。Lending 按借款、还款、清算和提款的实际路径确认后果和退出条件。参数配置、资金与外部依赖采用[通用链上标准](./通用链上安全评估标准-v0.5.md)的证据和分档规则，并按以下检查细则执行。

结项时，未确认的保护和替代路径不计入。适用检查所需的必要条件仍缺证时，该项记 0 并保留在适用分母中，记录缺证原因、已核事实和影响范围。选配项缺证只披露，确认不适用才记 N/A。业务或项目适用 0 分封顶须另有确证。 [证据缺失与结项](./通用链上安全评估标准-v0.5.md#5-证据缺失去重与结项) · [项目和业务风险封顶](./链上评估复用指南-v0.7.md#项目和业务风险封顶)

### 1. 冻结范围和判断口径

1. 从范围清单取得前期按功能划分的业务模块、生产部署、检查点、市场、资产、模式和受影响的必要操作。市场、资产和模式作为业务模块内的核验范围。沿准备阶段的关系图确定共享配置、主市场储备、池、资金管理对象及必要依赖。同链使用同一快照，核验对象计入每项目每轮跨链合计 50 个目标的上限。
2. 先核验共用控制和已选市场。只有必要操作受到池级或模式级差异影响，且读取指定对象足以补齐证据时，才在上限内下钻。复用已有池级状态、源码映射和汇总。到达上限时记录未核实的对象、受影响的必要判断和覆盖范围，按结项规则计分。
3. 对每项保存链、检查点、对象及字段、原始值、资产单位、适用模式、实际生效代码位置、派生公式和证据。当前状态、预先定义的情景和商业趋势分别记录。既有准备图中谁能改参数的证据供配置引用，由权限维度判定控制风险。
4. 在同一业务、同一大项和同一证据支持的范围内，先取全部适用检查命中的最低档位上限，再累计该档内已证实的独立轻微影响。按根因、受影响范围和后果去重，同一事实命中多条时取最高扣分。档内分为 `max(下档上限 + 1, 本档上限 − 有效扣分之和)`。档位 100 取 61 至 100 的整数，60 取 1 至 60，0 保持 0。其他已采用的细分档按该分表的实际下档上限设置边界。60 档的触发事实只定档，额外扣分只计触发事实之外且仍属同档的独立问题。适用检查的必要条件缺证时，按结项规则记该检查 0 分并保留已核实的局部结果和风险。
5. 样本、市场及模式分别列结果。采用预先确定的专项加权规则时，各具名输入范围先独立定档和细评，再按该规则汇总。公式输出直接作为汇总值并保留原精度。其余按同一业务及大项的通用规则结项，声明范围内适用的必要检查缺证记 0。每条档内事实保存部署路径、快照位置、影响及仍能履行必要权益的证据。

### 权限管理的 Lending 路径

按[通用权限分表](./链上评估复用指南-v0.7.md)对每种实际后果取最弱完整路径。可取得池资金处分或债权改写能力的升级控制归 H1，有界改变存量估值或清算条件的风险管理员归 H2，可无限期阻断必要还款、提款或清算的暂停控制归 H3。逐条回到实际权限对象、持有人、签名门限及可达的上级授予或恢复路径。若两种 Cap 的组合归同一多签，按实际最低共同批准需求核验。延时保护按生效配置核查受影响范围的必要退出入口及控制者能否在等待期提前关闭它。最弱路径或有效延时发生改变时，按通用表重新定档。资金可达性、实际付款和第三方组件运行状态归资金与外部依赖。

#### 配置档内扣分

下表要求用当前生效配置和对应入口证明轻微影响，并核验该事实自身对必要权益的作用。60 档仍可存在另一项已用于定档的独立故障。表里的“仍可完成”只要求候选扣分事实本身维持必要权益、保护和时限。候选事实若触发更低档，先重新定档。正常运行条件按基准条款评价。

| 细分项 | 扣 1 分：次要保护变弱 | 扣 2 分：操作已有额外负担 | 扣 3 分：次要路径已不可用 |
| --- | --- | --- | --- |
| 资产、市场和价格绑定 | 第二层交叉核对覆盖收窄，生效绑定和主校验仍覆盖全部适用资产。 | 备用同资产映射需要额外完成一次链上确认，所有必要操作仍能在约定条件内完成。 | 独立的批量绑定核对路径已停用，各资产仍有能完整执行必要业务的逐项有效映射。 |
| 抵押准入及清算联动 | 次要的准入或清算校验被削弱，当前主校验仍执行适用的抵押、清算及总扣押限制。 | 已确认原有操作需增加确认步骤才能继续，必要清算及处置仍满足原定条件。 | 次要批量处置入口不可用，已核验逐项处置仍能在相同适用条件下完成必要清算。 |
| 敞口限制 | 次要组合限额约束弱化，必要资产级、方向级和总敞口限制依旧有效。 | 调整已批准的额度需要额外处理或核对，但既有资格、上限和必要操作均得到保留。 | 独立的额度合并处理路径不可用，必要的分项调整与存量退出仍可完成。 |
| 利率及费用 | 参数生效前的次要比对保护削弱，部署依旧保证适用曲线定义、费用及结算上限。 | 当前费用或结算流程已有额外确认步骤，实际扣费、剩余资产处理和必要结算仍满足约束。 | 次要批量结息或收费入口不可用，逐项处理仍满足全部必要结算条件和期限。 |
| 特殊模式 | 一层附加模式交叉检查覆盖收窄，适用成员、方向、额度和模式退出保护仍受主机制强制约束。 | 已启用模式切换或退出增加处理步骤，但适用用户仍能按原有条件完成所需操作。 | 独立的便捷模式迁移入口不可用，现有用户仍能完整还款、退出或按原规则继续必要操作。 |
| 暂停、冻结与必要操作 | 次要的恢复检查或保护层减弱，当前操作开关和备用机制仍保障必要入口。 | 异常后需要额外执行一次状态确认或经已有路径恢复，必要操作仍在适用期限内完成。 | 次要批量或便捷入口停用，已核验其他入口能为同一实际受影响范围完整履行必要操作。 |

执行计算时按部署的整数顺序和舍入规则还原，记录范围和前提。

1. **准入和清算。** 存在独立初始限制时，令 `b` 为最大初始债务价值与抵押价值之比，`λ` 为有效清算线，`β` 为每偿还一单位债务的实际抵押扣押倍率。按实际用途、借款权重和模式调整有效参数。固定奖励、折价出售和动态奖励各用自身定义，协议分成只按代码计入总扣押一次。对普通超额抵押模型核对其适用关系，例如 `0 < b ≤ λ ≤ 1`。单 LLTV 机制的独立开仓距离记 N/A，继续核对清算约束。已停新增的模式按机制核验存量义务和退出。
2. **敏感性计算。** 在单抵押、单债务且相关参数固定时，计算相对价格下的开仓和清算指标。`M < 0` 表示该条件下账面抵押无法覆盖含奖励的清算需求。计分依据是它是否违反该范围已确认的实际安全约束。历史固定跌幅保留在 v0.12 复算区，当前情景是否计分由评估前已经采用的阈值决定。

   ```text
   到清算线的开仓缓冲 = 1 − b/λ
   最大开仓后相对价格下跌 d 的健康度 = (1 − d) × λ/b
   清算线处账面缓冲 M = 1 − λ × β
   清算线后再下跌 d 的账面缓冲 = 1 − d − λ × β
   固定 λ、β 且部分还款比例 0<f<1 时的剩余健康度 = (H_before − λ × β × f) / (1 − f)
   ```

   最后一式适用于价格不变、仍有正的剩余抵押、协议采用上述健康度口径的部分清算。清算规则不同、全额还款或涉及其他资产时，读取部署的实际扣押和剩余权益公式，按实际受影响的资产及模式留下结论。开仓接近清算线、清算后剩余健康度及协议现金短缺各自报告。
3. **敞口和利率。** 设 `X` 为代码比较的当前同单位数量，`Q` 为有限正上限，统计 `X/Q` 及 `max(Q−X,0)`。零上限先确认禁用、无限制或合法零值的真实含义。超上限存量记录新增入口现在如何执行，适用警戒以已确认的运行政策为准。利率用原生利用率 `u` 和实际函数 `r(u)`，核验定义域、分母、拐点和高利用率响应。对适用连续分段线性模型可算 `k_low=[r(u*)−r(0)]/u*`、`k_high=[r(1)−r(u*)]/(1−u*)`，要求 `0<u*<1`；其他机制按自己的分支和单位解释。固定利率机制的利用率响应项记 N/A，当前利率仍可披露。
4. **汇报配置分。** 把所有适用检查映射到相应档位上限，再按第一节处理独立的轻微影响。必要输入缺证的适用检查记 0，有机制证据证明不适用才记 N/A。相同默认配置与覆盖模式分别记录实际受影响范围，模式的存在及其保守情景结果只说明该模式的可达条件。

#### 资金与依赖档内扣分

先按已核实的当前情况定档。现金、额度及时限以同池同币及真实可达路径为依据，主路径仍可用须有证据。对每个独立候选事实沿用上文的 60 档处理，核验它是否新增必要权益缺口。

| 细分项 | 扣 1 分：次要保护变弱 | 扣 2 分：操作已有额外负担 | 扣 3 分：独立次要业务功能已不可用 |
| --- | --- | --- | --- |
| 现金周转和必要付款 | 经查证的备用现金补充路径减弱或失效，主路径仍按原步骤和时限覆盖必要应付。 | 实际兑现需额外完成一次调拨或转换，已核实同币额度和时间仍满足必要付款。 | 已启用的自选快速取款功能不可用，普通取款仍按适用期限覆盖全部同范围必要应付。 |
| 可调拨储备及损失缓冲 | 独立的备用储备减弱或失效，现有主储备仍按原步骤满足承诺额度、时限和用途。 | 取用新增一个可核验的解锁或确认步骤，期限、可用额度及承诺用途仍满足。 | 已启用的批量储备调拨功能不可用，逐项调拨仍能按期交付全部必要储备。 |
| 报价及价格适配器 | 第二层交叉验证或独立备用报价削弱或失效，实际主源有效，必要输入保护仍按当前条件执行，无新增操作负担。 | 已实际需要额外一次按需更新或切换才能继续，核对全部适用的估值、清算、还款、提款仍可按期限完成。 | 依赖报价的可选批量入口不可用，逐项操作仍可使用必要输入并按期完成。 |
| 外部资金调拨及必要服务 | 第二层外部调拨或服务保护减弱或失效，主路径仍按原步骤及时提供必要资金或服务。 | 已发生额外调用、短时延迟或补充授权步骤，整体仍能履行该范围必要权益及期限。 | 已启用的外部批量调拨功能不可用，逐项调拨仍能完整支持必要操作。 |
| 收入和补库保障 | 经核实的备用补库资金来源缩减或失效，主来源仍按原步骤和期限满足适用目标。 | 已有额外提取或划转步骤，核对到账归属、额度及时限后全部既定补库义务仍能履行。 | 已启用的批量归集功能不可用，常规逐项归集仍能按期完成所有适用补库义务。 |

1. **现金及缺口按池同币计算。** 校验 `S` 是否需按代码扣除已包含的虚拟国库债权。应计权益、外部管理资产和未到账承诺分别列账。`M(t)` 只用经过验证、在期限内可调回该池的同币额度。共享资金按已知分配或可证明上限入账，每份资金只保障一次。预期借款回收、备用报价或储备调拨按声明的情景和期限说明。

   ```text
   直接现金覆盖 = C/S                        # S > 0 时披露
   借款／供应比 = B/S                        # 协议原生利用率按部署计算
   直接现金缺口 = max(0, D(t) − C)
   含已核实补充资金的缺口 = max(0, D(t) − C − M(t))
   压力后损失缺口 = max(0, q × B − K)         # q 为已声明情景，K 为该池可用独立缓冲
   ```

   `D(t)` 是有据的实际应付或声明情景需求，按期限和权益条件取值。看不到明确应付款时，保留池级流动性指标，并明确债权和可付款分别已核到哪里。用户供应总额不默认等于现在必须全额兑现的债务。分母为零时说明实际机制。跨池和跨币种先按同池同币配对，估值只用于汇总并保留时间和来源。
2. **依赖按操作倒查到最终使用端。** 区分读缓存、交易按需更新、直接喂价和当前最终价格判定。对每个适用分支记录是否采用备用源、拒绝失效输入或无法继续。安全拒绝命中时继续判断会阻断哪条操作、普通还款和清贷后提款是否还能完成。单一来源、重复 feed 和无实际接管入口分别说明，按事先存在且适用的冗余、时效或恢复要求判分。只复用已核验的部署机制、可用输入及快照状态来检验这些条件。
3. **收入只使用可核对口径。** 区分应计利息、协议实际入账的利息、已提取和可用于补库的现金。混合手续费和静态 `借款余额×APR` 可用于说明组成或速率，实际已实现收入以可归因现金凭证为据。有预先声明的补库目标和可验证的留存资金时，另列可补额度和时间。
4. **输出资金与依赖分。** 按同一市场、币种、用户权益及操作范围列独立检查，先定最低档位上限，再依第一节累计独立同档事实。因同一报价故障出现的资金操作受限由直接依赖项处理，现金项引用它。适用的必要检查缺证记 0，只影响依赖该检查的评分范围。余额、供借总量、现金比率、未校准的敏感性结果和混合收入可随分项披露。输出已知范围状态、未核实范围、风险限于什么对象及可以恢复的条件。

例如某已声明市场因报价冗余低于事先定好的警戒，资金与依赖档位上限为 60。另一项有独立资金对象和生效路径证据的恢复步骤使同一范围多一次调拨，付款期限仍满足，对该独立事实扣 2 分，得 58。报价冗余警戒造成的重复影响沿原事实一并解释。

## 第一部分：业务关键权力与约束（v0.6）

### 1. 定位与边界

以 Lending 的业务后果为终点，分析完整权限图，再按最弱可达路径评分。角色是权限图中的节点，多签是强制执行约束，必须计入完整路径的最少不同签名密钥数；不另设重复加分项。

本项使用已确认的函数能力、权限机制映射及当前链上配置，不重新进行代码漏洞测试。代码逻辑评估参见 [代码安全评分标准](../../code-security/archive/code-security-rating-standard-v0.9.md)。

本版保留 H1—H3 后果分类，统一按授权与延迟条件评分，不再因后果名称把有效多签判为不及格。单密钥且无有效退出保护为 0；有效共同授权基准为 80；有效延迟分 24／48 小时两档。该分值为用户确认的初步评级政策，不代表损失概率。

本标准中“控制组”“独立”“实际控制”均指链上可核验的控制端、签名集合及授予／替换／升级关系。代码解释谁能做什么，链上 owner、角色和多签配置说明当前由谁控制；不要求证明背后的真人、公司或组织独立性。地址不同不自动加分，地址相同、共享密钥及可绕过的共同批准按已有图规则处理。

本项评价特权带来的控制风险。正常清算、按既定规则执行的业务行为，不自动视为特权损害。

### 2. 业务后果分类

| 后果编号 | 业务后果 | 追踪范围 |
| --- | --- | --- |
| H1 | 任意处分用户资产，或任意重写资产归属、债权债务 | 转移、任意授权、任意执行，以及经已确认组合路径取得相同能力的升级、参数或组件替换 |
| H2 | 在约束内改变估值、抵押或清算等条件，制造额外偿付／存量头寸风险，且未形成 H1 能力 | 受约束的价格源、抵押配置、风险限额及存量清算条件变更路径 |
| H3 | 无明确到期或独立恢复保障地阻断必要业务 | 阻断还款、提款、清算，以及恢复能力和恢复条件 |

授予角色、替换管理员、修改多签门限、启用模块、改变治理及 Timelock 约束，归入权限图的路径，不作为第四种后果单独扣分。

按已确认的最大业务后果归类。参数修改若可经已确认路径形成任意资产处分，归 H1，不能只因入口叫“风险参数”就按 H2。对应能力尚不明确时标待核验，不能未经证据升级或降级。同一路径可涉及其他后果，保留解释，最终取最低分，不累计扣分。

### 2.1 评分边界：按实际能力，不按“privileged”标签

- 关键路径：能直接或经组合影响用户本金、资产归属、债权债务、存量估值／清算条件，或阻断必要退出操作；能够铸造／授予上述角色、升级／替换关键组件、解除约束的上级也必须追踪。角色名或业务方称“次要”不能成为豁免依据。
- 辅助权限：已通过代码确认仅管理协议自有手续费／奖励、展示或其他不触达上述后果的功能，且不能经授予、升级、恢复或组合取得关键能力，列为披露，不进入关键权限最低分。一个辅助函数由 EOA 执行，不自动使全协议为 0。
- 函数内部或 friend 调用：不是外部直接权限，要连接实际可达调用者。恒定 abort 函数列为不可执行，不虚构现存能力。合法提款协议金库且受金库债权上限约束，不等同于任意处分用户本金。
- 辅助管理若能影响范围内用户已经取得的奖励权益，应单列该范围和后果，不能仅以“奖励模块”为由一概排除。未纳入范围的独立奖励持有人仍保持原边界，不扩大查询。
- 权限仅作用于单个资产／池或模块时，记录这个范围；只有已确认的共享控制路径才可作为全声明范围的权限约束。不能把小范围辅助权限直接外推为全协议失控。

先完成现有范围的“函数→所需角色（AND／OR）→当前能力对象与持有人→根控制及派生／升级边→后果和作用范围→评分”。不能仅取几个代表性角色，遗漏已有上级授予或可替换路径。每个已采函数有分类及依据；披露不补 100，也不与关键路径做数量平均。

### 2.2 必须按顺序执行的权限评估流程

| 步骤 | 必须完成的工作 | 输出与通过条件 |
| --- | --- | --- |
| 1. 冻结范围和版本 | 固定链、市场、资产／模块、检查点、源码映射和评分版本；先查已有规则与归档 | 不新增账户／市场；保存范围和版本 |
| 2. 逐函数确认能力 | 列全部特权函数、角色AND／OR、可执行状态、后果和作用范围 | 每个函数有代码位置；内部和恒定abort不虚构直接能力 |

| 4. 闭合权责图 | 展开铸造／授予、管理员、升级、恢复、模块和可解除约束；派生角色接回根控制 | 每个关键后果有完整路径，不能以代表角色代替全图 |

| 7. 判授权和时间锁档 | 单签0或合理多签80起点，再检查公开固定内容、强制24／48小时、旁路和协议退出开关 | 单签0／40／50，多签80／85／95；队列剩余时间另披露 |
| 8. 一次关联修正 | 在预先定义的关键控制域间检查共同密钥 | 基准、模块关联0／1、最终分及证据可回溯，同一关联不重复扣 |
| 9. 校验后发布 | 对照函数清单和图，确认关键路径无遗漏、其他分项未改、结果／规则／JSON同版本 | 完整后发布；缺关键路径则列具体缺口，不宣称已完成 |

新增部署、函数、角色或语义变化才回到相应步骤。正常复扫按已冻结JSON规则执行，无需Agent重做整份研究。不能为了预期分数临时换档，也不能在上述流程完成前发布完整权限分。


### 3. 权限图的节点、关系与约束

#### 3.1 最小记录

| 对象 | 记录内容 |
| --- | --- |
| 控制端 | EOA、多签、治理、模块、恢复控制者，以及链上可核验的控制集合 |
| 权限节点 | 当前角色、管理员关系、受控操作、目标合约及相关参数范围 |
| 执行条件 | 必须满足的签名、投票、等待、限额及其他链上条件 |
| 影响对象 | 市场、资产、用户权益、影响范围、金额边界及持续时间 |
| 证据快照 | 链、区块号及哈希、读取目标、原始值、相关交易和事件、取证时间 |

#### 3.2 图分析规则

| 分析对象 | 确定规则 |
| --- | --- |
| 直接能力 | 当前控制者能执行哪些影响资金、债务条件和必要操作的行为 |
| 间接取得能力 | 追踪授予角色、替换控制者、升级组件、修改约束的路径；保留每一步审批及时间条件 |
| 联合控制 | 需要同时满足的审批按组合条件计算；可任选通道分别计算，取更弱路径 |
| 控制重叠 | 同地址合并；共享签名人计算最小满足集合；不额外要求实际组织归属证明 |
| 约束可变性 | 控制者可以自行解除的约束不能按永久约束计；分析“先解限、后操作”的完整路径 |
| 持续使用 | 单次限额需检查能否重复、补充或重置；单次小额不必然意味着累计影响受限 |
| 恢复与阻断 | 同时追踪接管、取消、必要操作失能及恢复路径 |
| 证据不足 | 关键节点、控制关系或执行条件未知时，不得认定危险路径不存在 |

#### 3.3 必须覆盖的控制关系

| 配置情况 | 处理规则 |
| --- | --- |
| 超级管理员能任意设置多个角色 | 将其视为相关能力的间接控制者，沿授予路径计算实际审批和等待条件 |
| 多个角色由同一地址持有 | 合并能力集合，检查组合后能否解除限制、取消制衡或扩大资金影响；不按角色数重复扣分 |
| 不同角色由同一多签持有 | 不认定为角色独立；同一控制集合可能完成多个步骤 |
| 不同多签共享签名人 | 计算达成各门限所需的最小签名人联合，不将门限简单相加 |
| 地址不同但链上控制集合重叠 | 比较签名门限和完整批准路径；若同一最小集合可分别完成多个环节，不认定为独立制衡 |
| 模块拥有替代执行权 | 将模块及其控制者作为另一条路径；按其实际目标、函数、参数、额度及频率约束评价 |
| 恢复机制能替换签名人或门限 | 将恢复控制者、等待、取消及最终接管条件纳入图 |
| Guard、否决者或取消者存在 | 记录覆盖路径、独立性、可撤换性，以及其可能造成的阻断 |
| 控制者可修改自身约束 | 分析修改约束所需条件，不能只使用当前表面门限、限额或延迟评价 |
| 角色已放弃或无人持有 | 继续检查上级能否重新授予，以及必要业务是否因此失能 |

示例：两个 3/5 多签共享三名签名人，这三人可能同时控制两者，不能按“需要六人”评价。

“强制共同批准”指完整可达路径至少需要两把不同链上密钥。对加权多签，计算满足权重门限所需的最少不同密钥数 k；不是把 threshold 字段当人数。原生 2/3、3/5 等权多签分别为 k=2、k=3，都满足 B。1/N 或单把高权重密钥足以达标则 k=1，归 A。共享签名人只消除虚构的额外独立层，不抹掉已有 k≥2 的门限约束。可任选路径取最弱；必须联合的路径按不同密钥集合去重计算。恢复、模块、升级和授予绕过路径仍须纳入。未知控制类型记 U，不猜成单签。这里不证明真人／组织独立性。

Sui 原生多签验证不同公钥签名的权重是否达到门限，地址绑定门限及委员会；参考 [Sui Multisig Authentication](https://www.docs.sui.io/develop/transactions/transaction-auth/multisig) 和 [Mysten SDK multisig](https://sdk.mystenlabs.com/sui/cryptography/signers/multisig)。文档支持门限执行机制，本文分值不是 Sui 官方评级。

### 4. 去重与适用范围

| 情况 | 处理 |
| --- | --- |
| 同一根控制者通过多个角色达到同一后果 | 保留不同路径，取最低路径分，不累计扣分 |
| 同一路径涉及多个后果 | 保留后果解释，按最低适用结果汇总，不叠加处罚 |
| 多签、超级管理员、共享签名人同时存在 | 在同一权限图中解析，不作为三个独立扣分项 |
| 权限只涉及部分资产或市场 | 对应范围单独评价，不将局部能力无依据地外推至整个协议 |
| 不同市场 | 本版仅在已声明协议范围内按第 2 部分的供应金额权重汇总；市场／资产的局部结果和权重同时展示，不扩大范围 |
| 仅能暂停新增借款，不能动本金或阻断必要退出操作 | 不强行归入损害类别；展示其具体能力 |

### 5. 授权与有效延迟条件

#### 5.1 条件定义

| 条件 | 认定要求 |
| --- | --- |
| A：单密钥可达，无有效退出保护 | 某条完整路径仅需一把密钥，包括可单签绕过的表面多签 |
| B：强制共同批准，无有效退出保护 | 完整路径最少需要 k≥2 把不同链上密钥；有效多签即可满足，且不存在单密钥绕过路径 |
| C：单密钥控制＋有效退出保护 | 危险改变公开可见；完整路径存在不可绕过的等待；当前协议退出入口未被暂停、冻结或紧急配置阻断，且等待和退出入口不能被危险操作控制者提前绕过或关闭 |
| D：共同批准＋有效退出保护 | 同时满足 B 的共同批准要求及 C 的退出保护要求 |
| 确认不存在对应能力 | 在完整核验范围内，确认不存在直接或间接路径；不能仅依据角色无人持有 |

为避免 C 与 D 重叠，分类时优先识别是否满足 D：既满足 k≥2 共同批准又满足退出保护的路径归 D，仅满足退出保护的单密钥路径归 C。2/3 与 3/5 的 k 分别披露，本版不再凭未校准的“人数加分”区分两者。

不可绕过的延迟与当前协议级退出开关分别记录；只有延迟、但退出被暂停时，不能认定 C 或 D。没有延迟保护的协议不会仅因当前未暂停而进入 C／D。按已有机制区分受影响的操作或资产范围，无需遍历个人账户。

#### 5.2 主动否决与强制批准

主动否决需要及时发现并采取行动，不等同于“未经独立批准根本无法执行”。

| 机制 | 处理 |
| --- | --- |
| 仅有主动否决能力 | 记录覆盖范围、独立性及可撤换性，暂不单独提升档位 |
| 否决者已经实际取消危险操作 | 更新该操作当前状态，不据此证明所有未来操作都会被阻止 |
| 独立主体属于强制批准环节 | 满足完整路径要求时，按 B 或 D 认定 |
| 开放执行者只能执行已批准、已到期的固定操作 | 不将其误判为可自行决定操作内容的危险权限 |

#### 5.3 有效退出保护

| 检查点 | 具体要求 |
| --- | --- |
| 完整路径 | 上级授予、换模块、紧急通道不能更早造成相同后果 |
| 公开可见 | 危险改变及其目标、参数和生效条件可被核验 |
| 机制与排队状态 | 机制分使用公开排队到最早可执行的强制总延迟；当前已排队操作另列 ETA／剩余时间，不把正常倒计时误判成机制缩短，也不声称用户此刻还有完整等待窗口 |
| Lending 退出条件 | 核验协议提款、还款及必要减债入口的暂停／冻结／紧急状态和代码作用；正常还款前提、抵押检查不视为额外阻断 |
| 当前可行范围 | 按市场／资产／操作披露入口是否开放；现金余额另列，不要求用户级提款模拟或证明所有人能同时退出 |
| 保护可撤除性 | 危险操作控制者不能提前关闭退出入口或解除等待 |
| 证据不足 | 链上延迟、绕过路径或退出开关确实不明时，不能认定 C 或 D；不以未调查链外身份、未逐账户模拟为缺口 |

“两步权限转移”本身只说明接收确认流程，不自动证明有效退出窗口或独立审批。

有效延迟以秒为计算单位：24 小时=86400 秒，48 小时=172800 秒。低于 24 小时无延迟加分；24 至不足 48 小时为基本有效；至少 48 小时为增强。超过 48 小时不继续机械加分。必须公开固定操作目标／参数或升级内容，改变内容需重新等待；等待、改短等待及换管理员不能绕过同样的公开延迟；必要退出入口当前开放且危险控制者不能提前关闭。未达到这些条件的时间锁仅披露，不作为退出保护。

一个区块、10 分钟、6 小时均无延迟加分。原本等了 48 小时的正常排队操作剩一个区块，机制分不下降，剩余窗口仍明确披露。已确认应急通道可以更早完成相同后果则按更弱路径计算；只暂停新增业务、不妨碍还款提款，不当成退出旁路。C／D 只表示本政策下的退出窗口约束，不保证流动性、未来价格或所有人同时全额退出。

阈值参考公开治理实践，但不是行业统一安全定理：[Aave 治理](https://www.aave.com/docs/ecosystem/governance)使用 1 天／7 天执行延迟；[Compound v2 治理](https://docs.compound.finance/v2/governance/)使用 2 天执行延迟。本文选取 24／48 小时作为本版固定政策，单签最长仍不及格。

### 6. 分值与公式

#### 6.1 路径分值表（H1／H2／H3 通用）

| 授权条件 | 无有效延迟／不足 24 小时 | 有效延迟 ≥24 且 <48 小时 | 有效延迟 ≥48 小时 |
| --- | ---: | ---: | ---: |
| 单密钥可达 k=1 | 0 | 40 | 50 |
| 强制共同授权 k≥2，且无单密钥旁路 | 80 | 85 | 95 |
| 完整核验不存在对应危险能力 | 100 | 100 | 100 |

60 为及格线，合理多签80为良好基准，时间锁属于增量保护。2/3 与 3/5 等权多签均进入共同授权档；门限、成员、权重和重叠分别披露，本版不凭未校准的人数公式额外加分。1/N 或一把高权重密钥即可执行按单密钥处理。没有任何保护的单签为 0；有合格延迟的单签保留已讨论的 40／50 档，仍不能仅靠等待达到及格。H1—H3 记录不同后果及范围，不再使用不同基础分。

#### 6.2 计算符号

- `m`：一个具体市场及本次声明的资产／用户权益范围。
- `h`：适用的业务后果 H1、H2 或 H3。
- `P(m,h)`：在已确认机制与当前配置下，可达到该后果的完整权限路径集合。
- `q(p)`：路径 `p` 的控制条件 A、B、C 或 D。
- `T(p)`：完整路径生效前不可绕过的公开强制延迟秒数，及公开固定载荷／不可提前关闭退出等资格条件。
- `L(q,T)`：上表中授权与有效延迟对应的政策分值。

```text
路径分：S(p,h) = L(q(p), T(p))

单个后果分：S(m,h) = min { S(p,h) | p ∈ P(m,h) }

权限基准分：S_permission_base(m) = min { S(m,h) | h 为适用后果 }
最终权限分：S_permission(m) = max(0, S_permission_base(m) − D_assoc(m))
```

只有在相关范围核验完整、确认不存在对应直接或间接路径时，该后果记 100。不能因未发现路径、角色无人持有或地址读取失败，就将路径集合视为空并计 100。

不按角色数量或路径数量加权平均，不按漏洞数量、权限名称、是否使用多签或 Timelock 直接加减分。

#### 6.2.1 跨关键控制域的关联修正

合理多签完成必要授权保护，基准80；有效24／48小时延迟分别提高至85／95。60仍为及格线，80为良好基础，附加措施仅作增量提升。无保护单签0、有效24／48小时单签40／50保留。

关联扣分仅设0或1，在权限模块汇总时最多扣一次，不按共享密钥数、多签对、角色数或H1—H3类别累计。先按用户权益终点预定义关键控制域，例如借贷核心控制、最终价格控制；不能按文件数、模块名或钱包地址人为拆域。同域同一控制者多角色先合并。

不同关键控制域共用同一控制者、不同多签部分公钥重叠、委员会完全相同，均属于链上关联，最多同样扣1。这样不会出现合并成一个钱包反而免扣的倒序。共享不抹掉多签门限，也不构成额外独立审批层。真正单签旁路仍按单签0／40／50，而不是只扣1；未知关联不能冒充已证实独立。

```text
权限基准分 = 同一声明范围内最弱关键路径分
D_assoc = 1（共同授权路径所在的不同关键控制域共享密钥），否则0
最终权限分 = max(0, 权限基准分 − D_assoc)
```

单签或确认不存在对应危险能力的结果不叠加此项关联扣分。对仅涉及局部资产的路径保留作用范围，不无依据扩为全协议。基准分、关联扣分和最终分分开展示，不能在每条路径、每个H类和模块上重复扣。

NAVI现有13组关键路径基准均80；借贷核心与最终价格控制域存在共同公钥，因此关联只扣1，权限分为79。1分是明确的初步评级细分政策，不代表量化损失概率。


#### 6.3 特殊处理

| 情况 | 分数处理 |
| --- | --- |
| 暂停有不可自行延长的到期或独立恢复保障 | 不按无限阻断处理；临时可用性影响单列 |
| 已确认权限配置使必要操作永久失能，并影响用户资金 | 对应后果记 0，不能因权限已放弃得 100 |
| 硬约束使某种后果不可达 | 该后果可以记 100，继续检查其他剩余后果 |
| 约束仅缩小影响范围 | 按资产／市场分别评价，不抹除仍存在的能力 |
| 关键路径、影响范围或控制独立性未知 | 展示已确认结果及待核验范围，暂不发布确定总分；已确认风险继续保留 |

已确认永久失能的 0 分结果优先于普通路径分值表。它属于必要业务失能结果，不因尚有其他高分项而被抵消。

#### 6.4 多模块、弱旁路与关联多签示例

| 场景 | 处理 |
| --- | --- |
| 关键升级为 2/3 多签，无有效时间锁 | 路径基准80 |
| 上述多签另有 48 小时有效退出保护 | 路径基准95 |
| 同时存在 EOA 可立即给自己授予相同升级或参数能力 | 对应后果 0；表面多签不能抵消单签旁路 |
| 关键角色为多签，某 EOA 仅可修改展示信息或领取协议自有已结算费用，无关键组合能力 | EOA 辅助权限披露，不拉低关键权限分 |
| EOA 被称为“次要 feeder”，实际可写入借贷最终价格 | 属于关键价格路径，必须评分，不能按名称或角色重要性描述豁免 |
| A、B 都是 2/3，多签共享足以满足两者的两把密钥 | 若任选其一（OR）只需 2 键；若都必须批准（AND）仍可能只需同样 2 键，不能当成 4 键或额外独立层；两者仍保留多签保护 |
| 某函数要求两个 Cap，当前同归 A 多签 | 按 A 的实际门限，不把同一签名集合计两次；这不等于任意跨持有人协作计划已经验证 |

NAVI 现有映射必须包含：StorageAdminCap→mint_owner_cap→OwnerCap→参数／暂停；OracleAdminCap→create_feeder→FeederCap→最终价格写入；升级控制与日常能力持有分开；StorageAdminCap AND PoolAdminCap 的金库提款受金库余额上限约束，列为辅助能力及组合披露。完整图附函数来源、当前持有人、最少密钥集合和适用范围，不能只靠四个代表角色发布完整评分。

### 7. 动态更新与分数恢复

| 触发变化 | 更新方式 |
| --- | --- |
| 权限转移、角色管理员变化 | 重算其控制的全部下游路径，确认旧路径是否消失 |
| 门限或签名人变化 | 重算满足审批条件的最小集合、控制重叠及独立性 |
| 模块、恢复、Guard 等变化 | 更新替代执行、接管和阻断路径，不能只更新多签表面门限 |
| 延迟、限额及权限条件变化 | 重算完整路径及可累计影响，保护条件失效即重新归档 |
| 危险操作进入队列 | 更新该操作的剩余窗口及适用保护，不将正常排队操作一律视为攻击 |
| 改善配置 | 旧弱路径确已消失、相关证据完整后才提高分数 |
| 未识别的新配置 | 原结论标记待核验；历史分保留，不继续冒充当前分 |
| 数据缺失或链重组 | 标明快照及确认状态，不将暂时读不到权限当成权限已撤销 |

事件或差异检测仅用于定位需重读的范围，不是评分前提；首次采样可独立计算。历史展示可额外计算 `ΔS = 新的已确认分数 − 上一次已确认分数`；若任一轮证据不足或规则／范围不可比，不展示确定变化值。上次得分不冒充当前分。

门限变动不对应固定扣分。例如从 3/5 改为 2/5，若未跨控制档位，记录约束削弱但分数可不变；若一把密钥即可执行，则按单密钥的 0／40／50 档重算。正常排队倒计时不改变机制延迟档位；延迟参数、旁路或退出资格实际变化才重新判档。

### 8. 对外展示与跨模块引用

每个市场至少展示：

1. H1、H2、H3 的分项结果、适用范围及市场权限分。
2. 决定当前得分的最弱完整路径及控制集合。
3. 该路径的执行条件、约束、实际影响和证据。
4. 链上控制重叠、共同批准条件与密钥门限的说明。
5. 未核验节点、数据时效及待确认状态。
6. 规则版本及本次快照；如有可比历史，另展示分数变化和原因，非当前评分必需输入。

权限层输出的是“当前谁能通过何种路径、在什么条件与时间内影响哪些用户权益”。第二部分评估当前生效配置的健康度，不将提议、批准、排队等治理流程作为独立评分层。权限层仅在待执行操作影响当前控制路径或有效退出保护时引用其状态，不对同一事实重复加减分。

### 2. 抵押与清算缓冲：明确公式与初步判档

#### 2.1 归一化定义

- `b`：当前机制允许的最大初始实际债务价值／抵押价值；仅用于存在独立初始借款限制的机制。
- `λ`：开始触及清算线时的实际债务价值／抵押价值；已折算借款权重、模式覆盖等因素，不直接混用原始 LTV、RAY 或百分数。
- `β`：每偿还 1 单位债务实际扣押的抵押品总价值倍率，包含按代码分配给执行者和协议的总额。例如额外总奖励为 5% 时为 1.05；折价拍卖等机制须按自身公式归一化，不能一律使用 `1+字段值`。
- `d`：抵押品相对借款资产价格的跌幅；债务数量不变，不新增利息。抵押和借款价格同步变化时，使用其相对价格变化，不重复计算两边涨跌。

已核验普通超额抵押机制下 `0 < λ ≤ 1`、`β ≥ 1`、`0 < b ≤ λ` 是适用条件。确认违反对应机制的约束记 0；仅有字段语义未解析记 U。仅借出、禁止新增抵押借款（如有效 `b=0`）时，该用途的 C2 为 N/A，旧清算参数仍披露，不推断存量债务为零。

原始借款权重为 `w` 时，先按代码得到有效清算线，例如在 `HF=抵押价值×LT/(债务价值×w)` 的机制下 `λ=LT/w`；`b` 同样从实际开仓约束取得，不能默认所有协议都重复除以 `w`。

#### 2.2 公式

对一组允许的抵押／借款组合，定义两个独立情景，不将两次冲击连续叠加：

```text
情景 A：按最大初始比例借款，抵押相对价格下跌 d。
H₀ = λ / b
H(d) = (1 − d) × λ / b
D_open = 1 − b / λ                 # 从最大初始借款到清算线的价格缓冲

情景 B：已经到达清算线，此后抵押相对价格再下跌 d。
M = 1 − λ × β                     # 清算线处，计入总奖励后的账面缓冲
M(d) = 1 − d − λ × β               # 再下跌 d 后的账面缓冲

B_buf = min(D_open, M)             # 两个独立情景中更薄的缓冲
```

`H(d)≥1` 和 `M(d)≥0` 分别表示通过对应账面情景，不表示真实账户分布或清算一定成交。`M` 是完整债务对应扣押价值的保守覆盖测试，不要求协议一次清算全额，也不把它称作实际坏账。固定比例公式不适用时，用已确认的本协议机制计算等价结果，不扩展到逐头寸模拟。

单 LLTV、没有独立 `b` 的机制：不构造 `b=λ` 来罚“零开仓缓冲”，仅计算 `M` 并令 `B_buf=M`，标明开仓缓冲检查 N/A。动态奖励存在已知配置区间时，使用对应清算线情景中代码允许的最大扣押倍率；适用性必须随规则记录。

#### 2.3 固定压力幅度

| 情景类别 | 温和冲击 `d₁` | 较强冲击 `d₂` | 选择依据 |
| --- | ---: | ---: | --- |
| 一般组合 | 5% | 10% | 默认使用；包括借款资产不受同类限制的共享市场 |
| 同锚定／同底层的受限组合 | 1% | 3% | 当前机制限定组合，且已有资产／机制映射明确同一计价锚或底层，例如已映射的 LST／底层资产组合；记录相对价格风险假设，不仅凭符号或 E-mode 名称选择 |

上述幅度是 `lending-light-v2` 自定的初步压力阈值，不是 Aave、Euler、Compound 的统一推荐值，也不是某时间窗口的统计置信区间。同锚定不代表实际永不脱锚，采用较小幅度也不证明风险更低。缺少同类依据时直接使用一般组合，不为寻找价格历史或相关系数扩大采集。

阈值的数学含义是预留明确的相对价格余量：5%／10% 开仓缓冲分别要求 `H₀≥1/0.95≈1.052632`、`H₀≥1/0.90≈1.111111`；1%／3% 分别要求 `H₀≥1/0.99≈1.010101`、`H₀≥1/0.97≈1.030928`。同时还要求清算奖励后的 `M` 覆盖相同幅度。这样形成可解释的初筛规则，不把幅度选择包装为已经完成波动率校准。

一个配置允许多种组合时，按已知用途选择覆盖它们的最保守适用类别；不必枚举真实账户。只对合约限制的特定组合单列同类情景。

#### 2.4 评分

先检查确定的参数冲突，再按未经显示舍入的数值判断：

| 条件 | C2／高杠杆 C6 分数 | 含义 |
| --- | ---: | --- |
| 违反适用机制的参数关系，或 `B_buf < 0` | 0 | 参数冲突或清算线处计入奖励已不能账面覆盖；只作用于对应资产／组合，不表述为已发生损失 |
| 参数合法且 `0 ≤ B_buf < d₁` | 40 | 正缓冲不足或零缓冲，未通过本版温和情景；属于配置预警，不等同于参数失效 |
| `d₁ ≤ B_buf < d₂` | 60 | 通过温和冲击，但较强冲击下至少一个缓冲不足 |
| `B_buf ≥ d₂` | 100 | 通过两档已声明情景，不表示任何冲击下都安全 |

单 LLTV 用 `M` 进入同表。两项都不适用时为 N/A；必要字段未取得时为 U。`b=λ` 在允许此配置的双阈值机制中不称为非法，但会因 `D_open=0` 未通过本版压力条件。

| ---: | ---: | ---: | --- | ---: | ---: | ---: |
| 60% | 75% | 1.05 | 一般 | 20% | 21.25% | 100 |
| 75% | 80% | 1.10 | 一般 | 6.25% | 12% | 60 |
| 78% | 80% | 1.10 | 一般 | 2.50% | 12% | 40 |
| 90% | 93% | 1.05 | 同底层受限组合 | 3.225806% | 2.35% | 60 |

#### 2.5 特殊模式 C6

模式启用后，使用覆盖生效的 `b、λ、β` 及成员方向重新计算；不拿默认参数替模式通过，也不查询用户是否进入模式。关闭的模式披露关闭状态，对其新业务评分 N/A。隔离或单一借款模式检查成员和允许借款方向是否符合已确认机制：一致且约束生效为 100，已确认相冲突为 0，必要状态未知为 U。多个适用条件取最低值。无特殊模式为 N/A。

### 3. C4 上限：公式和运行状态

对合约实际比较的同单位数量 `X` 和有限正上限 `Q`：

```text
ρ = X / Q
剩余额度 = max(Q − X, 0)
```

供应上限用其实际供应口径，绝对借款上限用对应债务；比例型借款上限 `u_cap` 用 `ρ=u_native/u_cap`。借款比例不是美元金额，不能直接与绝对额度混算；不同市场的债务上限按自身计价口径处理。

| ρ | 披露状态 |
| --- | --- |
| `ρ < 90%` | 未接近上限 |
| `90% ≤ ρ < 100%` | 接近上限 |
| `ρ = 100%` | 达到上限 |
| `ρ > 100%` | 当前总量超过配置上限；保留数值和新增操作限制 |

90% 为本版运行提示阈值；100% 为配置边界。超过上限可能来自调低上限或计息，不能仅凭快照认定绕过存入／借款检查。零上限先按代码解释为禁用或无限额，不做除零；无上限明确显示“无限额／未设置”，不填 0 占用或 100 分。

C4 是必采披露项，不再单列经济适配分。公式判断容量占用，不声称“某绝对上限是最优规模”；本版不以新增 DEX 深度、流通量、风险资本调查来凑一个上限安全分。无某种上限本身不判失败；已有替代约束直接列出。

### 4. C5 利率：响应公式与判档

按目标协议代码计算 `r(u)`，其中 `r` 为不含奖励的借款年利率小数，`u` 为该协议原生利用率。原币计息和年化规则随适配器记录；不把 APR、APY、每秒利率或不同协议的斜率字段直接混用。

对具有单一拐点 `u*`、`0<u*<1` 的连续分段线性模型，统一计算：

```text
k_low  = [r(u*) − r(0)] / u*
k_high = [r(1) − r(u*)] / (1 − u*)
Δr_high = r(1) − r(u*)
```

披露 `r(当前u)、r(0)、r(u*)、r(90%)、r(95%)、r(100%)`，重复点合并。上述是从目标代码输出计算的有效斜率，不直接套用 Aave 的斜率参数含义。

| 条件（按顺序判断） | C5 分数 |
| --- | ---: |
| 已确认当前配置使模型在适用区间无法计算，或该类模型出现负利率、负有效斜率／向下跳变，或违反代码规定的连续性 | 0 |
| 有限、非负、连续、单调，`k_high>0` 且 `k_high≥k_low` | 100 |
| 有限、非负、连续、单调，但 `k_high=0` 或 `0≤k_high<k_low` | 60 |

100 表示在本版检查下高利用率区间保留不弱于低区间的价格响应，60 表示响应较弱或平坦。该政策只检查形状与响应，不规定统一最低 APR，不把极高利率或更陡曲线额外加分，不预测借款人一定还款。

无拐点的连续利用率响应模型，在当前模型状态固定的条件下，用 `[0,80%]`、`[80%,100%]` 的有效斜率进入同表，并按已知代码检查区间内单调性／定义域；时间自适应模型注明冻结了哪些状态。代码允许拐点为 0 或 1 时，按实际分支化简后进入无内部拐点的规则，不对零区间相除。合法阶梯定价等非连续机制按事先记录的等价响应规则适配，不把设计允许的跳变当配置错误。固定利率、到期定价等本来不依赖利用率响应的机制，C5 响应评分 N/A、当前利率仍披露。采集请求失败不是模型算不出来，记 U。

### 5. C7 操作配置：范围澄清

读取协议级和已有市场／资产级开关、冻结或紧急状态，结合代码说明它们是否阻断还款、提款、清算；若代码存在特殊名单，记录机制及已有配置的作用范围，不因此遍历账户。正常的抵押检查、还款前提、排队或仅停止新增借款不自动扣分。

| 当前自身配置效果 | C7 分数 |
| --- | ---: |
| 所评估的必要操作入口未被异常限制 | 100 |
| 已确认必要操作部分受限，同一受影响范围仍有有效的部分完成路径 | 60 |
| 已确认对应必要操作完全被阻断且无有效替代 | 0 |
| 必要开关或机制信息缺失 | U |
| 无该操作或机制 | N/A |

这里评价协议配置，未做个人提款模拟不是缺口。现金余额归第三部分，预言机故障处理归第四部分。已确认同一权限配置造成永久失能时，权限项记 0，C7 引用该结果，避免对同一根因重复计分。

### 6. 范围内汇总、未知与动态更新

先评价具体资产／模式；局部最低分不直接替代协议模块分。

```text
s_default(i) = min(该资产适用的 C1、C2、C5、C7)
s_mode(e) = min(该方向适用的 C1、C6、C5、C7)
s_config(i) = min(s_default(i), 该抵押资产所有已启用模式的 s_mode)
V_i = 计息供应债权原币数量 × 同一快照已有账面报价
w_i = V_i / ΣV_i
S_config = Σ(w_i × s_config(i))
S_oracle = Σ(w_i × s_oracle(i))
S_onchain = min(S_permission, S_config, S_oracle)
```

- 每个资产只占一个权重，不把 E-mode 作为额外资产重复计数。采用该抵押资产已开放配置的最弱分，是“允许配置”的保守汇总，**不是断言全部存款正在使用该模式**；无需调查用户实际模式占用。
- 供应债权口径扣除虚拟协议金库份额；不把现金与借款相加重复计权。沿用当前已采价格及时间标签，明确为账面权重、非交易时可成交估值；不新增价格请求。报价为零／负数或缺失、余额为负、分母为零时不能默默剔除或改用等权，应标出权重缺口。零供应且确无金额时权重为零，局部状态仍列出。
- 默认配置加权值可作辅助披露；用于协议模块分的口径必须明确包含启用模式。不得按账户使用量做未经采集的推断。
- 例：占供应金额 1% 的资产从 100 降到 40，其余不变，则配置模块降低 0.6 分；不会变成 40 或 0。局部 0 必须显著列出对应对象、金额占比和原因。
- 全协议暂停等已确认共同失效按真实作用范围纳入所有受影响资产；若覆盖整个声明范围，配置分自然为 0。不得仅因“共享市场”就猜测局部问题已传染全部资金，也不声称本加权值模拟了传染损失。
- 权限对共享合约的完整升级／控制路径仍取最低分；局部权限仅列其作用范围，不无依据升级为全局权限。NAVI 的两条升级路径属于本声明范围的共享控制。
- C3、C4、资金比例、选配及暂不开展项不参与最低分，不记成 100。C6 替代对应模式的 C2，不重复扣分。N/A 排除，空适用集合不补满分。
- 任一适用评分输入为 U 时保留范围及已知上下界，不剔除后发布确定模块分；权重缺口同理。正常 N/A、未启用选配和范围外项目不产生 U。全局已确认 0 可以发布 0，同时保留未知说明。
- 计算保留完整精度；页面显示一位小数，整数可省略小数。JSON、报告、页面的总分、分项、权重和版本必须来自同一结果。

该供应权重和分档是本版明确的初步评级政策，不能称为损失概率或经外部机构校准的模型。新增资产不能以“多一项满分”稀释风险；只有真实供应金额变化才改变权重。v0.9 历史结果原样保留，不把规则修正造成的分差描述成协议安全改善。

## 第三部分：市场资金状态（v0.3）

### 1. 必采范围

只读取既定市场、资产和直接承载资金的地址／对象；记录池、金库及已经映射的直接管理对象，区分同一份资产的余额和债权，避免重复加总。不追踪整个链、不遍历借款人、不推断最终受益人。

| 数据 | 必采口径 |
| --- | --- |
| 资金位置 | 合约／对象地址或 ID、owner、资产类型、余额字段及资金用途；Sui 的 `Balance<T>`、池内字段和对象持仓均可作为证据，不限于地址下的 `Coin<T>` |
| `S` 供应债权 | 当前应归属出借人的债权，按代码计息；协议总供应含虚拟金库份额时，原值与扣除后的债权分别列示 |
| `B` 借款 | 当前市场／储备借款，按代码计息 |
| `C` 现金 | 直接支持上述债权的池内现金；协议费用金库、已有明确用途不同的资产单列，不重复相加 |
| 其他已有资金对象 | 既有管理器持仓、非现金或待回收余额及直接状态；只记录已经映射的对象，不研究追偿链 |
| 原生利用率 | 按该协议的分子、分母、索引及舍入规则计算 |

### 2. 公式与披露

```text
现金覆盖 = C / S
借款／供应比 = B / S
现金／借款比 = C / B
某资产的供应或借款占比 = 该资产同口径价值 / 范围内同类总价值
```

最后一项是资产构成，不是地址集中度。协议原生利用率优先展示，`B/S` 仅在口径相同时才称原生利用率。上述比例不机械换算安全分。

分母为零时输出不适用及原始数量；`C=0、S>0` 显示现金耗尽，不据此判定资不抵债。暂停时现金仍是账面余额，另显示操作受限。不同币种先分别展示，再按注明来源和时点的现成价格汇总；不假定币种可以无成本互换。当前价格未核验时保留原币及明确标记的账面估值，不影响无价格依赖的参数公式。

如使用 `L/O`，必须写明 `L` 是总供应还是池内现金、`O` 是借款；两者均不是“有债务账户抵押率”，不能由该比值推出无坏账。资金比率是宏观流动性信息，不用相互抵消不同账户可能存在的缺口。

### 3. 本版不开展的结果

全市场借款人抵押总额、HF 分布、Top N、待清算总额、坏账总额全部标“暂不开展”，不再附逐账户采集任务或缺口补采计划。既有样本可作为历史材料留存，不能外推为市场总量、无坏账结论或本轮新采结果。

选配仅限既定接口已有的非账户级汇总和价格展示，不自动启用上述暂不开展项目。没有对应字段不填零，也不称技术上无法计算。

每项附快照、对象、原始值、单位、计算式及计价信息。本模块不生成数值分，不阻断其他模块的独立结果。

## 第四部分：预言机来源与配置韧性（v0.4）

### 1. 评估对象与必采项

根据当前实际来源、有效冗余和异常处理配置形成结果，不以“必须另找一份市场价格”作为评分前提。模块名称明确为配置韧性，不能把此分数描述为已经逐价核验实时市场报价。

| 必采项 | 最小内容 |
| --- | --- |
| 来源及绑定 | 借贷逻辑读取的最终价格入口、资产／feed 映射、单位、上游类型及明确的直接喂价入口 |
| 实际主备配置 | primary／secondary 或等价配置、启用标志、是否进入实际选择路径、是否同一来源／同一底层 feed |
| 异常规则 | 暂停状态、正值／有效性要求、过期限制、价差检查（若机制使用）、切换／停更／拒绝业务的条件 |
| 共同路径 | 是否汇入同一最终合约、是否共用适配器；谁能换源／禁用／绕过写价引用权限模块 |

同一个来源的两个接口、两个节点、两个配置槽不算两个来源；同一供应商的同一底层 feed 只计一次。一个聚合预言机内部声称有多个报价者，不据此当成协议已经接入多个独立可切换来源。现有绑定和代码足以判断时直接出结果，不调查源背后的组织。

### 2. 评分项

#### O1：来源绑定与当前启用状态

| 条件 | 分数 |
| --- | ---: |
| 至少一个当前启用的有效来源，最终读取路径、资产、单位及映射一致 | 100 |
| 已确认不存在可用的配置路径，或存在资产／单位错误，或全部必要更新入口被关闭且没有有效替代 | 0 |
| 关键绑定或启用状态未取得 | U |

“可用的配置路径”是代码与当前开关意义，不额外要求对每个市场执行交易或证明最新外部服务请求成功。暂停覆盖哪些路径须按代码判断；存在直接 Feeder 写价时，不能只看普通更新函数暂停就断言全部写价停止。

#### O2：有效来源冗余

令 `N_eff` 为在当前配置下，能够参与正常价格选择、交叉校验或自动替代的不同上游来源数。仅保留在配置表、未被实际选用的来源不计数。

| 条件 | 分数 | 输出 |
| --- | ---: | --- |
| `N_eff ≥ 2` | 100 | 有效多源；列出各自用途，不意味着没有共同最终合约或管理路径 |
| `N_eff = 1` | 60 | 有效单源；这是冗余较弱，不是当前报价错误 |
| `N_eff = 0` | 0 | 无有效来源路径；与 O1 同根因时引用，不重复扣减 |
| 无法确认来源是否真的参与路径 | U | 列明已知绑定，不把两个名称自动算双源 |

例如 secondary 与 primary 相同、备用被禁用、代码明确不使用备用，则按单源；有备用表项但没有自动选用路径也不按可切换冗余。通过同一控制者管理不同供应商不抹掉上游来源差异；控制集中另归权限。

#### O3：异常拒绝与切换约束

检查本机制适用的输入无效、过期、价差异常和主源调用失败的分支；依据已映射代码及当前限制即可，不要求故障注入、Gas 测试或个人操作模拟。

| 条件（先判断 0，再判断 60，其余满足条件为 100） | 分数 |
| --- | ---: |
| 已确认普通取价路径会将本机制定义的无效／超过有效期输入作为有效价格继续使用，且没有生效的拒绝或替代 | 0 |
| 无效输入最终被拒绝或停止更新，但当前配置的多源路径存在明确切换限制，例如主源报错先终止调用、主源禁用即返回而未尝试有效备源；或适用的校验开关未启用但尚无证据达到上一行 | 60 |
| 适用的校验和拒绝逻辑生效；单源异常时安全停止，多源在其配置覆盖的主源过期／无效／调用失败情形可使用有效备源，否则安全停止 | 100 |
| 必要代码关系或配置缺失 | U |

“停止更新”须结合最终读取端：旧价格能否在有效期后仍被接受要看消费端检查，不能只看更新函数 return。若报错会回滚整个交易且使用端拒绝无效旧值，记录可用性限制，不将其误判为使用错误价格。固定价格和链上兑换率按自身有效性机制判断，不机械要求时间戳或价差检查。

直接 Feeder／管理员可覆盖最终价格属于权限事实，必须披露；不因其存在把正常自动路径一律判为无校验，也不把这条特权路径虚构成独立价格源。若它是唯一正常来源，按该路径真实的输入验证和失效约束评价 O3。

### 3. 公式与展示

```text
S_oracle_config(m, feed) = min(O1, O2, O3)
```

同一资产依赖的必要 feed 仍取最低分；跨资产按第二部分第 6 节同一供应金额权重汇总。局部失效、有效单源／多源数量、受影响资产及供应占比单独展示；不能用加权分隐藏局部 0。U、N/A、确定 0 和空集合的规则与第二部分相同。该分只反映声明范围内的来源与配置韧性。

已有 NAVI 配置的适配例：35 个主市场来源中 19 个为有效 Pyth＋Supra，16 个实际单源；NS／WAL 主备同为 Pyth，按 `N_eff=1`。这只演示 O2 的 100／60 判定，不直接当作所有 feed 的模块总分；最终仍结合 O1／O3。来源：2026-11-16 检查点 345866572 的已采配置，不是本标准更新时重新扫描的结果。

### 4. 价格值与外部信息：选配披露

已有、已启用的接口直接提供价格和时间时，可以披露原始价格、更新时间和协议判断。对同币种、同单位、同口径且时间可比的现成参考价，可选计算：

```text
δ = abs(协议价格 / 参考价格 − 1)
```

不强制找第二价格源，不使用该选配项决定基础 O1—O3 是否完整，也不沿用旧版 1%／5%／15% 偏离表或来源可信性 40 分封顶作为本版必评分规则。若选配发现确凿的错误绑定或失效输入被接受，仍将该事实归入对应必评分项，不能因证据来自选配而忽略。

按需更新机制中，存储时间较旧不能单独证明预言机故障；应记录其交易时更新及消费端过期拒绝机制。这里不要求逐账户、逐交易复现。美元估值使用的价格与时间照实标注，不把历史缓存价格称为实时可成交价格。[Pyth 按需更新机制](https://www.pyth.network/blog/pyth-a-new-model-to-the-price-oracle)

桥、发行方、底层赎回可用性及来源组织背景不开展额外调查。已有的最终合约、共享组件和管理路径作为链上配置事实展示，不要求建立穷尽依赖图。

### 5. 更新触发与规则迁移

每轮读取既定对象的来源／启用／阈值配置；主备、更换适配器、暂停、升级或校验逻辑改变时，重算受影响项。源码映射仍适用时复用，不每轮重新审计。

旧版“预言机与依赖当前健康度”与本版“预言机配置韧性”不是同一个评分对象；升级时显示版本与口径变化，不直接计算跨版本涨跌。配置模块因 C3／C4 移出评分和新增压力判档，也不与旧版本直接作分差比较。未启用的价格披露项不记 U，已确认无源／弱冗余／切换限制仍照常出分。
