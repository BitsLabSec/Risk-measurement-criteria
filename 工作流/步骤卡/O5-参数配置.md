# O5 参数配置

## 这一步在做什么

逐行过一遍业务对应专项的**第 3 节「参数配置」表**。每一行在每个市场上登记一条检查，回答几个是非题；有公式的行，把公式的输入告诉脚本，由脚本计算并定档。

O6（资金与外部依赖）用完全相同的格式，只是换成专项第 4 节的表。

## 开始前你需要

- `O4-permissions.json` 已通过检查
- 业务对应的专项文件第 3 节

## 产出

`O5-config.json`：专项第 3 节的每一行，在每个市场上各一条（共用的写一条 `ALL`）。

## 操作步骤

1. **逐行列检查。** 打开专项第 3 节的表，每一行（例如 `L-C2.1`）登记一条：
   - 这一行的读数对所有市场相同（例如全局开关、共用的利率模型）：一条，`market_id` 写 `ALL`；
   - 每个市场的读数不同（例如每个储备各自的 LTV）：每个市场一条。

   同一个编号不能既写 `ALL` 又写具体市场。

   专项有「各业务适用的检查项」表时（例如 DEX 第 0.1 节），只登记表里为这种业务列出的编号；其他编号不登记，登记了检查会报错。
2. **有公式的行：填输入。** [公式表](../交付物字段表.md#六由脚本计算的公式)里列出的编号由脚本计算。`q_hard` 和 `q_warn` 都填 `by_formula`，在 `inputs` 里按公式表中的输入名逐个填写：
   - 来自读数：`reading_id` 写 RD 编号，`constant` 写 `无`；
   - 来自代码常量或你的判断（例如 yes／no）：`reading_id` 写 `无`，`constant` 写值，`note` 写依据；
   - `divide_by`：把原始读数换成公式要的单位要除以多少。比如读数是 `8000`、单位 bps，公式要小数 `0.8`，就填 `10000`。
3. **没有公式的行：回答是非题。** 按下面「怎么判断」的顺序回答。
4. **`reading_ids`**：列出这个判断用到的全部读数，包括公式输入用到的。
5. **`reason`**：一句话写清依据。凡是答了 `yes` 的问题，都要在这里说明。

## 怎么判断

**每一条都按这个顺序回答，前面的成立就不用往下看：**

| 顺序 | 字段 | 问题 | 答 yes 的结果 |
| ---: | --- | --- | --- |
| 1 | `refers_to` | 这个事实已在别的检查里计分了吗？（例如价格源错绑已在 C1 计分，D1 只是引用） | 填那个 CK 编号，本条不计分 |
| 2 | `q_not_applicable` | 这个机制在本市场确认不存在吗？ | N/A |
| 3 | `q_aggregate_not_stored` | 需要的汇总值协议没存，只能扫历史或枚举用户才能得到吗？ | 只披露，不计分 |
| 4 | `q_hard` | 违反这一行的「硬约束」，或必要操作完全受阻且没有替代吗？ | 0 分 |
| 5 | `q_warn` | 触发这一行的「警戒阈值」，或必要操作部分受阻但仍有可用路径吗？ | 60 分 |
| 6 | `q_weakened` | 已证实某个次要保护、备用路径或便捷入口失效，但主路径仍能完整承接吗？（这一行「90 的例子」那一类） | 90 分 |
| — | 都不是 | | 100 分 |

- 专项表里写「只披露」、没有硬约束的行，脚本自动按披露处理，照常登记即可。
- 「停止新增、允许存量退出」不算受阻。机制本身规定的等待（例如解锁期）也不算受阻。
- `q_hard`、`q_warn` 只能依据专项表里写的硬约束和警戒。**表里没写的阈值，不要自己定。**

**由脚本计算的编号**：哪些编号、要填哪些输入、怎么定档，统一见[交付物字段表 · 由脚本计算的公式](../交付物字段表.md#六由脚本计算的公式)。输入名必须和表里一模一样。

**C2 类检查的提示：**

- **直接填协议存的原始参数，不要自己推算。** 例如清算奖励填 `bonus`（不要自己算 1 + 奖励），利率曲线填基础利率和两段斜率（不要自己算拐点利率）。公式支持哪些写法，见[公式表](../交付物字段表.md#六由脚本计算的公式)。
- **L-C2.1、L-C2.3 按「抵押 × 借款 × 模式」组合检查。** 一个市场有多个组合时（例如它参与了好几个 E-mode 组合），每个组合一组输入，用 `group` 写上组名（例如 `emode-6`），全部填进同一条检查。脚本逐组计算，取最差的结果。**不要自己挑最差的那组。**
- **LTV 为 0 的资产不能作抵押**，L-C2.1 没有可检查的组合：填 `q_not_applicable: yes`。
- **「同底层」要人工复核。** `same_underlying` 填 `yes` 时，`note` 写清理由，例如「两边都是美元稳定币」「LST 与其底层 SUI」。这一项会在人工复核时重点看。

- L-C2.4、CD-C2.2 要判断「主流资产」：按[通用标准第 4.3 节](../../onchain/链上安全评估标准.md#43-主流资产的口径)查，`reason` 写查询日期和来源。
- C3 类（暂停、冻结开关）：把每个开关对应到 O1 登记的必要操作。全部必要操作都被挡住、没有替代入口 → `q_hard: yes`；部分被挡住 → `q_warn: yes`。

## 填写示例

```json
{
  "checks": [
    {"id": "CK01", "business_id": "BZ01", "market_id": "MK01", "check_id": "L-C2.1",
     "inputs": [
       {"name": "b", "reading_id": "RD01", "constant": "无", "divide_by": 1e27, "note": "ray 精度，lending.move:88"},
       {"name": "lambda", "reading_id": "RD02", "constant": "无", "divide_by": 1e27, "note": "同上"},
       {"name": "beta", "reading_id": "RD03", "constant": "无", "divide_by": 1e27, "note": "1 + 清算奖励，logic.move:310"},
       {"name": "same_underlying", "reading_id": "无", "constant": "no", "divide_by": 1, "note": "SUI 抵押借 USDC，不同底层"}],
     "q_not_applicable": "no", "q_aggregate_not_stored": "no",
     "q_hard": "by_formula", "q_warn": "by_formula", "q_weakened": "no", "refers_to": "无",
     "reading_ids": ["RD01", "RD02", "RD03"], "reason": "按 SUI 储备的 LTV、清算线、清算奖励计算",
     "evidence": ["sources/logic.move:300-330"]},
    {"id": "CK02", "business_id": "BZ01", "market_id": "ALL", "check_id": "L-C3.1",
     "inputs": [], "q_not_applicable": "no", "q_aggregate_not_stored": "no",
     "q_hard": "no", "q_warn": "no", "q_weakened": "no", "refers_to": "无",
     "reading_ids": ["RD09"], "reason": "全局暂停开关为 false，各储备均未冻结",
     "evidence": ["cmd:sui GraphQL object(address:0x…) @ checkpoint 182733001"]}
  ]
}
```

## 完成检查

```bash
python3 工作流/scripts/bitsscore.py validate 评估记录/<项目>/<评估ID> --step O5
```

检查会确认：专项第 3 节的每一行在每个市场都有登记；有公式的行输入齐全；没有公式的行没有填 `by_formula`。

## 常见错误

- 自己算出缓冲值，再填 `q_warn: yes`。有公式的行一律填 `by_formula`，让脚本算。
- 自己推算公式的中间值（例如 1 + 奖励、拐点利率），作为常量填进去。应该填原始读数，换用公式的另一种写法。
- 有多个组合时只填了自己认为最差的一组。
- 单位没换算，`divide_by` 填了 1。例如 bps 要填 10000，1e27 精度要填 1e27。
- 「能改参数」当成配置问题。能不能改属于权限（O4）；这里只看**当前值**。

## 卡住了怎么办

公式要用的值读不到：在 O3 里把那条读数标成 `unreadable`，脚本会把这个检查记为评估未完成。不要自己估一个值。
