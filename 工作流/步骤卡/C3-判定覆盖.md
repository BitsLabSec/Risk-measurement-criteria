# C3 判定覆盖

## 这一步在做什么

脚本会把每份报告的受审版本和生产版本逐行比对，列出所有改动。你要对每一处改动回答一个问题：**行为有没有变？**

脚本再根据你的答案判定每一行生产代码是否被覆盖。判定规则：

- 这一行和受审版本相同（只改了格式、位置也算相同），**并且**它用到的函数和字段的行为都没变 → **覆盖**；
- 其他情况 → **未覆盖**。

## 开始前你需要

- `C2-reports.json` 已通过检查

## 产出

- `C3-semantic-changes.json`：脚本生成改动清单，你填其中三个字段
- `C3-coverage.json`：脚本生成

## 操作步骤

1. 第一次运行：
   ```bash
   python3 工作流/scripts/bitsscore.py coverage 评估记录/<项目>/<评估ID>
   ```
   如果有改动，脚本会生成 `C3-semantic-changes.json`，然后停下来，提示你去填。
2. 打开 `C3-semantic-changes.json`。每一处改动，脚本已经填好了：
   - 改动位置（`audited_lines`、`production_lines`）；
   - 所在函数（`enclosing_symbol`）；
   - 改动预览（`diff_preview`，`-` 开头的是旧代码，`+` 开头的是新代码）。

   你需要填写下面三个字段：
   - `semantic_change`：`yes` 或 `no`，按下表判断；
   - `identifiers`：填 `yes` 时，写出**行为变了的函数名或结构体字段名**，通常就是 `enclosing_symbol` 里的那个名字；如果是结构体增删了字段，就写字段名。填 `no` 时写 `[]`；
   - `reason`：一句话理由。
3. 预览看不全时，自己看完整的 diff：
   ```bash
   git -C <repo_path> diff <受审commit> <生产commit> -- <文件路径>
   ```
4. 填完后再运行一次 `coverage`，直到脚本输出各档的覆盖统计。

## 怎么判断 `semantic_change`

| 改动内容 | 填 |
| --- | --- |
| 只改注释、空格、换行、缩进 | `no` |
| 只改日志或事件里的文字或字段 | `no` |
| 只改错误码的数字 | `no` |
| 只改局部变量名，逻辑完全一样 | `no` |
| 只多出或少了一个闭合括号，是因为周围代码移动了位置 | `no` |
| 改了计算、条件、常量的值 | `yes` |
| 增加或删除了检查（`assert`、`require`） | `yes` |
| 改了调用了哪个函数，或者调用时传了什么参数 | `yes` |
| 新增了函数 | `yes`（`identifiers` 写新函数名） |
| 删除了函数 | `yes`（`identifiers` 写被删的函数名） |
| 结构体增加、删除或修改了字段 | `yes`（`identifiers` 写字段名） |
| **拿不准** | `yes` |

**拿不准时一律填 `yes`。** 填 `yes` 只会让更多行被判为未覆盖，不会高估分数。

## 填写示例

```json
{
  "change_id": "CH-1a5e976c30",
  "report_id": "AR01",
  "production_path": "sources/pool.move",
  "audited_lines": "20-20",
  "production_lines": "20-20",
  "enclosing_symbol": "fun fee",
  "diff_preview": "- fun fee(x: u64): u64 { x / 100 } / + fun fee(x: u64): u64 { x / 50 }",
  "semantic_change": "yes",
  "identifiers": ["fee"],
  "reason": "手续费从 1% 改成 2%"
}
```

填了 `identifiers: ["fee"]` 后，生产代码中没有改动、但调用了 `fee` 的行（例如 `fee(amt)`），也会被判为未覆盖。

## 完成检查

`coverage` 输出类似下面的内容，并写入了 `C3-coverage.json`：

```
核心档：20 行，覆盖 13（直接 0，沿用 13），未覆盖原因 {'dependency-changed': 1, 'changed': 6}
```

## 未覆盖原因的含义

| 原因 | 意思 |
| --- | --- |
| `no-report` | 没有任何报告的范围包含这个文件 |
| `out-of-scope` | 文件在报告范围内，但这一行在报告排除的部分或只审部分之外 |
| `changed` | 这一行相对受审版本改过 |
| `dependency-changed` | 这一行没改，但它用到的函数或字段的行为变了 |
| `no-diff` | 拿不到受审版本，没法比对 |

## 常见错误

- 为了让分数高一点，把行为改动填成 `no`。
- 填了 `yes`，`identifiers` 却留空。脚本会拒绝继续。

## 卡住了怎么办

改动太多（例如几百处）时，也要逐条判断，不能批量填。实在做不完的，停下来报告进度，交给人决定。
