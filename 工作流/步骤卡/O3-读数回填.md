# O3 读数回填

## 这一步在做什么

把 O2 清单里每个字段的值，**在 O1 的快照上**读出来，原样填进 `O3-readings.json`。

只照抄，不换算单位，不做计算。单位换算在 O5、O6 里通过 `divide_by` 告诉脚本，计算由脚本完成。

## 开始前你需要

- `O2-targets.json` 已通过检查

## 产出

`O3-readings.json`：O2 里每个目标的每个字段一条读数。

## 拿不到数据时按这个顺序试

**任何情况下都不扫历史交易、不枚举全部用户。** 按顺序试，前面的走通了就不用往下：

| 顺序 | 方法 | `method` | 什么时候用 |
| ---: | --- | --- | --- |
| 1 | 查询函数 | `getter` | 合约提供了读取这个值的函数 |
| 2 | 读对象字段（Sui） | `object_field`／`dynamic_field` | Sui 对象的全部字段都是公开的，没有 getter 也能直接读。表（Table）里的条目用 `dynamic_field`：表不是对象，要用 `table` 命令一次读出全部条目 |
| 2′ | 按类型找对象（Sui） | `type_query` | **只用于找权限凭证**：不知道 Cap 的对象 ID 时，按 Cap 的类型在快照上查出全部实例和持有人。类型要写定义它的那个包的 ID |
| 3 | 读存储槽（EVM） | `storage_slot` | 变量没有 getter（私有变量）。用已核验源码的存储布局算出槽位：`forge inspect <合约> storage-layout`，mapping 槽位为 `keccak256(key . slot)`。`method_detail` 写槽位和计算依据 |
| 4 | 代码常量 | `code_constant` | 值写死在代码里。`evidence` 写源码位置 |
| 5 | 定向读一笔交易 | `targeted_tx` | **只用于 Sui 原生多签**：成员和门限不在链上状态里。用 `sui_read.py <目录> msig <地址>` 读这个地址发出的最近一笔交易，从签名中解出成员、权重、门限，并用公钥推回多签地址核对。`method_detail` 写交易 digest |
| — | 都不行 | — | 不要估、不要猜。`status` 填 `unreadable`，在 `gaps.json` 登记 |

其他几种情况：

- **协议根本没存这个汇总值**（例如所有待赎回总额，只能逐笔加总）：不用读。O5／O6 里对应检查填 `q_aggregate_not_stored: yes`，只披露。
- **值读到了，但看不懂单位或含义**：不要猜。在 `gaps.json` 登记（`blocks_denominator` 填 `true`），交人处理。
- **Sui 多签从来没发过交易**：解不出成员。路径按单签登记，并在 `gaps.json` 登记（不阻断）。

## 操作步骤

1. **用采集工具或脚本读取时**：把结果转成本文件的格式，`source` 填 `collector`。工具的内部格式和本工作流无关，只要最后的读数符合这里的字段要求。
2. **手工读取时**：一定要指定快照，不要读「最新」状态。
   ```bash
   # Sui：用工作流自带的读取工具，原始响应自动存进 证据/raw/，并打印证据引用
   python3 工作流/scripts/sui_read.py <目录> object <对象ID> --at <检查点> --name <名字>
   python3 工作流/scripts/sui_read.py <目录> table <表ID> --at <检查点> --name <名字>
   python3 工作流/scripts/sui_read.py <目录> by-type <包ID>::<模块>::<Cap 类型> --at <检查点>
   python3 工作流/scripts/sui_read.py <目录> msig <多签地址>
   # EVM：在指定区块调用
   cast call <地址> "<函数签名>" --block <区块号> --rpc-url <RPC>
   # EVM：在指定区块读存储槽
   cast storage <地址> <槽位> --block <区块号> --rpc-url <RPC>
   ```
3. 每个字段填一条：
   - `value`：原样照抄，大数字按字符串写，例如 `"750000000000000000000000000"`；
   - `unit`：原始单位，例如 `1e27`、`bps`、`秒`、`地址`；
   - `method`、`method_detail`：按上面的顺序表填；
   - `at_snapshot`：在快照上读的填 `exact`；节点不支持按快照读、在快照前后各读一次且一致的填 `bracketed`；代码常量和定向交易填 `not_applicable`；
   - `evidence`：只能是五种格式之一（见[工作流 README](../README.md#填写格式约定)），例如 `cmd:cast call 0x… "ltv()" --block 21000000`。
4. **读不到时**：`status` 填 `unreadable`，`value` 填 `无`，并在 `gaps.json` 登记（`step` 填 `O3`；必需对象 `blocks_denominator` 填 `true`）。

## 怎么判断

| 情况 | 怎么填 |
| --- | --- |
| 值是代码里写死的常量 | `method` 填 `code_constant`，`source` 填 `source_code`，`evidence` 写源码位置 `路径:起-止` |
| 浏览器上看到的值 | `source` 填 `explorer`，`evidence` 写链接；能用 RPC 复核的尽量复核 |
| 读到的是多签成员列表 | 每个成员地址一条读数，或者一条读数里写成逗号分隔的地址列表 |
| 只能读到最新值、无法指定快照 | 在快照前后各读一次，一致就填 `at_snapshot: bracketed`；不一致就换支持历史状态的节点 |

## 填写示例

```json
{
  "readings": [
    {"id": "RD01", "target_id": "OT02", "field": "ltv", "status": "read",
     "value": "750000000000000000000000000", "unit": "1e27", "chain_id": "sui:mainnet",
     "method": "object_field", "method_detail": "content.fields.ltv",
     "at_snapshot": "exact", "source": "rpc", "evidence": "file:证据/raw/reserves.json"}
  ]
}
```

## 完成检查

```bash
python3 工作流/scripts/bitsscore.py validate 评估记录/<项目>/<评估ID> --step O3
```

## 常见错误

- 把 `8000 bps` 改写成 `0.8`。这里只照抄，换算留到 O5、O6。
- 读的是最新状态，不是快照状态。

## 卡住了怎么办

RPC 报错：重试，或换一个数据源。仍然读不到，按第 4 步处理。
