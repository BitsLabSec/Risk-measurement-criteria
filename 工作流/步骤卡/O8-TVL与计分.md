# O8 TVL 与计分

## 这一步在做什么

填写每个业务和每个市场的 TVL，然后运行脚本，算出业务分和项目链上分，生成交付物。

TVL 用来给多个市场和多个业务加权。分数全部由脚本计算。

## 开始前你需要

- `O7-fatal.json` 已通过检查
- 如果有致命项候选，人已经确认完（`human_decision` 不是 `pending`），否则结果会是「待人工确认」

## 产出

- 你填：`O8-tvl.json`
- 脚本生成：`O8-score.json`、`O8-score.md`

## 操作步骤

1. **算 TVL。** 用快照时的读数：业务托管的用户资产数量 × 美元价格。
   - 每个业务一条；O1 里的每个市场也各一条；
   - 不托管资产的业务（例如纯路由），`tvl_usd` 填 `0`，脚本会按 5% 的下限给权重；
   - **选口径**：`tvl_source` 从下面三种里选一种，**同一次评估的所有业务用同一种**，这样权重才可比：

     | 口径 | 什么时候用 | 每条要填 |
     | --- | --- | --- |
     | `defillama` | DefiLlama 有这个协议、并且能按业务拆开 | `evidence` 写页面链接，`basis` 写取的是哪一项 |
     | `official_dapp` | 官方 dapp 有统计，DefiLlama 拆不开 | `evidence` 写页面链接，`basis` 写取的是哪一项 |
     | `onchain_balances` | 前两种都没有，或口径对不上 | `reading_ids` 列出余额读数，`basis` 写哪些余额乘以哪些价格；顶层 `price_source` 写价格来源 |

   - 市场的 TVL 单独选口径 `market_tvl_source`。DefiLlama 一般拆不到市场，市场通常用 `onchain_balances`；
   - `tvl_time_utc` 写数据的时间，尽量接近快照；
   - 三种都拿不到：`tvl_available` 填 `no`，`tvl_source` 填 `none`，所有业务等权。
2. **运行检查和计分。**
   ```bash
   python3 工作流/scripts/bitsscore.py validate 评估记录/<项目>/<评估ID> --step O8
   python3 工作流/scripts/bitsscore.py onchain-score 评估记录/<项目>/<评估ID>
   ```
3. **生成交付 JSON。** 所有要评的维度都做完后运行：
   ```bash
   python3 工作流/scripts/bitsscore.py export 评估记录/<项目>/<评估ID>
   ```
   它会按 T0 的 `dimensions` 重新计分，生成 `deliverable.json`（前端的数据源），并按[交付格式](../交付格式.md)自检。自检不通过不会写出文件，这是脚本的问题，交给人处理。
4. **看结果状态。**

| 状态 | 意思 | 你要做什么 |
| --- | --- | --- |
| 已评分 | 出分 | 交付 `deliverable.json`（`O8-score.md` 供人阅读） |
| 评估未完成 | 有必需的事实没读到，或有阻断缺口 | 按 `O8-score.md` 里「未完成的原因」补齐，再重新运行。补不齐就照实交付，不发布分数 |
| 待人工确认 | 有致命项候选还没人确认 | 交给人确认 O7，再重新运行 |

## 脚本怎么算（只需了解，不要自己算）

- **权限**：每条路径按最少密钥数和有效延时查表，每类后果取最低，H1／H2／H3 再取最低。另外披露密钥集中度：最少几把密钥就能走通全部路径（不计分）。
- **配置、资金**：每个市场取各检查的最低分，再按市场 TVL 加权。
- **业务分** = 0.4 × 权限 + 0.3 × 配置 + 0.3 × 资金依赖。某个大项为 N/A 或只有引用时，去掉它，剩下的权重重新归一。确认的致命项使业务分记 0。
- **项目分** = 各业务分按 max(TVL 占比, 5%) 归一后加权。

规则依据：[链上安全评估标准](../../onchain/链上安全评估标准.md)第 8 节。

## 交付物

`O8-score.md` 的开头写明每条链的快照和时间戳，以及有效期：权限持有人或门限变更、合约升级、核心参数改动后，结果过期，需要重评。

不要手改 `O8-score.json` 和 `O8-score.md`。觉得结果不对，把情况写进报告，交给人处理。

## 完成检查

`onchain-score` 运行成功，并输出了状态。

## 常见错误

- 用当前价格而不是快照时的价格算 TVL。
- 把 LP 凭证和底层资产各算一次，TVL 重复计算。
