# C6 计分与交付

## 这一步在做什么

运行脚本计算代码安全分，然后交付结果。

## 开始前你需要

- C5 已通过检查

## 产出

- `C6-score.json`：机器可读的结果
- `C6-score.md`：一页结果，给人看

## 操作步骤

1. 运行：
   ```bash
   python3 工作流/scripts/bitsscore.py score 评估记录/<评估ID>
   ```
2. 脚本会依次：
   - 检查 T0 到 C5 的所有文件；
   - 重新统计行数、判定覆盖；
   - 计算覆盖分、加上总体评价、应用封顶；
   - 写出结果。
3. 确认输出的结果是下面四种之一：

| 结果 | 意思 | 交付什么 |
| --- | --- | --- |
| `已评分，XX.XX 分` | 正常 | 整个评估目录 |
| `无法评分` | 部署未确认、源码未核验，或者有阻断分母的缺口 | 整个评估目录。`C6-score.md` 会列出原因，已经核实的部分照常交付 |
| `不适用` | 范围内没有任何有效代码 | 整个评估目录，以及范围依据 |
| `待人工确认` | C5 记录了反常写法线索（B1），还没有人确认是否扣分 | 把 `C6-score.md` 交给人。人在 `C5-overall.json` 里填好 `b1_human_decision` 和 `b1_human_reviewer` 后，再运行一次 `score` |

## 交付清单

交付整个 `评估记录/<评估ID>/` 目录，里面至少包括：

- `T0-task.json`、`P1-baseline.json` 到 `P5-roles-controls.json`、`gaps.json`
- `P6-graph.md`
- `C1-lines.json`、`C2-reports.json`、`C3-semantic-changes.json`、`C3-coverage.json`、`C4-findings.json`、`C5-overall.json`
- `C6-score.json`、`C6-score.md`
- `证据/` 目录（命令输出、截图等）

## 完成检查

- `score` 命令没有报错；
- `C6-score.md` 里的结果、各档覆盖率、封顶和最终分都已生成。

## 常见错误

- 手改 `C6-score.md` 里的分数。分数只能由脚本生成。如果觉得不合理，就在交付说明里写出来，交给人处理。
