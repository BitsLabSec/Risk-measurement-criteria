# P3 业务与模块

## 这一步在做什么

回答两个问题：

1. 用户能用这个协议做哪几件事（**业务**）？
2. 源码由哪些模块组成，每个模块服务于哪些业务？

## 开始前你需要

- `P2-sources.json` 已通过检查，源码已经检出到本地

## 产出

`P3-business-modules.json`：

- `businesses`：每项业务一条
- `modules`：每个源码模块一条，外部依赖也要单独写一条

## 操作步骤

1. **列出所有模块。** 在源码目录运行：
   ```bash
   # Move：列出所有 module 声明
   grep -rn "^module \|^\s*module " <源码目录> --include=*.move
   # Solidity：列出所有 contract、library、interface
   grep -rnE "^\s*(abstract )?(contract|library|interface) " <源码目录> --include=*.sol
   ```
   范围内的每个 module 或 contract 填一条 `modules`。
2. **列出用户入口。**
   ```bash
   # Move：public 和 entry 函数（在 Sui 上，用户可以通过 PTB 直接调用任何 public 函数）
   grep -rnE "public (entry )?fun |entry fun " <源码目录> --include=*.move
   # Solidity：external 和 public 函数
   grep -rnE "function \w+\([^)]*\)[^{;]*(external|public)" <源码目录> --include=*.sol
   ```
   去掉只读函数（Move 中不改状态的 getter；Solidity 中的 `view` 和 `pure`），剩下的就是用户入口。
3. **把入口归成业务。** 按「用户想完成什么事」来分，例如：存款、借款、还款、清算属于「借贷」；兑换、加减流动性属于「现货交易」。`specialty` 从下面的对照表里选。
4. **填模块之间的关系。**
   - `business_ids`：这个模块被哪些业务用到；
   - `calls_module_ids`：它调用了哪些其他模块。用 `grep` 查 `use` 语句（Move）或 `import` 语句（Solidity）。
5. **外部依赖也要列出来**，例如预言机、外部 DEX、Sui framework 中有业务含义的模块。这类模块：`is_external` 填 `true`，`source_id` 和 `file` 都写 `外部`。

## 怎么判断（specialty 对照表）

| 业务特征 | `specialty` |
| --- | --- |
| 存款、借款、还款、清算 | `lending` |
| 用户直接和池子兑换、加减流动性 | `dex_amm` |
| 路由到多个池子或场所完成兑换 | `dex_aggregator` |
| 做市商报价，用户按报价成交 | `dex_rfq` |
| 存入资产换份额，由策略管理资产 | `yield_vault` |
| 加杠杆开仓、减仓 | `margin` |
| 限价单 | `order_limit` |
| 定投（DCA） | `order_dca` |
| 质押 LP 领奖励 | `farm` |
| 锁仓换凭证，到期赎回，分红 | `staking_redemption` |
| 新币发行认购、领取、退款 | `launchpad` |
| 永久封存 LP 后领手续费 | `lp_burn` |
| 固定额度的补偿分期领取 | `compensation` |
| 永续合约 | `perpetuals` |
| 代币本身的发行和转账 | `token` |
| 都不是 | `other`（同时在 `gaps.json` 里说明，交给人决定） |

## 填写示例

```json
{
  "businesses": [{
    "id": "BZ01", "name": "借贷", "specialty": "lending",
    "user_entries": ["incentive_v3::entry_borrow_v2", "incentive_v3::entry_repay"],
    "assets_or_state": ["各资产池余额", "用户债务", "用户存款"]
  }],
  "modules": [
    {"id": "M01", "name": "lending_core::incentive_v3", "source_id": "S01", "file": "lending_core/sources/incentive_v3.move",
     "is_external": false, "business_ids": ["BZ01"], "purpose": "用户入口，转发到 lending", "calls_module_ids": ["M02"]},
    {"id": "M06", "name": "oracle::PriceOracle", "source_id": "外部", "file": "外部",
     "is_external": true, "business_ids": ["BZ01"], "purpose": "借款估值用的价格", "calls_module_ids": []}
  ]
}
```

## 完成检查

```bash
python3 工作流/scripts/bitsscore.py validate 评估记录/<评估ID> --step P3
```

## 常见错误

- 按文件分业务。业务要按「用户能做的事」来分，一个业务通常跨多个模块。
- 漏掉了工具模块，例如数学库、事件、配置。它们也是模块，也要列出来，`business_ids` 填使用它们的业务。

## 卡住了怎么办

某个模块看不出用途时，`purpose` 写「用途未查清」，并在 `gaps.json` 登记缺口（`step` 填 `P3`，`blocks_denominator` 填 `false`）。
