# O6 资金与外部依赖

## 这一步在做什么

逐行过一遍业务对应专项的**第 4 节「资金与外部依赖」表**。借贷、杠杆、永续、CDP 还要加上[通用预言机检查 OR-1 到 OR-4](../../onchain/链上安全评估标准.md#53-通用预言机检查or)。

填写格式、是非题的顺序和 O5 完全相同，见 [O5 卡](./O5-参数配置.md)。

## 开始前你需要

- `O5-config.json` 已通过检查
- 业务对应的专项文件第 4 节

## 产出

`O6-funds.json`：专项第 4 节的每一行、OR-1 到 OR-4（适用时），在每个市场上各一条（共用的写一条 `ALL`）。

## 操作步骤

1. **先确定欠用户什么。** 对 F1 类检查，先写清义务：币种、数量或份额、什么时候到期。再核对**同池、同币种**的可用资金。
   - 不同池、不同币种的钱不能互相抵用；
   - 同一笔钱只能覆盖一项义务；
   - 放在外部策略里的钱，只有证实能按期调回的，才算可用。
2. **有公式的行填输入**，`q_hard`、`q_warn` 填 `by_formula`。
3. **没有公式的行**按 O5 卡的顺序回答是非题。
4. **预言机检查**（借贷、杠杆、永续、CDP 必填，其他业务用到价格时也要填）：
   - OR-1：读价函数有没有时效上限？没有（例如用了 `get_price_unsafe`）→ `q_warn: yes`。
   - OR-2：由脚本计算，见[公式表](../交付物字段表.md#六由脚本计算的公式)。OR-1 已经触发的，OR-2 填 `q_not_applicable: yes`，`reason` 写「OR-1 已触发」。
   - OR-3：照常登记，脚本按只披露处理。
   - OR-4：不在 EVM L2 上的，填 `q_not_applicable: yes`。
   - 多个市场共用同一个价格源时，写一条 `ALL`；各市场价格源不同时，每个市场一条。

## 怎么判断

**由脚本计算的编号**：哪些编号、要填哪些输入、怎么定档，统一见[交付物字段表 · 由脚本计算的公式](../交付物字段表.md#六由脚本计算的公式)。输入名必须和表里一模一样。


**常见情况：**

| 情况 | 怎么填 |
| --- | --- |
| 借贷协议现金很少、利用率很高 | 不计分。只有存在**明确到期**的应付时，L-F1.1 才有义务 |
| 资金存在其他协议里 | 目前还没有已发布的 BitsScore 评分，一律只在 `reason` 里披露对方协议，不因此答 yes。以后对方有了评分且低于 60，D2 那一行才答 `q_warn: yes` |
| 某个情景（「如果唯一报价源停止」） | 不计分，除非专项明确把它列为计分项 |
| 已到期的赎回总额协议没存，只能逐笔扫描 | `q_aggregate_not_stored: yes` |

## 填写示例

```json
{
  "checks": [
    {"id": "CK20", "business_id": "BZ01", "market_id": "ALL", "check_id": "OR-2",
     "inputs": [
       {"name": "oracle_type", "reading_id": "无", "constant": "pull", "divide_by": 1, "note": "Pyth 按需更新"},
       {"name": "max_age_s", "reading_id": "RD12", "constant": "无", "divide_by": 1000, "note": "配置单位为毫秒，oracle.move:45"},
       {"name": "heartbeat_s", "reading_id": "无", "constant": "none", "divide_by": 1, "note": "拉取型没有心跳"}],
     "q_not_applicable": "no", "q_aggregate_not_stored": "no",
     "q_hard": "by_formula", "q_warn": "by_formula", "q_weakened": "no", "refers_to": "无",
     "reading_ids": ["RD12"], "reason": "全部储备共用同一个价格配置", "evidence": ["sources/oracle.move:40-60"]}
  ]
}
```

## 完成检查

```bash
python3 工作流/scripts/bitsscore.py validate 评估记录/<项目>/<评估ID> --step O6
```

## 常见错误

- 拿其他池子的余额去覆盖这个池子的义务。
- 价格过期但有备用价格源仍然有效，却答了 `q_hard: yes`。备用源有效时，主源失效最多是 90。
- 同一个根因（例如价格源错绑）在 C1 和 D1 都计分。在 D1 填 `refers_to` 指向 C1 那条。

## 卡住了怎么办

找不到资金到底放在哪里、能否调回：在 `gaps.json` 登记（`step` 填 `O6`，`blocks_denominator` 填 `true`）。
