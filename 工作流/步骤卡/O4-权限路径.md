# O4 角色关系与权限路径

## 这一步在做什么

分两件事：

1. **补齐关系图。** 前期准备的关系图（P6）只有代码里的角色，例如模块 X 有 `AdminX`、模块 Y 有 `AdminY`。这一步要查清每个角色在链上**实际由谁持有**：EOA、多签还是时间锁；多签由哪些地址签名，时间锁由谁提议。把这些链上实体挂到角色节点下面。
2. **找权限路径。** 对每个业务，找出所有能造成以下三类后果的**完整路径**，并写清每条路径上谁必须批准、要等多久：

| 后果 | 意思 |
| --- | --- |
| H1 | 任意处分用户资产，或改写用户权益（包括升级合约） |
| H2 | 在约束范围内改变存量用户的条件（例如调整对已有仓位生效的清算线） |
| H3 | 无限期阻断必要操作（例如暂停还款且没有自动到期） |

你只登记事实。**最少密钥数、有效延时和得分都由脚本计算。**

规则来自[链上安全评估标准](../../onchain/链上安全评估标准.md)第 3 节；各后果在不同业务里的具体含义，见对应专项的第 2 节。

## 开始前你需要

- `O3-readings.json` 已通过检查
- P5 的角色和控制

## 产出

- `O4-permissions.json`，分四部分：
  - `role_holders`：每个 P5 角色在链上由谁持有；
  - `principals`：链上实体，即 EOA、多签、时间锁，以及它们的成员；
  - `paths`：权限路径；
  - `absent`：确认不存在的后果。
- `O4-role-graph.md`：脚本生成的链上角色关系图。

## 只看最顶层

关系图只追到**顶层的权限凭证和共享对象**：包或合约本身、全局配置、注册表、管理员凭证、金库。

- DEX 有成千上万个交易对，不逐个追每个池子的权限。池子通常共用全局配置和同一个管理员凭证，追到那一层就够了。
- 只有当专项要求、或者 O1 明确选定了某个池子，并且这个池子有**自己独立的**特权角色时，才追这个池子。
- 追到最终签名地址就停，不去查签名地址发过哪些交易。

## 操作步骤

**第 1 步：登记角色持有人。**

以 P6 关系图为线索，对 P5 里每个角色（只要它关联的控制影响到 O1 范围内的业务），登记一条 `role_holders`：

- `credential`：链上凭证。Sui 写 Cap 对象 ID；EVM 写 `合约地址#角色名`，例如 `0xabc…#DEFAULT_ADMIN_ROLE`，Ownable 写 `0xabc…#owner`。
- `holder_status`：
  - `held`：有持有人，`holder_principal_ids` 写持有人（一个角色授予了多个地址的，全部列出）；
  - `burned`：凭证已销毁或权限已放弃；
  - `unassigned`：查不到持有人。这**不等于**能力不存在，在 `gaps.json` 登记。

**第 2 步：展开持有人，登记链上实体。**

每个持有人登记一条 `principals`，一直追到**最终的签名地址**：

| 持有人是 | `kind` | 怎么填 |
| --- | --- | --- |
| 单个地址 | `eoa` | `threshold` 写 0，`members` 留空 |
| 多签（Safe、Sui 原生多签等） | `multisig` | `threshold` 写门限；`members` 列出每个签名地址，每个签名地址也各登记一条 `eoa`。成员本身是多签的，照样登记成 `multisig`，脚本会递归展开 |
| 时间锁合约 | `timelock` | `delay_seconds` 写当前最短等待时间；`members` 列出**提议者**，`threshold` 写需要几个提议者（通常 1）。提议者本身是多签的，照样展开 |
| 治理合约、DAO、看不出是什么 | `other` | 在 `gaps.json` 登记，交人处理 |

- Sui 原生多签的成员和门限，按 [O3 卡](./O3-读数回填.md#拿不到数据时按这个顺序试)的第 5 种方法，从一笔交易的签名里解出来。
- **同一个链上实体只登记一次。** 这决定了关系图怎么连，也决定了最少密钥数怎么算：
  - `AdminX` 和 `AdminY` 由同一个多签 M 持有：只登记一个 M，两条 `role_holders` 都指向 M。图上 M 同时连到 `AdminX` 和 `AdminY`。
  - `AdminX` 由多签 M1 持有，`AdminY` 由多签 M2 持有，两个多签有一个共同的签名地址 a：a 只登记一次，M1 和 M2 的 `members` 都引用 a。图上 a 同时连到 M1 和 M2，脚本计算密钥数时也只算一次。

**第 3 步：生成并检查关系图。**

```bash
python3 工作流/scripts/bitsscore.py role-graph 评估记录/<项目>/<评估ID>
```

打开 `O4-role-graph.md` 看一遍：每个角色都应该连到一个链上实体，或者标出「凭证已销毁」「查不到持有人」；多签和时间锁都应该展开到签名地址。

**第 4 步：登记路径。**

对 P5 里每个后果为 H1–H3、且 `reachability` 不是 `disabled_in_code` 的控制，写一条或多条路径：

- `approver_ids`：这条路径上**全部**必须批准的控制者。例如升级要多签 A 提议、多签 B 执行，就写 A 和 B。角色由时间锁持有的，写这个时间锁（脚本会顺着提议者展开）。
- `delay_seconds`：路径经过时间锁时，写时间锁的 `delay_seconds`；没有时间锁写 0。
- 有等待时，回答三个问题：
  - `delay_public`：待执行的内容在等待期间是否公开可查？
  - `delay_bypass`：有没有能跳过等待的路径？
  - `exit_closable_in_delay`：等待期间，控制者能否先关掉用户的退出入口？
- 还要追**间接路径**：能授予这个角色的上级角色、能升级合约的人、紧急入口。它们能达到同样的后果，也是路径。

**第 5 步：回答按后果的问题。**

| 字段 | 只对 | 问题 |
| --- | --- | --- |
| `h1_rate_limited` | H1 | 这条路径受代码强制的出金限速约束（例如每 24 小时最多转出一定比例），并且同一个控制者关不掉、调不大吗？是 → 脚本按 H2 计 |
| `h1_covers_all_assets` | H1 | 这条路径能处分这个业务的**全部**用户资产吗？ |
| `h3_auto_expire` | H3 | 暂停会自动到期，且不能连续续期吗？是 → 不构成 H3 |

不适用的写 `na`。

**第 6 步：H3 的控制者怎么选。**

H3 按「谁能让阻断持续下去」来评。如果角色 X 能暂停，但另一个角色 Y 能解除暂停**并且**能撤掉 X，那么阻断能否持续取决于 Y。这时 `approver_ids` 写 Y，不写 X。

例：守护者 EOA 能暂停提款，3/5 多签能解除暂停并撤掉守护者 → 路径的 `approver_ids` 写这个 3/5 多签。

**第 7 步：登记不存在的后果。**

每个业务的 H1、H2、H3，要么至少有一条路径，要么在 `absent` 里登记。`verified` 填 `yes` 必须满足：已经追完全部授予、升级、紧急入口，确实不存在。

- 升级：只有确认**不能再升级**才算不存在。例如 Sui 的 UpgradeCap 已销毁，或者 EVM 合约不是代理、代理管理员已放弃权限。
- 只是「没找到持有人」不算不存在，填 `verified: no`。

## 怎么判断

| 情况 | 怎么填 |
| --- | --- |
| 能升级合约 | 一律是 H1 路径 |
| 1-of-N 多签 | 照实登记，门限写 1；脚本会算出 1 把密钥 |
| 按权重的多签 | 门限写权重门限，`weight` 写各成员权重 |
| 一个控制影响多个业务（例如全局升级） | 一条路径，`business_ids` 列出所有受影响的业务 |
| 时间锁的等待时间本身能被同一个控制者立即改短 | `delay_bypass` 填 `yes` |
| 只能暂停「开新仓」「新存款」 | 不是 H3，不登记 |

## 完成检查

```bash
python3 工作流/scripts/bitsscore.py validate 评估记录/<项目>/<评估ID> --step O4
```

检查会确认：P5 的每个相关角色都登记了持有人；每个业务的 H1–H3 都有着落；P5 的每个相关控制都出现在路径里；多签门限合理；时间锁写了等待时间；按后果的问题填对了。

## 常见错误

- 只写了直接调用，漏了「上级角色先授权自己，再调用」这类间接路径。
- 同一个地址登记了两次，导致重叠签名人被算成两把密钥。
- 按「多签的成员是不是同一个人」去判断独立性。我们只看链上地址，不判断现实中的持有人。

## 卡住了怎么办

- 找不到门限或延时的证据：按「没有」登记，即按单签、延时 0 填，并在 `evidence` 里写明没找到。
- 控制者是 `other` 类型：在 `gaps.json` 登记（`step` 填 `O4`，`blocks_denominator` 填 `true`），交人处理。
