## 二、脚本生成的交付物

| 交付物 | 命令 | 内容 |
| --- | --- | --- |
| `P6-graph.md` | `graph` | 模块与角色关系图（Mermaid）：业务、模块、职责（带档位）、角色、控制、缺口，以及它们之间的使用、调用、实现、授予、可调用、作用于关系 |
| `C1-lines.json` | `lines` | 每个源码文件的有效行、每行的档位和所属职责；每档行数；未归入职责的行；可疑定档报警 |
| `C3-semantic-changes.json` | `coverage` | 受审版本到生产版本的每处改动（脚本生成，agent 只填 `semantic_change`、`identifiers`、`reason`，字段见下文） |
| `C3-coverage.json` | `coverage` | `by_tier`：每档行数、覆盖数（直接、沿用）、未覆盖原因计数；`detail`：逐段的覆盖状态、未覆盖原因、覆盖它的报告；`a4_small_changes_only` 及不满足的原因 |
| `C6-score.json / .md` | `score` | 状态（已评分／无法评分／待人工确认／不适用）、各档覆盖、覆盖分、总体评价及加减分项、封顶及参与封顶的发现、最终分 |
| `O4-role-graph.md` | `role-graph` | 在 P6 关系图上补齐链上实体：模块对应的顶层对象、角色持有人、多签签名人、时间锁提议者（Mermaid） |
| `O8-score.json / .md` | `onchain-score` | 快照、状态、项目链上分、各业务分和权重、每条权限路径的密钥数和延时、每个检查项的结果和计算过程、0 分市场、致命项、未完成原因、有效期 |
| `deliverable.json` | `export` | 前端唯一数据源：证据树、链上角色关系图、快照、规则版本、报告、缺口、证据字典。格式见[交付格式](./交付格式.md) |

## 三、前期准备

### `T0-task.json`（T0 任务单）

任务单

| 字段 | 类型 | 取值或约束 | 说明 |
| --- | --- | --- | --- |
| `assessment_id` | 文本 | 有格式要求 | 评估 ID，格式 <项目>-<YYYYMMDD>，同一天第二次评估加 -2，例如 navi-20261125 |
| `previous_assessment_id` | 文本 | 有格式要求 | 上一次评估的 ID；第一次评估写 无 |
| `reason` | 枚举 | `first` ／ `scheduled` ／ `permission_change` ／ `upgrade` ／ `parameter_change` ／ `rule_change` ／ `correction` | 为什么做这次评估：first 首次；scheduled 定期复评；permission_change 权限持有人或门限变了；upgrade 合约升级；parameter_change 核心参数改了；rule_change 评分规则升版；correction 纠正上次的错误 |
| `project` | 文本 |  | 项目名称 |
| `dimensions[]` | 枚举列表 | 至少 1 项，`code_security` ／ `onchain` | 本轮评估维度 |
| `chains[]` | 对象列表 | 至少 1 项 | 涉及的链 |
| `chains[].chain_id` | 文本 | 有格式要求 | 链标识，格式 sui:mainnet 或 evm:<chainId>，例如 evm:1 |
| `chains[].name` | 文本 |  | 链的名称，例如 Sui Mainnet |
| `scope_statement` | 文本 |  | 委托方给出的范围原文，或你记录的口径 |
| `known_entries[]` | 文本列表 | 可为空 `[]` | 委托方或公开资料给出的入口地址或包 ID（只是线索） |
| `known_repos[]` | 文本列表 | 可为空 `[]` | 已知的源码仓库 URL（只是线索） |
| `out_of_scope[]` | 文本列表 | 可为空 `[]` | 明确排除的范围 |
| `assessor` | 文本 |  | 评估人或 agent 名称 |
| `date` | 文本 | 有格式要求 | 开始日期 YYYY-MM-DD |

## 六、由脚本计算的公式

下表列出的检查项，`q_hard` 和 `q_warn` 填 `by_formula`，在 `inputs` 里按「输入」列的名字逐个填写，定档由脚本完成。其余检查项回答是非题。

### 抵押缓冲（`lending_buffer`）

- 适用检查项：L-C2.1、L-C2.3、M-C2.1
- 公式：D_open = 1 − b/λ；M = 1 − λ·β；B_buf = min(D_open, M)（单一 LLTV 机制 B_buf = M）
- 定档：违反 0 < b ≤ λ ≤ 1、β < 1，或 M < 0 → 0；B_buf < 5%（同底层 1%）→ 60

| 输入 | 含义 |
| --- | --- |
| `b` | 开仓上限（小数）；单一 LLTV 机制填常量 none |
| `lambda` | 有效清算线（小数） |
| `beta` | 清算扣押倍率，例如 1.05 |
| `same_underlying` | yes／no：是否同底层组合（按 Lending 专项第 6 节证明） |

### 利率曲线（`rate_curve`）

- 适用检查项：L-C2.2
- 公式：k_low = (r_kink − r0) / u_kink；k_high = (r1 − r_kink) / (1 − u_kink)
- 定档：有负利率，或利率随利用率上升而下降 → 0；k_high = 0 → 60

| 输入 | 含义 |
| --- | --- |
| `r0` | 利用率 0 时的年利率 |
| `u_kink` | 拐点利用率；没有拐点填 0.8 |
| `r_kink` | 拐点处的年利率；没有拐点填 r(0.8) |
| `r1` | 利用率 100% 时的年利率 |

### 价格不确定性（`margin_h`）

- 适用检查项：M-C2.2
- 公式：H情景 = (λ / b) × (1 − εc) / (1 + εd)
- 定档：H情景 < 1 → 60

| 输入 | 含义 |
| --- | --- |
| `lambda` | 有效清算线 |
| `b` | 开仓上限 |
| `eps_c` | 抵押侧允许的最大价格不确定性 |
| `eps_d` | 债务侧允许的最大价格不确定性 |

### 保证金（`im_mm`）

- 适用检查项：P-C2.1
- 公式：比较 IM 与 MM
- 定档：IM ≤ MM → 0

| 输入 | 含义 |
| --- | --- |
| `im` | 初始保证金率 |
| `mm` | 维持保证金率 |

### 价格年龄（`oracle_age`）

- 适用检查项：OR-2
- 公式：比较允许的最大价格年龄与上限
- 定档：拉取型 > 300 秒，或推送型 > 心跳 × 2 → 60

| 输入 | 含义 |
| --- | --- |
| `oracle_type` | 常量 pull（使用方按需更新）或 push（预言机定时推送） |
| `max_age_s` | 允许的最大价格年龄（秒） |
| `heartbeat_s` | 推送型的心跳（秒）；拉取型填常量 none |

### CDP 清算缓冲（`cdp_buffer`）

- 适用检查项：CD-C2.1
- 公式：清算缓冲 = MCR − 1 − p
- 定档：清算缓冲 < 0 → 0；< 5%（同底层 1%）→ 60

| 输入 | 含义 |
| --- | --- |
| `mcr` | 最低抵押率，例如 1.10 |
| `p` | 清算罚金或奖励比例，例如 0.10 |
| `same_underlying` | yes／no |

### 系统抵押率（`cdp_tcr`）

- 适用检查项：CD-F1.1
- 公式：TCR = 抵押总价值 ÷ 总债务
- 定档：TCR < 1 → 0；TCR < CCR → 60

| 输入 | 含义 |
| --- | --- |
| `collateral_value` | 全系统抵押总价值 |
| `debt` | 稳定币总债务 |
| `ccr` | 协议定义的临界抵押率；没有定义填常量 none |

### LST 兑换率（`lst_rate`）

- 适用检查项：LS-C2.1
- 公式：R_backing = (已质押 + 待领取 + 闲置 − 待兑付赎回) ÷ 供应量；偏离 = (R_stored − R_backing) ÷ R_backing
- 定档：偏离 > 一个 epoch 的应计奖励率 → 0；|偏离| > 0.5% → 60

| 输入 | 含义 |
| --- | --- |
| `r_stored` | 合约存储的兑换率 |
| `staked` | 已质押总量 |
| `pending_claim` | 待领取 |
| `idle` | 闲置缓冲 |
| `pending_redeem` | 待兑付赎回 |
| `supply` | LST 总供应 |
| `epoch_tolerance` | 一个 epoch 的应计奖励率 |

### 验证者集中度（`concentration`）

- 适用检查项：LS-F1.2
- 公式：最大集中度 = 单一验证者质押量 ÷ 总质押量
- 定档：> 50% → 60

| 输入 | 含义 |
| --- | --- |
| `max_stake` | 质押量最大的验证者的质押量 |
| `total_stake` | 总质押量 |

### 锁定覆盖（`coverage`）

- 适用检查项：BR-F1.1
- 公式：覆盖 = 源链锁定量 ÷ 目标链流通量
- 定档：覆盖 < 1 → 0

| 输入 | 含义 |
| --- | --- |
| `locked` | 源链锁定量 |
| `circulating` | 目标链流通量 |

### 区间覆盖（`interval_cover`）

- 适用检查项：BR-F1.2、FA-F1.1、L-F1.1、LB-F1.2、LS-F1.1、M-F1.1、P-F1.1、V-F1.1
- 公式：比较应付区间与可用资金区间
- 定档：应付下界 > 可用资金上界 → 0；两区间重叠 → 60；可用资金下界 ≥ 应付上界 → 通过

| 输入 | 含义 |
| --- | --- |
| `due_low` | 应付下界 |
| `due_high` | 应付上界 |
| `avail_low` | 可用资金下界 |
| `avail_high` | 可用资金上界（确定值时上下界填同一个读数） |
